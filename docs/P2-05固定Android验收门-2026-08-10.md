# P2-05 固定 Android 验收门（2026-08-10）

## 1. 目的

为 P2-05 的最后一个工程子门定义固定中端 Android 的验收条件、证据格式和停止线。本门必须在真实固定设备上执行；任何桌面浏览器、开发者工具模拟、Playwright 视口或模拟器结果都不得冒充固定设备证据。

## 2. 当前状态

未开始：尚未锁定固定设备，也没有任何真机证据。桌面 Edge 的 10,000 条深翻资源探针只用于提前暴露回归，不替代本门。

## 3. 固定设备基线（提交设备前必须确认）

| 项目 | 要求 |
| --- | --- |
| 设备 | 一台固定中端 Android 手机（建议 8GB RAM 档位或以下） |
| 系统 | Android 版本、厂商 ROM 版本、安全补丁日期 |
| 浏览器 | Android Chrome 精确版本；另行注明系统 WebView 提供方与版本（用于未来 APK 阶段） |
| 屏幕 | CSS 宽度、density、DPR、可用存储 |
| 网络 | 首装在线 + 断网两种状态 |
| 身份 | 设备序列号/唯一标识只写摘要或脱敏后记录，不随项目公开 |

## 4. 场景矩阵

每个场景都使用与桌面相同的固定 10,000 Case / 10,000 Revision / 10,000 fingerprint 种子，并记录：

1. 默认 legacy-v13 首次加载、BOOT_OK 与真实可交互时间；
2. v16 隔离候选 clean 启动（epoch/verifiedEpoch/cache_hit）与 dirty 启动 full audit；
3. CAS 竞争：跨标签页写锁、单事务回滚、无可写半代；
4. full v1.2 导出、只读预检、安全快照与恢复往返；
5. CandidateSet-heavy、长备注与复杂 ResearchQuery 的同构结果；
6. 连续深翻资源探针：storage estimate、JS 堆（可用时）、long task、内存峰值；
7. PWA 安装、离线冷启深链、浏览器清理边界；
8. 回收站、分页、检索与打开路径在 390/412px 宽度无横向溢出。

## 5. 证据格式

每个场景保存到 `tmp/`（不进入 Git）：

- `device-info.json`：设备、系统、浏览器/WebView、屏幕与存储；
- 控制台 `error/warning/pageerror` 计数与文本；
- 指标 JSON：时间、epoch、digest、容量、内存/long task；
- 每场景截图（失败必留，成功至少 1 张）；
- 执行命令与开始/结束时间；
- 若为人工步骤（文件分享、返回键、系统字体、打印），记录操作清单与结果。

汇总后把“工程结论 + 设备环境 + 证据清单”写入 P2-05 文档，并在 README 只更新为“固定 Android 门已通过”的表述。

## 6. 停止线

- 没有真实固定设备时，不得宣称 Android Chrome/WebView 已通过；
- 模拟器、桌面视口或 Playwright 设备模拟不得作为真机证据；
- 未记录设备/浏览器版本时，结果不签名；
- Web v1 未稳定前不提前进入 Capacitor/APK 壳；
- 本门通过不等于 Android APK、SAF、系统分享、签名包或商店发布完成。

## 7. 下一步

用户提供或确认一台固定中端 Android 设备后，按本方案逐场景执行；在此之前，P2-05 继续标记为部分完成，且不提升默认发布代。
