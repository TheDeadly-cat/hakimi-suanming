## 黄道方法身份纵切

当前规则层只接受两种精确身份：

```text
tropical / ayanamsha:null / tropical_identity_v1
sidereal / manual_offset_unverified / subtract_supplied_offset_v1
```

request、result、execution、request/result digest、content projection、UI 与动态审稿绑定均保留方法
身份。execution 保存 `{kind, ayanamshaId, algorithmId}`，刻意不复制数值 offset。旧 0.1、0.2、0.3
request protocol 以及缺失、未知、交叉错配身份均失败关闭；当前 request/artifact/projection 为
`0.4-draft`。

独立审计在首轮通过后发现并修复：

- sidereal 空白 offset 被 `Number("")` 静默转换为零；
- sidereal + whole-sign 先按 raw tropical ASC 选宫头，导致宫头和入宫错误；
- `assignHousePlacement` 只在 H12 处理 0° wrap，其他宫位跨 0° 时错归；
- `2.0002°` 等合法 offset 的浮点残差可把 150° 宫头判进前一星座；
- UI 宫头／四轴显示 raw frame，而 body、content、wheel 显示选定 zodiac frame；
- 度分秒舍入可出现 `53′60″`；
- 静态／动态审稿模板在新增方法和内容身份后仍复用旧版本；
- 动态模板同时导出 raw 与 zodiac angle，可相减恢复手填 offset。

修复后，唯一 `deriveZodiacPlacement` 使用版本化 `1e-10°` 边界 snap；whole-sign、content、wheel、
宫头与四轴 UI 均复用该推导。offset `2.0002°` 的 12 个整宫宫头显示后都严格位于星座 0°，容差外
两侧值不会被吞。静态模板现为 v0.8/v008，动态模板为 v0.10/v010；各前代身份均明确拒绝。
