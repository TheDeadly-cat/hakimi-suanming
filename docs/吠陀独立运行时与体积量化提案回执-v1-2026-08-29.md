## 4. tradeoff 与依赖问题矩阵

安全／隐私／可复现性矩阵为两个候选分别登记风险和未来控制要求，所有 validationStatus 均为 `required_not_performed`，且 `preferenceClaimed=false`。这建立的是 decision-neutral 问题覆盖，不是 review 结论、控制已实现或风险已消除。

五类依赖问题矩阵覆盖：

1. Python runtime；
2. Swiss Ephemeris code；

每类依赖均保持 `selection=undecided_not_selected`、`reviewComplete=false`、`legalConclusionEstablished=false`、`redistributionAuthorized=false`。当前仅把 [公开一手许可观察 evidence child](./吠陀运行时依赖公开一手许可观察回执-v1-2026-08-29.md) 的 link-only refs 以 `python/swisseph/data/worker/loopback = 1/3/3/1/0` 投影进问题矩阵；五类中只覆盖 4 类，loopback 仍为 0。公开读取回执不能替代具体版本、许可证正文、代码或数据来源、作品／版本／载体三层权利账，也不作许可兼容或商业使用结论。

## 6. 严格闭包与两项 P2 修复

本轮在终审中发现并修复了两项 P2：

1. 初版 `complete` 状态只有 ceiling 与“review 未执行”标记，不能证明 ADR 提案材料覆盖。现已加入两个候选的 security／privacy／reproducibility 风险—控制矩阵、五类依赖未回答问题矩阵，以及第 5/6 项的接口和量化引用，并以 `proposalCoverageComplete=true`、`reviewsComplete=false` 分账；
2. 对象 canonical snapshot 初版以普通对象承接任意键，own `__proto__` 可能造成原型赋值而不是数据键。现已改为不会执行 legacy prototype setter 的安全承接，并加入 raw/object `__proto__`、digest 与 exact-key 负例。

raw parser 使用内部 typed-array 槽，零 trap 拒绝 Proxy，拒绝 SharedArrayBuffer、Resizable ArrayBuffer 与 detached view，并先复制到私有固定缓冲区。对象 API 被动拒绝 accessor、Proxy、Symbol、非普通 prototype、稀疏数组、循环／别名、非有限数与 `-0`；canonical materialization、domain-separated digest、held-handle 读取、普通目录链、单链接端点、realpath 与 endpoint identity revalidation 均有定向负例。

提案精确绑定 ADR、input draft／requirements、fact draft／requirements、rule draft／requirements 七个唯一线性上游；无 parent 或中央 registry 回链。许可 evidence child 是正交单向聚合输入，不加入或重排这七节点链；child 自身只绑定 ADR，且无 proposal／parent／registry 回链。提案、七节点线性链与 evidence child 共同形成当前 runtime DAG，但没有跨文件或父子原子快照，也不排除读取区间 mutation 或 ABA。
