# 紫微内容 v0.9：四化十二宫位置化审稿矩阵与证据

日期：2026-08-12

范围：`packages/ziwei-iztro-adapter-draft`、`packages/ziwei-workspace-artifact-draft` 与主应用只读内容总目录

状态：工程实现与定向验收完成；专家批准 0，正式发布 0

## 1. 本轮要解决的具体缺口

v0.8 已能从验真盘面提取本命生年禄、权、科、忌，并把每条事实放入对应目标宫的三方四正复核包；但卡片仍主要展示四化的通用方向。用户看到“紫微化科在迁移宫”时，还要自行把“化科”与“迁移宫”拼接，缺少一句直接、位置明确而又不过度断言的说明。

v0.9 因此冻结一张 **4 × 12 = 48 条**的审稿矩阵：每条同时指定本命生年四化标签和落宫角色，提供位置化短解、宫位专属反向提醒、专家问题及来源绑定。真实盘面只按“已验真四化标签 × 实际落宫”命中对应候选，不按名称自动换算吉凶。

用户提供的 [周易网八字排盘示例](https://www.zhouyi.cc/bazi/sm/) 只作为“排盘后立即给出位置相关内容”的产品工作流参考，不是本轮紫微语义来源，也没有进入来源登记数。

## 3. 固定内容契约

新增版本：

```text
ziwei.natal_transformation_all_palaces.neutral_candidate/0.1
```

每条 `BrowserProbeNatalTransformationPalaceCandidateContent` 固定包含：

- `transformationLabel`：禄、权、科、忌之一；
- `palaceRoleId / palaceRoleLabel`：十二宫之一；
- `genericCandidateContentId`：绑定 v0.8 通用四化候选；
- `palaceRoleContentId`：绑定既有十二宫问题域候选；
- `positionSummary`：直接说明“生年化 X 星曜落某宫时，可先观察什么”；
- `counterweight`：该宫专属的反向提醒和现实核对边界；
- `reviewPrompt`：要求专家给出流派成立条件、现实依据与反例；
- `sourceRefs`：复用三条四化来源和两条宫位来源，恰好 5 条且不新增来源登记；
- `reviewStatus: awaiting_expert_review`、`publicationStatus: isolated_candidate_only`；
- `expertTruthClaimed:false / directOutcomeAllowed:false / scoringAllowed:false`。

模块加载时会失败关闭以下异常：

- 不是恰好 48 条；
- 任一四化不是 12 条，或任一宫位不是 4 条；
- 内容 ID、四化宫位组合或位置短解重复；
- 通用四化／宫位问题域绑定不一致；
- 五来源缺失、重复或未登记；
- 出现“必然、注定、大吉、大凶、发财、富贵”等结果化措辞；
- 任一专家真值、直接结果或评分开关被打开。

## 4. 十二宫的高风险边界

48 条不是把同一个模板机械换宫名。每宫分别登记观察对象、四化方向、反向提醒与现实核对资料：

| 宫位 | 位置化观察重点 | 固定禁止越界 |
| --- | --- | --- |
| 命宫 | 自我定位、表达、边界与反复校正 | 不固定人格，不判人生顺逆或地位 |
| 兄弟宫 | 同辈互助、分工、沟通与资源分配 | 不判手足数量、亲疏或谁支配谁 |
| 夫妻宫 | 情感投入、承诺协商、公开表达与安全感 | 不预测婚期／结果，不使用性别刻板结论 |
| 子女宫 | 培育、创作、输出、反馈与责任牵挂 | 不判生育能力、子女数量或亲子结果 |
| 财帛宫 | 资源配置、预算责任、财务说明与账目焦虑 | 不等同收入／收益，不作投资建议 |
| 疾厄宫 | 作息照护、计划管理、健康沟通与身体关注 | 不诊断疾病、不判寿命，不替代医疗服务 |
| 迁移宫 | 外部资源、陌生环境决策、公开呈现与适配担忧 | 不预测异地或出行成败 |
| 交友宫 | 社群资源、组织责任、专业形象与信任落差 | 不判某人可靠、背叛或固定身份 |
| 官禄宫 | 项目资源、交付责任、专业评价与能力反馈 | 不指定职业，不预测录用、升迁或收入 |
| 田宅宫 | 空间资源、产权边界、文书透明与维护牵挂 | 不判置业、继承、资产规模或家庭结果 |
| 福德宫 | 休息兴趣、节奏控制、感受表达与意义落差 | 不作心理诊断，不把体验固定成性格 |
| 父母宫 | 支持往来、照顾文书责任、制度评价与期待落差 | 不判父母健康、寿命或家庭命运 |

## 5. 真实盘面投影与界面

`natal-transformation-review.ts` 在生成每条出现项时同时绑定：

1. 已验真的星曜、四化与落宫事实；
2. v0.8 通用四化候选；
3. 十二宫问题域；
4. 新增的四化 × 宫位候选；
5. 主星时已有的主星 × 宫位位置主线，辅／杂曜则保持不适用。

4218 卡片现在按以下顺序显示：问题域、原位置主线、通用四化方向、落宫修正、宫位专属反向提醒。来源折叠区由 3 条四化链接扩为 3 条四化 + 2 条宫位链接。页面和投影仍固定：

```text
result: null
goodBadOrientation: null
eventOutcome: null
```

某组三方四正没有已验真的本命生年四化时，出现项保持 0，并继续明确“不补入宫干、飞化、自化或运限四化”。选择目标宫位只重新渲染只读投影，不写 IndexedDB，也不改变 mutation epoch。

## 10. 下一步可执行的专家工作

专家可以直接按 48 条矩阵审稿，而不需要先操作代码：

1. 逐条确认“通用四化方向 × 宫位问题域”的组合是否适用于选定流派；
2. 标出需要拆分的流派、成立条件、反例和禁止场景；
3. 特别复核夫妻、子女、财帛、疾厄、田宅、福德、父母七类高风险表述；
4. 只对有具名审稿人、日期、依据和裁决的条目建立后续批准记录；
5. 好坏方向仍应作为独立裁决字段，不能从“禄／权／科／忌”名称或工程权重自动推导。
