# 八字内容 v0.4：十神审稿表与神煞事实注册表

> 日期：2026-08-12  
> 状态：工程候选，待命理专家校勘  
> 发布边界：默认发布身份继续是 `legacy-v13 / targetSchema 13`；本文不授权提升默认代、不改 mutation epoch / CAS，不把神煞写进正式排盘事实层。

## 1. 本轮目标

上一轮完成了透明的旺衰候选和四柱十神入口，但十神内容仍由“十神通用描述 + 柱位通用范围”拼接，神煞只有大纲。本轮补齐两个不依赖发布授权、Android 设备或专家真值的内部项：

1. 把十神内容改为真正的 `10 × 4` 原创审稿表，每个十神在年、月、日、时柱都有独立条目。
2. 建立首批五项神煞事实注册表，只计算“基准字段 → 目标地支 → 命中柱位”，不输出神煞吉凶解释。
3. 神煞继续默认关闭；Web 只提供用户显式展开、页面内临时计算的只读研究预览，不写入案例或规则快照。

## 2. 研究方法与来源

### 2.1 研究问题

- 原典能否明确支持目标地支的映射？
- 原文使用年干/年支还是日干/日支作为基准？
- 哪些后续判断依赖生旺、冲破、空亡、纳音或组合，不能被压缩成“命中即吉/凶”？
- 同名异法尚未完成来源准入时，系统如何失败关闭？

### 2.2 深读来源

## 3. 十神 `10 × 4` 审稿表

### 3.1 契约

每个条目包含：

- `tenGod` 与 `position`，形成唯一审稿 ID，例如 `七杀:month`；
- `focus`：该十神在该柱位关注的议题；
- `flowing`：表达顺畅时的行为倾向；
- `strained`：失衡时需要警惕的倾向；
- `evidenceClass = original_editorial`；
- `reviewStatus = candidate_pending_expert_review`；
- `doesNotEstablish`：明确不能单独证明具体事件、关系结果、职业层级或固定吉凶。

代码事实源：`packages/bazi-interpretation/src/ten-god-position-content.ts`。40 个组合必须全部存在、ID 唯一，缺一项即测试失败。

“禁用冲突槽位”只说明项目知道有待裁决的另一基准位置；它不主张该异法已经正确，也不会参与命中计算。

### 4.3 命中事实结构

```ts
interface ShenshaFactHit {
  ruleId: string;
  name: string;
  basis: "year_branch" | "year_stem";
  basisValue: string;
  targetBranches: readonly string[];
  matchedBranches: string[];
  positions: Array<"year" | "month" | "day" | "hour">;
  sourceLocator: string;
  reviewStatus: "source_transcribed_candidate";
  interpretation: null;
}
```

未知时辰时，时柱先从候选命中位置中排除；不允许因为其他三柱可算就猜测时柱命中。

## 5. Web 行为

1. “旺衰与十神解读”继续直接展示，但十神卡片改用 40 项独立审稿表，并显示审稿 ID。
2. “神煞事实研究预览”初始只显示默认关闭状态和边界说明。
3. 用户点击“打开只读研究预览”后才临时计算；结果不写 IndexedDB、不修改 `RevisionRecord.ruleProfile.layers.shensha`，也不触碰 mutation epoch。
4. 命中卡片只显示基准、目标支、命中柱和来源定位；解释字段固定为 `null`。
5. 原典中的性别刻板、疾病、灾祸、违法、死亡等确定性断语不进入用户界面。

## 7. 仍未关闭的门

1. **专家门**：40 项十神文案和五项神煞转录都仍需逐条审稿。
2. **异法门**：日干/日支基准没有通过来源准入，继续禁用。
3. **组合门**：生旺、冲破、空亡、纳音、合刑与其他神煞组合尚未进入解释。
4. **正式层门**：`layers.shensha` 仍为 `false`；研究预览不等于正式神煞规则层已上线。
5. **高风险表达门**：不输出健康、法律、死亡、灾祸、财富或关系结果的确定性预测。
