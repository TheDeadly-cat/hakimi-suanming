# Web 研究工作台信息架构 v0.1

> 状态：低保真原型与前端拆分基线  
> 适用：[产品方向更新 v0.2](./产品方向更新-v0.2-专业研究版.md)  
> 设计语言：[视觉系统与原创边界 v0.1](./视觉系统与原创边界-v0.1.md)

## 1. 组织原则

产品按“研究任务”组织，不按“今日运势、感情、事业”等消费栏目组织。

命盘内部的三层视图统一命名为：

- **概览**：快速确认输入、四柱和主要结构；
- **结构**：查看完整命盘矩阵、关系和运限入口；
- **研读**：查看规则命中、推导、版本、来源与争议。

“研究”保留为产品整体模式，以及案例库、对照台、规则差异等跨页面能力，不再作为第三个命盘标签。

## 2. 核心对象关系

```text
案例 Case
  ├─ 原始出生资料与来源
  ├─ Event v2（明确时间语义）、标签、笔记、材料
  │    └─ EventTimeMigrationReceipt（旧浮动时间的新 ID 并列解释）
  └─ 命盘修订 Revision 1…N
       ├─ 输入与校时快照
       ├─ engine / tzdb / rule_profile 版本
       ├─ ChartFacts 与运限快照
       └─ 依据、引用与导出物
```

修改出生时间、地点、历法参数或规则配置时，默认创建新修订，不静默覆盖旧盘。每个命盘页面持续显示修订号、时间精度、规则配置、引擎和时区库版本。

Event v2 的时间与命盘出生时间分别建模，但遵守同一条“不猜测”原则：旧 Event v1 升级为 `legacy_floating`，非分钟事件为 `calendar_date`，新分钟事件为 `zoned_minute`。只有后者保存 IANA 时区、DST 解析、偏移与规范 UTC；gap 拒绝，overlap 显式选择，不把旧浮动时间按当前设备时区静默解释。旧浮动事件需要新时间解释时，不修改原 ID，而是经用户显式确认创建并列的新 ID 目标和只追加回执。

### 2.1 多体系长期边界

当前对象关系、无前缀路由和 full v1.2 都固定属于八字。未来紫微斗数与西洋星盘通过独立版本化能力包进入同一研究工作台，共享本地研究、来源、附件和平台外壳，不共享模糊的通用命盘事实。第二体系完成输入、计算、Revision、重开与备份验收前，不显示可点击的体系切换器，也不为其预建空数据。完整决定见 [多术数融合扩展边界 v0.1](./多术数融合扩展边界-v0.1.md)。

## 4. 导航与布局

### 4.1 桌面端

左侧 216 px 主导航：

- 工作台；
- 案例库；
- 对照台；
- 知识与来源；
- 顶部突出“新建排盘”；
- 底部固定离线状态、备份健康与设置。

进入案例后，中间主工作区提供“命盘、运限、事件与笔记、材料”导航；命盘内部再使用“概览、结构、研读”。

右侧 280～336 px 是可折叠依据栏：

1. **算得出**：输入和确定性计算链；
2. **怎么解**：规则、流派和差异；
3. **来源**：书名、版本和章节；
4. **怎么说**：只在启用 AI 时出现并明确标识。

### 4.2 手机端

底部导航保持五项：**工作台、案例、排盘、对照、知识**。设置放在顶部工具菜单，备份风险同时出现在工作台。

功能不删减，只改变呈现方式：

| 桌面 | 手机 |
| --- | --- |
| 多盘并排 | 固定基准盘 + 当前比较盘 + 差异列表 |
| 右侧依据栏 | 底部抽屉 |
| 密集表格 | 固定行标题、横向矩阵或虚拟列表 |
| 多栏典籍 | 目录抽屉 + 正文 + 来源抽屉 |
| 常驻复杂筛选 | 底部筛选面板 |

排盘、批量导入和备份恢复使用专注式全屏流程，可临时隐藏底栏。

## 5. 关键页面

### 5.1 工作台

主要任务：继续上次案例和时间节点、新建排盘、打开最近案例/对照、恢复导入任务、处理未备份或空间不足。

桌面使用紧凑列表和分区，不做大卡片瀑布流；“岁序脊线”连接最近研究活动。手机首屏只保留继续研究、排盘和最近案例。

| 状态 | 行为 |
| --- | --- |
| 首次空状态 | 解释本地保存，提供“新建排盘”和“导入案例” |
| 加载 | 保留应用壳和列表尺寸，不使用神秘测算动画 |
| 数据库/迁移错误 | 说明哪些数据仍可读，提供诊断导出与恢复入口 |
| 离线 | 核心入口照常可用，仅标出在线地点搜索/资料更新暂停 |
| 多标签页冲突 | 重新载入，或把当前草稿保存为副本 |

### 5.2 排盘与校时

四步流程：

1. 案例信息：别名、匿名编号、标签、资料来源；
2. 出生资料：公历/农历、闰月、时间精度、地点；
3. 时间与规则：时区、DST、民用时/真太阳时、换日与排运配置；
4. 检查生成：输入摘要、推导链、警告和规则版本。

关键要求：

- 原始输入、民用时间、时区修正和真太阳时并列显示；
- 用户明确选择本修订采用的时间，不静默替换；
- 未知时辰可直接生成 13 个代表性探针候选并进入对照台；
- 离线时允许手填时区和经纬度；
- 修改已有案例时明确提示“将创建修订 N”；
- 真实展示“规范化输入 → 历法计算 → 生成结构 → 应用规则”。

错误必须定位到具体字段或阶段；部分计算失败显示“未计算”，不能用空白冒充无结果。

### 5.3 命盘：概览 / 结构 / 研读

标题区始终显示：

```text
案例别名 · 修订 2 · 时间精度：分钟
传统子平工作配置 0.1 · 引擎版本 · tzdb 版本
```

**概览：** 四柱简表、时间精度、五行/十神分布、主要结构关系、近期笔记和运限入口。

**结构：** 完整四柱矩阵、藏干、十神、十二长生、纳音、空亡、干支合冲刑害破、生克及可开关神煞层。

**研读：** 规则命中条件、推导过程、字段类型、规则包/引擎/时区版本、流派差异、来源、结构化事实导出与用户批注。

点击任意单元格时，高亮关联项并更新依据栏。手机保持“行标题 + 年月日时四列”完整，复杂行折叠，依据进入底部抽屉。

规则升级时，旧修订继续固定旧版本；用户选择“生成新修订”，不能后台偷偷重算。

### 5.4 运限时间轴

轨道自上而下：原局上下文、大运、流年、流月/流日/流时、真实事件、研究笔记与引用。

- 支持十年、年、月、日、时五级缩放；
- 可按年龄、年份或日期跳转；
- 选择节点后叠加原局、大运和当前时间；
- 可固定两个节点做差异查看；
- 计算节点、用户事件、规则观点使用不同图形和文字，不用吉凶红绿灯；
- 加载失败保留已完成层级并标出失败范围。

手机一次聚焦 3～5 个横向节点，下方展示详情，并同时提供明确缩放按钮。

**事件验证与节点双向链：**

- 从节点检查器打开绑定事件时，路由写入 `view=research&event=<uuid>`；事件卡返回节点时恢复其稳定 `node`、`at` 与方向上下文；
- `event=<uuid>` 只精确匹配当前 Case/Revision；UUID 无效、记录缺失或属于其他案例/修订时显示明确错误，不退回最近事件或近似节点；
- 新建分钟事件必须先选择有效 IANA 时区。唯一时刻直接解析；DST overlap 展示 earlier/later 候选及各自偏移/UTC，必须显式选择；DST gap 直接拒绝，不向前或向后平移；
- 旧 `legacy_floating` 明示“未绑定时区、无规范 UTC”，任何时间字段都禁止同 ID 覆盖；用户必须进入迁移面板明确确认。分钟记录选择 IANA 时区与 DST 决策后，以新 ID 派生固定 IANA 2026c 的 `zoned_minute`；非分钟记录以新 ID 派生 `calendar_date`。源记录不改变，并在同一事务追加 Event 专用回执；
- 同一源可按不同 IANA/DST 解释并列派生多个目标；完全相同的源+目标快照不能重复，一个目标也不能归属多条回执。回执绑定的日期精度、起止日期、时间上下文、Case、Revision 与 TransitNodeRef 冻结；标题、标签、来源引用、反馈、正文和软删除/恢复等生命周期仍可编辑；Citation/Attachment 不自动复制或改绑；
- 事件列表支持关键词、标签、反馈、有效/已删除/全部，以及当前修订/当前节点绑定筛选；被 `event=<uuid>` 指定的记录应保持可见、滚动到位并获得可感知高亮/焦点，即使与当前筛选冲突；
- 新分钟 Event 保存活动 IANA 2026c 身份；CandidateSet 页面提供 2025b/2026c 并列复算。本命盘区域仅在完整性、bazi 0.4.0 六字段 executor、bundled tzdb、规则、精度和 DST 均 exact 时显示“只读复演”按钮；操作零写入，并常驻提示关系、运势、流年和 Transit 仍是当前算法。Edge 当前 2026c UI/390px 门 1/1 已通过；其他历史 engine、Chrome/Firefox/Android 与跨代 registry 仍需后续工作；
- 单盘报告当前为 v1.3：完整模式显示与所选事件有关、端点投影一致且冻结快照正文 SHA-256 重新计算通过的时间派生回执，匿名模式同时移除事件时间上下文与回执。

### 5.5 案例库与批量导入

桌面使用可排序表格；手机使用高密度列表。字段至少包括别名、时间精度、标签、规则配置、修订数、更新时间和验证状态。

导入流程：

```text
选择文件 → 编码/格式预览 → 字段映射 → 行级校验
→ 重复与冲突处理 → 演练摘要 → 正式写入 → 抽样复核
```

- 大数据集分批解析，可取消和继续；
- 错误提供逐行报告，坏行不污染好行；
- 默认跳过重复或导入为副本；
- 只允许自动合并标签和笔记，出生资料与计算事实不自动合并；
- 中断后保留导入会话。

### 5.6 对照台

支持：多案例同规则、同案例不同规则、同案例不同修订、未知时辰候选。

桌面一次显示 2～4 个活动列，统一行序并同步滚动。差异明确分为：输入、历法计算、规则命中、解释观点、来源/版本。

手机固定一个基准盘和一个比较盘，先显示差异列表，再进入两项上下对照；其余案例保留在会话切换器中。颜色只表示新增、缺失、改变，不表达吉凶。

### 5.7 知识、来源权利与依据覆盖

知识区分为四个视图：基础术语/关系表、用户导入资料与正文、来源权利台账、依据覆盖审计。权利明确的随包典籍是未来内容域，但当前生产构建内置典籍正文为 **0**，不能用来源候选或古代作品公版声明冒充已获准分发的精确文本。

- 全文与书内搜索；
- 从命盘字段打开术语和原文；
- 选中文段加入案例笔记或依据；
- 从原文反查引用它的规则和笔记；
- 始终显示书名、精确版本、章节、来源、正文哈希与授权状态；
- 来源权利台账分别显示古代作品层与现代版本/校点/数字化文本层，不把二者折叠成一个“公版”标签；
- 用户导入资料从创建、编辑、备份到恢复都只能保持“用户提供、未核验、仅本机、未复核”，不能进入公共知识包；
- 随包正文必须通过 manifest、正文哈希、两层权利、分发策略、署名/许可义务和两个真实复核身份的构建门；任一项未知或失配时默认拒绝；
- 依据覆盖审计以 36 个版本化四柱字段主题为当前固定分母，分别显示 provenance 完整、结构化链接、双人核验、可分发来源四项指标、验证状态分布、逐主题缺口和可复算报告摘要；
- “用户候选”引用只提高结构化链接指标，不提高双人核验、可分发来源或金标；版权/许可状态和命理证据核验状态始终是两条独立轴。

桌面端用资料、来源审计、依据覆盖三个页签切换；手机端保持同样数据和操作，指标卡与逐主题缺口纵向排列，不删减权利层或覆盖层。该新增视图已完成 1440×900 与 390×844 生产预览浏览器验收，仍需 Edge 与固定 Android 设备复验。

### 5.8 设置、备份与恢复

- 修改默认规则只影响新案例；旧案例可批量生成新修订；
- 显示存储占用、离线包、最近备份和数据风险；
- 删除全部数据和恢复前先展示影响范围；
- 恢复前先校验格式、版本、完整性和空间，并生成当前安全备份；
- 当前 IndexedDB 普通构建为 Dexie v13 bridge，显式 production-v14 为笔记/事件增加案例活动流索引；production-v15 candidate 在 v14 的十五个用户数据分区之外新增 `revisionCalculationReceipts`，并保持既有行与索引不变。Schema 15 新 Revision 的创建基线与 Case、Revision、`birthFingerprints` 原子提交，显式计算快照只追加；`birthFingerprints` 仍是派生索引，不计入用户备份；
- 当前 full backup 为 v1.2，十六个用户分区全部进入规范排序、独立分区摘要、payload/envelope 摘要、安全备份、容量准入与恢复 CAS。full v1.1 严格冻结为十五分区格式，必须先按自己的 Schema、计数、摘要和关系验真，再只补空 `revisionCalculationReceipts` 迁入 v1.2，旧 Revision 不回填；full v1.0 及更早格式继续沿各自冻结契约逐代验真。core backup 仍为 v0.2，并继续拒绝遗漏非空计算收据；
- 当前浏览器聚焦证据包括 Edge 151 与 Chrome 150 的 v14→v15 专项门各 9/9、共 18/18：覆盖只新增空收据 store、创建基线和显式快照、非空 full v1.2 在全新 v15 context 恢复和再导出、多标签写锁、容量不足、启动校验/摘要/事务失败、`BOOT_OK` 中断及陈旧 target 阻塞。应用内浏览器另验证桌面历史收据与精确复演；此前 Event v7→v13→full v1.1 与离线、Chrome→Edge 组合门继续作为旧代兼容证据；仍缺整款产品其余 Chrome 门、Firefox、固定 Android/WebView、可靠文件落盘/分享与极端容量门；
- 冲突默认恢复为副本，覆盖必须逐类确认；
- 恢复失败时原数据库不变或自动回滚。

## 6. 全局状态规范

- 空状态只有一个主动作和一个次动作；
- 应用壳加载后不用全屏转圈；
- 错误说明哪些结果仍可信、哪些未完成；
- 离线是可工作的状态，不是错误页；
- 覆盖操作优先生成修订或备份；
- 笔记可以合并，出生输入和计算事实必须选择版本；
- 长任务可取消、恢复并保存阶段结果；
- AI、网络和在线知识库不可用时，确定性计算不消失。

仅在需要时显示顶部状态：

```text
离线 · 核心功能可用，地点搜索暂停
尚未备份 · 128 个案例仅保存在此浏览器
规则更新可用 · 已有命盘仍固定旧版本
存在未保存修订 · 保存为草稿或放弃
```

## 7. 原创视觉落点

- 工作台：岁序脊线连接最近研究；
- 命盘：纸白网格、墨色正文、玉青选择态；
- 时间轴：朱砂线只标当前节点和时间关系；
- 依据条：所有事实和观点的统一下钻入口；
- 典籍：现代书页阅读宽度，不仿旧纸；
- 对照：文字、边框和形状表达差异，不使用红绿吉凶；
- 哈基米角色只在空状态和帮助中低频出现。

## 8. 第一轮低保真原型
