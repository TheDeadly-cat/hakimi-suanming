# 八字旺衰现实专家审阅候选包 v1（2026-08-26）

## 结论

本轮只完成了现实专家审阅的机械候选包和失败关闭门，没有取得、伪造或推定任何现实专家身份、资质、独立性或意见。

当前状态仍是：需要两名身份、资质、审阅范围和彼此独立性均经现实核验的八字领域专家；已占席 `0/2`，独立专家意见 `0/2`，原始意见 `0/2`，`expertReviewBundleComplete=false`，`expertClaimsAuthorized=false`。

## 冻结输入

候选包位于 `content/bazi-strength-expert-review-packet.v1.json`，当前 packet ID 为 `hakimi.bazi.strength.expert-review-packet/1.5.0`，包摘要为 `cfe554b60b4698e0acd0a42e14484f4683eb7663d4f6862b767cf70404d2cd5f`。它逐字节绑定 12 个工程和证据输入：

- legacy-v13 的输入/事实契约与 rule profile；
- 旺衰规则候选、claim registry、敏感性审计；
- 七条工程 Binding 的 hash-only 候选账；
- 来源 binding 候选账及三层权利候选账；
- single-chart-report v1.7 独立 frozen golden `aba357d98a99271cc9a9b2727ad1c7c516424c94b7cf34f765cb38b0e9a74b29`。

任何绑定文件的字节漂移都会使审阅包校验失败；变更后必须生成新包并让两名专家针对新冻结输入重新审阅。候选包不绑定体系 manifest 自身，以避免 manifest 将候选包纳入文件闭包时产生循环摘要。

## 三类角色分账

1. 八字领域专家：只审阅旺衰规则、门派/版本、反例案例和高风险表达边界；不能签发权利法律结论、工程复现结论或公开发布授权。
2. 来源与权利复核者：只审阅作品、版本、载体和许可证据；不能签发八字内容真值、工程复现结论或公开发布授权。
3. 工程复现复核者：只审阅输入锁、算法锁、摘要与测试；不能签发门派真值、权利法律结论或公开发布授权。

这三类意见必须分别留账；其中任何一类通过都不能替代另外两类。

## 身份与隐私边界

真实姓名、联系方式、原始资质材料、机构原始证明、审阅历史和核验过程原件不得进入公开仓库。它们必须加密、离线保存。

公开包未来只允许保存受控身份绑定：`reviewerId`、公开显示名或受控匿名名、核验方法、资质摘要、核验日期、审阅范围、证据类型和核验人。公开身份绑定不是原始身份档案，也不等于资质本身。

## 独立性门

两名专家分别提交意见前，必须逐项核验并留存：机构/组织、师承、亲属或同住、共同商业利益、规则或案例集共同创作、共同服务、汇报/监督关系、事先接触另一意见、共享未公开来源/案例、共同依赖同一上游算法或教材。

“两个人”不自动等于“两份独立意见”。如果两人实际依赖同一上游判断，必须披露并降低独立性结论，不能用人数掩盖共同依赖。

## 审阅顺序与原件保存

固定顺序为：冻结输入、规则、来源、权利与 golden → 核验两席身份/资质/范围/独立性 → A 在不可见 B 意见时独立提交 → B 在不可见 A 意见时独立提交 → 同时封存两份不可变原始意见 → 并列列出一致与分歧 → 需要时分别追加独立补充 → 另发 reconciliation note。

补充意见和 reconciliation note 不得覆盖 A/B 原始意见。两席必须回答同一组四个旺衰方法问题，避免用不同题目制造表面一致。

## 分歧处理

- 门派分歧：拆成有版本的门派 profile；
- 输入语义分歧：拆成有版本的 input policy；
- 底本/版本/来源身份分歧：受影响 binding 继续 `unverified`；
- 规则解释分歧：并列保留，不选赢家；
- 工程错误：修复产物并让两席对新冻结输入重审；
- 高风险表达分歧：采用保守表达或不发布；
- 无法判断：`defer`。

禁止多数表决、意见平均或由生成模型自动选赢家。未解决分歧只能 `defer` 或 `reject`，不能直接采用。
