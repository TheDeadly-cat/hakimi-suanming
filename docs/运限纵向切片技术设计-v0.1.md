# 运限纵向切片技术设计 v0.1

> 状态：实施前设计草案  
> 适用范围：哈基米八字研究台响应式 Web / PWA 及后续 Android 安装包  
> 更新时间：2026-08-01

## 1. 已锁定的平台决策

1. **先完成响应式 Web / PWA。** 运限研究闭环首先在桌面浏览器与 Android Chrome 中实现、验证并支持安装为 PWA。
2. **Android 是第二阶段唯一原生适配目标。** Web 版本通过功能、离线、存储和响应式发布门后，再用平台壳适配 Android 安装包。
3. **暂不支持 iOS。** v1 不制作 iOS 安装包，不承诺 Safari / iOS PWA 功能等价，也不为 iOS 返回手势、文件系统、分享或商店审核增加专用实现。通用 Web 标准带来的偶然可用性不等于正式支持。
4. 运限首先是可复算的研究工具，不输出吉凶、事件预测或红绿灯式结论。
5. 原局、运限节点、真实事件和研究记录必须区分事实类型、来源及版本，不能在视觉或数据模型中混为一类。

## 2. 目标与非目标

### 2.1 本纵向切片要完成的闭环

```text
打开不可变修订
  → 载入版本化 TransitSnapshot
  → 按当前日期或指定日期跳转
  → 查看大运 / 小运 / 流年 / 流月 / 流日 / 流时分层轨道
  → 选择稳定节点并与原局同屏查看
  → 在该节点记录真实事件
  → 保存后从事件双向返回同一修订、时间轴版本和节点
  → 刷新、离线重开、前进后退仍能恢复
```

### 2.2 本切片不包含

- 不生成旺衰、格局、用神、神煞或吉凶断语。
- 不一次渲染或持久化一生全部流时节点。
- 不把计算结果藏在 Canvas 中；Canvas 或 SVG 只能作为非必要增强层。
- 不在 URL 中编码出生日期、时间、地点、坐标、姓名别名或事件正文。
- 不在 React 组件中自行推算干支或决定 DST 歧义。
- 不为 iOS 增加专有安装、手势、文件或布局分支。

## 3. 当前基线与必须先解决的问题

当前工程已有起运、交运时刻和十柱大运事实，也已有事件 CRUD 及临时 `FutureTransitNodeRef`。但完整切片仍缺：

- `TransitSnapshot` 的版本化 Schema、稳定节点 ID 和迁移策略；
- 小运及流年至流时的窗口化事实接口；
- 修订绑定的运限规则快照，页面不能继续隐式使用引擎默认规则；
- URL 驱动的运限视图、尺度、日期锚点和节点选择；
- 事件编辑器写入非空运限节点引用及事件到节点的反向链接；
- 分层轨道的 DOM、键盘、触控、降级和部分失败状态；
- Android PWA 与后续安装壳的返回手势、软键盘、安全区和深链验证。

在这些契约稳定前，现有大运界面只能标记为工程预览，不能作为完整 v1 运限时间轴。

## 5. 总体架构与数据流

```text
Revision + Rule snapshot + tzdb version
                  │
                  ▼
        transit-core 纯函数/窗口任务
                  │
                  ▼
       TransitSnapshot + stable refs
            │                 │
            │                 └── 可丢弃窗口缓存
            ▼
        React 运限工作台
      URL 状态 │ 焦点/滚动状态
            │
            ▼
       Event editor / list
            │
            ▼
      Dexie 持久事件与节点引用
```

### 5.1 分层职责

| 层 | 负责 | 明确不负责 |
| --- | --- | --- |
| `transit-core` | 版本化规则校验、父子区间、干支事实、稳定节点 ID、来源与已知缺口 | DOM、URL、Dexie、设备当前时间、事件正文、吉凶解释 |
| 应用服务 / controller | 组合修订与规则快照、请求窗口、取消过期任务、解析“今天”的修订时区日期 | 渲染样式、直接操作焦点 |
| React | 路由状态投影、分层 DOM、焦点、加载/错误状态、事件编辑交互 | 自行计算干支、静默解决 DST、生成随机节点 ID |
| URL | 可复制的视图、尺度、日期锚点、选中节点和时间轴版本 | 出生隐私、事件正文、滚动像素、未提交表单 |
| Dexie | 修订、持久事件、节点引用、迁移和可验证关联；可选窗口缓存 | 把缓存当作事实源、保存每个瞬时焦点或一生全部节点 |
| 平台适配层 | 当前时间、文件、分享、Android 返回行为和后续安装壳桥接 | 命理计算和规则选择 |

## 6. `transit-core` 与分析任务契约

### 6.1 纯计算约束

`transit-core` 必须满足：

- 相同修订、规则快照、tzdb 版本、窗口和引擎版本产生相同快照及节点 ID；
- 不读取 `window`、DOM、IndexedDB、设备语言或 `Date.now()`；
- 接收显式日期锚点和时区；“今天”由平台时间服务转换后传入；
- 所有区间采用 `[start, endExclusive)`，边界归属可独立测试；
- 返回事实、推导链、来源状态和已知缺口，不返回预测性文案；
- 支持按尺度和窗口请求，深层节点可懒加载；
- 支持取消或由调用方忽略过期结果，不能让旧请求覆盖新选择。

建议接口方向：

```ts
type TransitWindowRequest = {
  revisionId: string;
  revisionResultHash: string;
  ruleProfileDigest: string;
  timelineVersion: string;
  tzdbVersion: string;
  timeZoneDatabase: TimeZoneDatabaseSnapshot;
  timeZone: string;
  scale: "decade" | "year" | "month" | "day" | "hour";
  anchor: string;
  before: number;
  after: number;
};

type TransitNodeRef = {
  namespace: "transit-node";
  timelineVersion: string;
  nodeType: "dayun" | "xiaoyun" | "year" | "month" | "day" | "hour";
  nodeId: string;
};
```

实际名称以最终契约评审为准；关键约束是 `timelineVersion` 不可为空，`nodeId` 不依赖数组位置、随机数或本次加载窗口。

### 6.2 节点身份

- `revisionId + timelineVersion + nodeType + nodeId` 必须唯一重建节点。
- 大运节点可使用稳定柱序及实际区间共同校验；年、月、日节点使用规范历法键；流时节点必须能区分重复民用时刻。
- DST 回拨产生两个相同墙上时间时，节点 ID 以对应 UTC 瞬时点或显式 offset/fold 区分，不能只用 `YYYY-MM-DDTHH:mm`。
- 节点引用失效时，事件记录仍保留原始引用与版本；UI 显示“旧时间轴节点暂不可重建”，不能删除或偷偷改绑。

### 6.3 `TransitSnapshot`

快照至少包含：

- 修订 ID、结果 hash、规则 digest、引擎、时间轴及 tzdb 版本；
- 请求尺度、日期锚点、时区和窗口边界；
- 原局上下文；
- 六层节点窗口及父子引用；
- 当前日期节点、选中节点可用性和活动祖先链；
- 每层计算状态、来源状态与已知缺口；
- 快照 hash 或足以复算的规范输入。

快照是计算结果，不是用户编辑事实。允许重新生成，但同版本重算必须一致。

2026-08-03 实现状态：新生成和严格当前节点解析固定 `hakimi-transit:1.2.0`；1.2 完整快照 executor descriptor 精确绑定 bundled 2026c `timeZoneDatabase`，瞬时点↔民用时、节点墙上时间及本地柱统一使用同一个随包 resolver，命名时区计算禁用宿主 TZDB，并以 `Africa/Casablanca` 行为差异作为回归哨兵。只读关系复核仅额外白名单接受 `hakimi-transit:1.1.0` + algorithm v2，保留旧引用并重建其 node ID；1.1 没有完整快照 executor，不能把 node-ref 验真写成完整历史重放。bazi 0.4.0 本命盘只读复演仍只精确重算 time calibration、luck rule snapshot、历法/四柱 facts 与 result hash。老 Revision 没有持久化 relations/luck/transit 输出或绑定；研读页新增的是 `storedHistoricalOutputCompared=false` 的显式版本派生投影，不是旧输出比对，且全程零存储写入、不创建 Revision。历史 `browser-intl-unreported` 仍只能完整性验真。

## 7. React 状态职责

React 只保留界面所需状态，并按来源分组：

| 状态 | 唯一事实源 | 恢复方式 |
| --- | --- | --- |
| 当前修订 | 路径参数 | 深链 / 浏览器历史 |
| 视图、尺度、锚点、选中节点 | URL 查询参数 | 刷新、复制链接、前进后退 |
| TransitSnapshot | `transit-core` 请求结果 | 按 URL 和修订重算或读缓存 |
| 节点事件 | Dexie | 按 case / revision / node ref 查询 |
| 焦点节点、滚动窗口、展开状态 | React 临时状态 | 不承诺刷新恢复 |
| 未提交事件草稿 | React 表单状态；必要时另设显式草稿机制 | 不写 URL，不混入正式事件 |
| “今天” | 平台时间服务 + 修订时区 | 每次明确请求时重新解析 |

关键规则：

- 不同时在 URL、React state 和 Dexie 保存三个相互竞争的“当前节点”。
- URL 参数变化触发快照请求；请求具有序号或 `AbortSignal`，只提交最新结果。
- 箭头键移动焦点时不立即写浏览器历史；Enter/Space 或触控点击确认选择后才更新 URL。
- 打开深链时先校验修订和时间轴版本，再选择节点；不能先展示错误节点再闪回。
- 计算失败按层保存状态，高层成功结果不会因低层失败而清空。

## 8. URL 状态与历史记录

建议规范链接：

```text
/cases/{caseId}/revisions/{revisionId}
?view=transit
&scale=year
&anchor=2026-08-01
&node=year%3A2026
&timeline=transit-core%400.1.0
```

参数要求：

- `view`：`overview | structure | transit | research`；
- `scale`：`decade | year | month | day | hour`；
- `anchor`：按修订时区解释的规范日期或该尺度允许的规范值；
- `node`：经过编码的稳定节点 ID；
- `timeline`：创建节点的时间轴版本；
- 参数使用固定顺序序列化，未知参数不进入业务状态；
- 不加入出生字段、坐标、别名、来源备注、事件文本和滚动坐标。

历史策略：

- 明确选择页签、尺度、跳转日期或节点：`pushState`；
- 横向滚动吸附后更新窗口锚点、规范化非法参数：`replaceState`；
- 更新查询参数时不滚到页面顶部；
- `popstate` 恢复尺度、节点、焦点语义和详情，不恢复过期滚动像素；
- 浏览器直接刷新、PWA 冷启动和 Android 深链必须落到同一节点；
- 参数合法但节点不属于指定版本时，显示非阻塞失效提示，并保留可计算的上层轨道。

命盘页签应使用真实链接而非纯本地按钮，使复制、刷新、浏览器后退及在新标签页打开保持 Web 语义。

## 9. DOM 分层时间线与列表降级

### 9.1 语义 DOM

时间轴的必要信息必须存在于 DOM：

```html
<section aria-labelledby="transit-title">
  <header>工具栏与原局上下文</header>
  <section aria-labelledby="dayun-track-title">
    <h3 id="dayun-track-title">大运</h3>
    <ol>
      <li><button>第 3 柱 丙子 2016—2026</button></li>
    </ol>
  </section>
  <!-- 小运、流年、流月、流日、流时使用相同结构 -->
  <section aria-labelledby="selected-node-title">选中节点详情</section>
  <section aria-labelledby="node-events-title">真实事件</section>
</section>
```

- 每层是有标题的 `section`，节点保持有序列表和原生按钮；不滥用 `application`、`treegrid` 或自定义伪按钮。
- 轨道外层是可命名 `region`，节点按钮提供类型、干支、区间、当前/选中状态和事件数量的可读名称。
- `aria-pressed` 表示选中，`aria-current="date"` 表示当前日期；颜色不是唯一信号。
- 活动祖先链在 DOM 中有文字摘要，不能只靠跨轨道连线表达。
- Canvas/SVG 可画“岁序脊线”或连接线，但隐藏后仍有完整列表、详情和操作。

### 9.2 渐进增强与列表降级

- CSS 正常时，列表增强为横向轨道并使用原生滚动吸附。
- 不支持 `scroll-snap` 时仍可横向滚动，并提供“前一组 / 后一组”按钮。
- CSS 未加载或高对比模式下，六层退化为普通纵向有序列表，节点顺序和事件入口仍可用。
- JavaScript 某个深层窗口失败时，已载入的上层 DOM 保留，并在失败层显示范围、原因和重试按钮。
- 屏幕阅读器可使用“紧凑列表模式”，不强制逐个经过视觉缓存中的装饰节点。
- 虚拟化时为节点设置正确的 `aria-posinset` / `aria-setsize`，或明确只描述“当前窗口”，不能让辅助技术误以为窗口就是全集。

### 9.3 视觉层次

轨道自上而下：

1. 原局上下文；
2. 大运；
3. 小运；
4. 流年；
5. 流月；
6. 流日；
7. 流时；
8. 选中节点详情；
9. 真实事件及研究记录。

选中节点在各层居中对齐为一条细朱砂“岁序脊线”；玉青边框表示用户选择，朱砂实心圆加“今”字表示当前日期，空心圆表示确定性节点，菱形及文字数量表示事件。禁止用红/绿表示吉凶。

## 10. 响应式 Web / PWA 与 Android 适配

### 10.1 手机宽度与触控

必须验证 `360 / 375 / 390 / 412 / 430px`，390×844 为主要设计基准：

- 页面外边距 12～16px；
- 主要触控目标至少 `44×44px`；
- 每条轨道一次聚焦 3～5 个节点，节点宽度约 64～72px；
- 长区间、来源和完整日期放在下方详情，不把节点撑到只能看到两个；
- 使用 `overflow-x: auto`、`scroll-snap-type: x mandatory`、`scroll-snap-align` 和原生惯性滚动；
- 不实现自定义手势识别器，不阻断页面纵向滚动或浏览器边缘返回手势；
- 使用 `overscroll-behavior-inline: contain` 控制轨道串联滚动，但保留纵向滚动；
- 工具栏提供明确的前后窗口及尺度按钮，所有手势都有可点击替代；
- 底部为现有导航和 `env(safe-area-inset-bottom)` 留出空间；事件保存按钮不能被遮挡；
- Android 软键盘弹出后使用可见视口校验表单，不以固定 `100vh` 推算可用高度。

### 10.2 桌面和平板

- `≥1100px`：保留现有左导航、主工作区和右依据栏；运限详情在主区内，不与字段依据栏争抢状态。
- `768–1099px`：主区单栏，依据栏维持抽屉；轨道仍使用横向窗口。
- `1280/1440px`：每轨显示约 7～11 个节点，但正文详情维持可读行宽。
- 轨道标签、工具栏和原局上下文保持稳定尺寸，右依据栏开关不能导致节点宽度剧烈变化。

### 10.3 PWA 安装与离线

Web 纵向切片发布前须验证：

- Android Chrome 可通过浏览器标准安装入口安装 PWA，不制作误导性的假安装按钮；
- standalone 模式、状态栏、安全区、离线启动和深链冷启动可用；
- 首次成功加载基础资源后，断网仍能打开已保存修订、计算已支持运限、选择节点、读取/写入事件；
- Service Worker 更新失败时旧版本仍可启动，不能出现页面新代码配旧 Schema 的半升级状态；
- 需要联网的能力单独降级，不影响本地运限研究闭环。

### 10.4 后续 Android 安装包

只有 Web/PWA 发布门通过后才进入 Android 壳：

- 复用同一 React 页面、`transit-core`、Schema 和 Dexie 数据格式；
- 文件、分享、当前时间和返回动作只能通过已有平台接口接入壳能力；
- Web 备份导入 Android 壳后，修订 hash、时间轴版本、节点引用和事件关联必须一致；
- APK/AAB 中不得加入项目密钥或因壳层改变确定性计算；
- Android 屏幕旋转、字体缩放、显示缩放、状态/导航栏和软键盘单独验收。

Android 返回键和预测性返回手势的优先级：

1. 若节点详情中的临时菜单或对话框打开，先关闭最上层；
2. 若事件表单有未保存修改，显示可访问的放弃/继续编辑确认；
3. 若当前 URL 有节点或更深尺度，回到浏览器历史中的上一个运限状态；
4. 若处于命盘运限页，回到案例或上一个应用页面；
5. 只有应用历史栈为空时才交给系统退出。

Web 使用标准 History API；Android 壳只适配系统返回事件，不能另建一套与 URL 冲突的内部导航栈。横向轨道不得吞掉屏幕边缘返回手势。

## 11. Dexie 持久化边界

### 11.1 必须持久化

- 不可变修订及其规则快照、结果 hash；
- 用户创建的事件、日期精度、标签、来源、反馈、正文和删除状态；
- 非空的稳定 `transitNodeRef`（仅节点绑定事件）；
- 用户明确保存的研究视图；
- Schema 迁移、备份恢复所需版本和关联信息。

### 11.2 不作为持久事实

- 当前焦点、hover、滚动像素和展开状态；
- “今天”的瞬时值；
- 尚未提交的普通表单状态；
- 一生所有流日/流时节点；
- 可以由相同修订和版本重新生成的窗口快照。

如为性能增加 `transitSnapshotCache`：

- 键至少包含 `revisionId + revisionResultHash + ruleProfileDigest + timelineVersion + tzdbVersion + scale + window`；
- 缓存可随时删除，不进入事实完整性判断；
- 引擎、规则或 tzdb 变化自动失效，不把新计算覆盖进旧修订；
- 默认不把大体积缓存纳入备份；备份恢复后按需重算。

### 11.3 事件关联与迁移

- 新建节点事件时，在同一事务边界内校验案例、修订和节点引用结构。
- 日期事件允许 `transitNodeRef = null`；从运限节点创建的事件必须非空。
- 编辑事件默认保留原节点，只有明确“解除绑定 / 重新绑定”才改变引用。
- 删除修订前必须明确事件处置；不能留下看似有效但无法解释归属的引用。
- 旧 `future-transit-node` 引用通过显式数据库迁移转换；不能仅在渲染时临时改名。
- 无法迁移的旧引用保留原始数据和状态，显示可诊断错误并允许导出。

## 12. 键盘、读屏与无障碍

### 12.1 键盘模型

- Tab 依次进入工具栏、每条轨道的当前 roving 焦点、节点详情和事件操作；
- `← / →`：前后节点；
- `Home / End`：当前窗口首尾；
- `PageUp / PageDown`：前后一个节点窗口；
- `↑ / ↓`：父级/子级轨道，并尽量保持日期锚点；
- `Enter / Space`：确认选中节点并写入 URL；
- `Escape`：关闭临时界面或退出事件编辑，焦点返回触发位置。

快捷键在输入框、选择框和文本域内不得截获正常文本编辑。

### 12.2 状态表达

- 全局 `:focus-visible` 清晰可见；选中、今天、事件和失败均有文字或形状，不只用颜色；
- 节点可读名称包含层级、干支、区间、事件数量和状态；
- 选择后由 `aria-live="polite"` 宣布完整活动链，不重复播报横向滚动中的每个像素变化；
- 加载容器使用 `aria-busy`，每层错误有可聚焦重试按钮；
- 事件保存成功和失败使用状态区，不只短暂 toast；
- 详情或确认对话框关闭后恢复焦点；弹层不能焦点逃逸；
- 支持 200% 文本缩放、Windows 高对比模式和 `prefers-reduced-motion`；
- 正文和控件达到 WCAG 2.2 AA，装饰性连线不承担关键信息。

## 13. 性能与并发

### 13.1 窗口化原则

- 大运可以完整加载；小运和流年至流时按锚点窗口请求。
- 流时只计算可见窗口及少量前后缓冲，禁止预计算一生流时。
- 每轨 DOM 节点数量设置上限；移动端通常只需当前节点前后各 2～4 个，桌面可扩大但不得无限增长。
- 切换尺度或快速跳转时取消旧任务，或用递增请求序号丢弃迟到响应。
- 下层请求失败不清除成功的父层快照。
- 事件按 case / revision / node ref 建索引查询，不能为每个节点扫描案例全部事件。

### 13.2 初始性能门

正式预算需由 AT-09 固定设备基线确认；在此之前至少执行：

- 横向滚动期间不出现持续超过 50ms 的主线程长任务；
- 单次普通节点选择不触发整页或所有轨道重算；
- 可见轨道总 DOM 节点保持有界，深层加载不造成持续内存增长；
- Dexie 查询和窗口计算可取消或分块，不阻塞输入；
- 若纯计算在固定设备超过一帧预算，迁移到 Worker，但 Worker 只承载纯输入输出，不访问 DOM 或 Dexie；
- React 使用稳定 key 和节点引用；不得以数组下标作为跨窗口节点 key。

性能报告必须记录设备、浏览器版本、数据规模、是否离线、窗口大小和统计口径。

## 14. DST、精度不足与 unsupported 降级

### 14.1 DST 重复和缺失时刻

- 春季跳时产生的不存在民用时刻不能伪造流时节点；对应范围显示“当地时间不存在”及实际 offset 变化。
- 秋季回拨的重复民用时刻生成两个可区分节点，展示 offset 或“第一次 / 第二次”，稳定 ID 以实际瞬时点区分。
- 若规则要求用户选择 DST 歧义，UI 必须显式呈现候选，不能静默选较早或较晚时刻。
- 事件的原始日期精度与节点瞬时点分开保存；改变显示时区不能改写原事件输入。

### 14.2 unsupported 场景

以下情况按层降级：

- 修订没有唯一 UTC 瞬时点；
- 未知时辰或日期精度不足以产生目标层；
- 时间超出引擎、上游历法或 tzdb 支持范围；
- 修订所绑定的规则或时间轴版本当前不可执行；
- 时区不存在、历史 offset 无法解析或数据损坏；
- 某层计算异常或缓存校验失败。

降级要求：

- 保留已确定的原局和上层运限；失败层显示“未计算”，不得以空白表示“没有”；
- 显示失败范围、错误类型、所需输入及可行下一步；
- 不回落到设备时区、当前默认规则或另一个时间轴版本；
- 仍允许记录不绑定节点的日期事件和研究笔记；
- 旧节点事件可查看和导出，但明确标记节点暂不可重建；
- 错误状态可通过稳定 URL 和诊断信息复现，诊断中不泄漏出生隐私。

## 15. 测试矩阵

### 15.1 契约与 `transit-core`

- `TransitSnapshot`、节点引用和 URL Schema 的严格解析及未知字段拒绝；
- 同输入同版本的快照 hash、顺序和节点 ID 完全一致；
- 六类节点父子覆盖、半开边界、跨年/月/日和换日规则；
- DST 跳时、回拨、固定偏移、跨时区及历史 offset fixture；
- 精度不足、范围外、规则版本缺失和上游失败负向用例；
- 窗口拼接无缺口、无重复，迟到请求不会覆盖新结果；
- 每粒度金标准及差异归因；金标未过时保持工程预览门关闭。

### 15.2 URL 与 React

- 查询参数解析、规范顺序、编码、非法值修复及隐私字段扫描；
- 深链刷新、复制打开、前进/后退恢复同一尺度和节点；
- “今天”使用修订时区，覆盖设备时区已经跨日的情况；
- 六层轨道选择、活动祖先链、分层加载和部分失败；
- 箭头只移动焦点，确认后才创建历史记录；
- 节点事件保存非空引用，编辑保留引用，明确解绑后才置空；
- 从事件返回时间轴后定位到相同修订、版本和节点；
- 路由变化不无条件滚到页面顶部。

### 15.3 Dexie 与恢复

- 事件/修订/节点引用关联校验和事务回滚；
- 旧 `future-transit-node` fixture 迁移、无法迁移记录保留；
- 缓存失效、删除后重算、缓存损坏不污染事实；
- Web 备份恢复后节点引用和事件数量/hash 一致；
- PWA 离线重启后可继续选择节点并新增事件；
- 后续 Web→Android 壳恢复结果一致。

### 15.4 响应式、触控与 Android

- 自动截图：1440、1280、768、430、412、390、375、360px；
- 390px 每轨可聚焦 3～5 个节点，底部导航不遮挡操作；
- 44px 触控目标、横滑、纵向页面滚动、滚动吸附和无 `scroll-snap` 降级；
- Android Chrome 浏览器与已安装 PWA 的软键盘、安全区、显示缩放、字体缩放和旋转；
- Android 返回键/预测性返回按既定优先级工作，横向轨道不吞边缘手势；
- standalone 离线深链冷启动和 Service Worker 升级失败回滚；
- 后续 APK/AAB 壳冒烟及硬件返回验证；
- **不把 iOS/Safari 测试列为 v1 发布门。**

### 15.5 无障碍与性能

- 全流程仅键盘完成：日期跳转、尺度、六层轨道、节点选择、事件创建和返回；
- 屏幕阅读器读取层级、节点状态、活动链、加载和失败；
- axe、人工焦点顺序、200% 缩放、高对比模式和 reduced motion；
- 固定中端 Android 设备记录计算、首次渲染、节点选择、滚动长任务、DOM 数和内存；
- 快速连续跳转、离线、缓存未命中和大量事件压力测试。

## 16. 纵向切片验收标准

只有同时满足下列条件，才可把本切片从“工程预览”提升为 v1 功能：

1. 指定不可变修订可生成版本化 `TransitSnapshot`，六层节点具有稳定引用和可审计推导链。
2. 原局、大运、小运、流年至流时与选中节点同屏；未支持层明确降级，不伪造结果。
3. “今天”和指定日期跳转按修订时区工作，刷新及前进/后退恢复一致。
4. 任意可用节点可创建真实事件，事件保存节点引用并可双向返回。
5. URL 不含出生隐私，直接深链、PWA 冷启动和离线重开均定位一致。
6. 360～430px 与 1280/1440px 功能等价；手机每轨聚焦 3～5 节点，主要目标至少 44px。
7. 完整键盘与读屏流程可用，颜色不承载唯一信息，关键页面达到 WCAG 2.2 AA。
8. DST 重复/缺失时刻、精度不足、版本缺失及不支持范围均有 fixture 和可解释降级。
9. 深层窗口按需计算，滚动和选择通过固定 Android 性能门，不预计算一生流时。
10. 响应式 Web/PWA 先通过发布门；随后 Android 安装包通过屏幕、安装、返回手势及 Web 备份恢复测试。
11. Web/PWA v1 发布说明明确支持桌面浏览器与 Android Chrome/已安装 PWA；Android APK 后置，iOS 暂不支持。

## 17. 推荐实施顺序

1. 完成 AT-01～AT-04，锁定 `TransitSnapshot`、节点引用、规则快照和 DST 语义。
2. 实现 `transit-core` 的大运→流年最小窗口，再依次扩展小运、流月、流日和流时；每层先有 fixture 和部分失败契约。
3. 完成 URL 状态机及命盘“运限”页签，建立深链、刷新和历史恢复。
4. 实现语义 DOM 的分层轨道、原局上下文和节点详情；随后添加横向滚动吸附增强。
5. 从研究日志中抽取可复用事件编辑器，完成非空节点绑定与双向链接。
6. 增加 Dexie 迁移、索引、缓存边界和备份恢复测试。
7. 完成 360～430px、键盘、读屏、DST、离线及固定 Android 性能验收。
8. Web/PWA 发布门通过后再接 Android 壳、系统返回手势、安装与恢复；不启动 iOS 工作流。

此顺序允许每增加一层都保持可运行、可复算、可降级的研究闭环，同时避免在领域契约未稳定前先做不可维护的整页时间轴。
