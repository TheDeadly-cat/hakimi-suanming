## 4. 独立性、意见与分歧边界

- 两席 identity binding 必须绑定不同 reviewer，身份核验不得由 reviewer 自己执行；核验事件与 identity record 必须在 pairwise assessment 开始前形成。仓内只允许受控公开投影与仓外加密 dossier 的不透明引用。
- 原始意见必须在 pairwise assessment 完成后开始，四题各一次、response ID 全局唯一；原始意见的 prior exposure 只能是 `none_declared`，高风险边界只能是保守表达、延后、不发布或不适用。
- 十个 independence factor 必须逐项、按固定顺序评估，`assessmentStartedAt <= assessedAt <= assessmentCompletedAt`；共同上游披露、冲突、unknown 或 unresolved 不得导出独立结论。当前 collection eligibility 只能为 `blocked`。
- 两份原始意见必须分别绑定 A/B 两席，并各有一个对应 seal receipt；seal 元数据不能冒充原件真实性、custodian 身份或不可覆盖证明。
- 四题 comparison 必须被 agreement/disagreement 完整且互斥覆盖；证据引用必须对应同题 A/B response。多数表决、意见平均、模型选赢家和未解决即采用均禁止。
- `engineering_error` 必须要求新 packet 与两席重审；`high_risk_expression` 只能保守表达或不发布。
- reconciliation dispositions 必须与 inventory disagreements 精确双射，且不得覆盖原始意见或直接改产品；每份 supplement 必须被至少一个非空 proposal ref 引用，不能成为 orphan。

## 5. Bundle 不是引用清单自签

通用 record/JSON preflight 遇到 `bazi_expert_review_bundle_v1` 会固定拒绝；必须调用专用 bundle 入口并同时提供完整 `componentRecords`：两份 identity、一个 pairwise assessment、两份 original opinion、两份 seal、一个 inventory、条件性 reconciliation 以及 supplements。

专用入口会逐项执行完整 record preflight，并交叉核对共同 session/purpose、reviewer/slot、全部内部 component refs、opinion/seal 对应、四题 response refs、disagreement/reconciliation 双射和实际组件时间。identity、independence、opinion、seal、inventory、supplement/reconciliation 与 bundle 的 record 必须在下游消费前形成；纯虚构 `recordId + recordDigest`、自报 chronology、orphan supplement 或缺失 reconciliation 不能通过。外部 verifier/evidence/private/first-seen/retrieval refs 仍只做格式预检，不属于内部 component DAG 闭包，也不建立真实性。

即使完整 synthetic 图在测试中结构预检通过，返回仍是 `bundleAssemblyStructurallyPreflighted=true` 与全部真实性/专家门/发布投影 false；它不是现实 `expert_review_bundle`，也不使现实实例数从 0 增加。
