## 2. 已落盘的核心合同

### 2.1 binding 与 evidence subject

- 12 条报告 binding 与显式 `evidenceSubjectId` 的 key 集合必须完全一致，subject 必须唯一且能由知识层注册表解析。
- 允许的 subject 必须为活动的 `interpretive_claim`，且 `requiredForV1=false`；这表示它是解释证据主题，不是 v1 机械排盘成立的前置真值。
- Citation 的 target 必须精确绑定当前 Revision 的 `chart_field` 与该 binding 的 subject。伪造、未知、pillar 目标、移植到另一 binding、换成另一合法 subject 或混合不存在 Revision 的 target 都失败关闭。

### 2.2 KnowledgeDocument 与 exact quote

- 构建器在接纳前按实际文档内容重算 SHA-256；调用方伪造 `contentHash`、章节范围或文档正文不能直接进入报告。
- Citation 的文档引用、声明摘要、section、locator 和 exact quote 必须与同一冻结 KnowledgeDocument 闭合。
- 报告不把来源正文复制进 admission ledger；引用和摘要只承担机械绑定与复核定位作用。

### 2.3 `C#`／`D#` 引用闭合

- Citation reference `C#` 按报告规范顺序生成并与可见 binding target／证据主题标签精确闭合。
- Document reference `D#` 按文档首次引用连续生成；同一文档重复出现复用同一 `D#`，同一 `D#` 必须对应完全相同的来源与权利投影，而不只比较 `documentId` 或 `contentHash`。
- 汇总中的目标、文档和权利数量按唯一实体计算，不能用重复 Citation 放大覆盖率或准入计数。

### 2.4 每条 binding 的机械准入

机械准入能够区分以下事实状态：

1. 没有匹配 Citation；
2. 只有 candidate；
3. 存在 rejected 且没有可接纳 verified 记录；
4. verified Citation 已闭合，但相应文档版本不允许报告内再分发；
5. verified Citation 与可再分发 SourceRights 记录共同闭合。

多目标情况下按唯一 binding target 计数。跨 binding、跨文档版本、摘要漂移或记录被篡改均不得升级。

### 2.5 SourceRights 失败关闭边界

- 作品层、版本／载体层、分发策略和 reviewer decision 使用受限枚举与精确字段合同；未知或 blocked 状态不能伪造为 redistributable。
- “verified-redistributable”只表示提供给构建器的结构化记录满足本项目机械合同，不是法院、版权方或法律顾问确认的权利结论。
- `sourceIdentityStatus` 固定为 `not_assessed`；`citationTargetEstablishesSourceIdentity=false`。Citation 指向某主题或文档，不建立作者、出版者、转录者、reviewer 或权利人的现实身份。
- 权利记录的双 reviewer 字段只证明两个结构化记录位存在并满足合同，不证明两位真人、现实身份、彼此独立或有权作出法律判断。

### 2.6 full、DST withheld 与 anonymous

- full 报告的 `admissionSummary` 带 `visibility=full`。实际执行机械评估时使用 `evaluationStatus=evaluated`。
- DST／时间上下文未决导致解释整体扣留时，使用 `evaluationStatus=not_evaluated_interpretation_withheld` 且相关计数全零；全零不能被解读为“已评估但没有问题”。
- anonymous 报告使用固定 redacted 准入形状，不携带 `evaluationStatus`、动态 Citation／rights 状态、subject、文档、reviewer 或权利明细，也不复制来源正文。它仍按既有匿名报告合同保留逐句工程状态与允许展示的规范叙事；匿名不是“移除所有解释正文”，也不能替代用户对导出内容的隐私判断。

### 2.7 Schema、异步 validator 与 frozen golden

- 报告 Schema、构建器与异步 validator 对上述关系做一致性复核；篡改 Citation reference、subject、summary、redistributable 状态、document reference 或文档摘要会由 Schema 或 validator 拒绝。
- `1.7.0` 使用独立冻结 golden，保留 `1.6.0` 历史 golden 作为迁移差异基线；二者不相互覆盖。
- golden 只证明确定性工程投影被显式冻结，不证明其中命理表达正确、来源获得许可或已获发布授权。

## 4. 8 sources／12 bindings 现在证明什么

可以证明：

- 项目有一份有限、显式、可机械复核的 8-source／12-binding 来源资格基线；
- 报告不会仅凭 URL、书名、版本别名、candidate Citation 或不匹配的权利记录提升准入；
- 对 exact quote、文档摘要、subject、Revision target、引用编号、匿名边界和汇总计数的篡改有失败关闭合同。

不能证明：

- 12 条 binding 已全部拥有真实、可靠、获准使用的来源正文；
- 古籍的作者、版本、底本、转录层、评注层或网页载体权利已逐项解决；
- SourceRights 记录中的声明在法律上成立；
- 命理解释具有术数真值、科学有效性、专家共识或面向个人的确定性；
- 紫微、西洋、吠陀等其他体系已经由八字报告合同一并产品化；
- 项目可以公开发布。
