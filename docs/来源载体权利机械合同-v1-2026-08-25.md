# 来源载体权利机械合同 v1

日期：2026-08-25

状态：合同、4 条三层权利候选与 5 个载体观察层已落盘；正式来源实例、双人复核与法律结论未完成

## 1. 固定边界

- 发布治理继续固定为 `legacy-v13 / targetSchema 13 / migrationId null`。
- 本次不改变 fail-closed、mutation epoch、恢复或迁移边界。
- `publicDeploymentAuthorized=false`。
- `expertClaimsAuthorized=false`。
- 本次未访问任何第三方后台、付费内容、prompt、知识库、断语库或受保护资产，也未取得任何新的许可。

## 2. 合同目的

现有 `SourceRightsRecord` 继续负责作品层和现代版本层的权利状态。新增独立 `SourceCarrierRecord`，负责记录实际取得或物化正文的载体身份、摘要、访问方式、载体权利、存储策略和复核状态。

三层必须分账：

```text
作品层 SourceRights
→ 现代版本/编校层 SourceRights
→ 实际载体层 SourceCarrier
```

作品进入公有领域，不自动证明现代排印、校注、扫描图、网站整理文本、OCR 结果或商业数据库载体可以复制和再分发。

## 3. `SourceCarrierRecord` v1

当前合同至少绑定：

- `carrierId`；
- `documentId` 与 `documentContentHash`；
- 载体类型、提供方、取得时间、访问方式和可审计 URL；
- 正文、图像、OCR 摘要；
- 载体权利状态、司法辖区、许可标识、版权说明和证据链接；
- 复制、必要引用、再分发三项独立权限；
- `public_repo / private_vault / link_only / do_not_store` 存储策略；
- 不同复核身份的签署及编辑时间线。

合同采用严格字段解析，未知字段不能静默进入记录。

## 4. 失败关闭规则

公开随包材料只有同时满足以下条件才可通过机械准入：

1. `SourceRightsRecord` 的作品层和现代版本层均允许再分发；
2. `SourceRightsRecord` 与 `SourceCarrierRecord` 指向同一 `documentId` 和正文 SHA-256；
3. 载体权利为已核清的公版、许可或已核验项目原创；
4. 复制、必要引用、再分发三项权限均为 `true`；
5. 存储策略为 `public_repo`；
6. `contentDigest` 精确等于实际文档正文 SHA-256；
7. 载体权利证据链接非空；
8. 至少两个不同复核身份完成载体分发复核。

权利未知不能授予任何复制、引用或再分发权限；受限载体不能允许再分发；`link_only` 只能保存链接元数据，不能复制正文或进入公开随包产物。

## 5. 构建准入

当前构建入口使用 `content/knowledge/manifest.v2.json`。每个条目必须同时包含：

```text
path
documentId
contentHash
sourceRights
sourceCarrier
```

构建门会在读取任何正文前先核对路径、作品／版本层记录、载体层记录和完整目录库存。正文只通过 held handle 有界读取；每级目录链、文件 endpoint 和 realpath 在读取端点复核，读取后再扫描完整库存。实际正文 SHA-256 与规范化内容来自同一 Buffer。缺少载体记录、摘要不一致、link-only、权利未知、未完成双人复核、symlink／junction、hardlink、超限文件或库存变化均失败关闭。

`manifest.v1.json` 作为历史空清单保留，不再是当前构建入口。v2 当前仍为空清单，因此本次没有新增随包正文。

## 7. 后续逐条冻结要求

每条 binding 后续必须分别保存并核验作品身份、版本身份、载体身份、正文摘要、最小充分 exact quote、准确 locator、作品层依据、版本层依据、载体层依据、分发策略和两份独立复核。不能再分发的内容只能保持 private 或 link-only，不能进入公开仓库或构建产物。

工程启发式、权重、衰减和分数语义若没有真实古籍直接依据，必须如实标记为工程启发式或观察量，不能包装成古法原文。
