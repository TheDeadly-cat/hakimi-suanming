# GitHub 相似项目筛选（2026-08-01）

## 结论

没有发现适合“整仓搬运”并直接作为本项目 Web v1 基座的仓库。当前工程已经具备本地优先、修订不可变、规则锁版、摘要验真、事件验证、批量导入和原子恢复；直接换成外部项目会丢失这些边界，也会把许可证、典籍版权和未经验证的命理结论一起带进来。

可采取的方式是：只迁移经过文件级审计的 MIT 工程机制，保留原版权声明，并用本项目契约和金标重新实现/验收。此次筛选没有复制任何外部代码、图片、文案、典籍正文或数据集。

## 若以后迁移外部代码，必须先过的门

1. 锁定具体 commit，不跟随 `main` 漂移。
2. 核对根许可证、目标文件头、第三方依赖和资产/字体/图片许可；README 的一句“开源”不等于所有内容均可复制。
3. 建立来源台账：仓库、commit、文件、许可证、修改说明、保留的 copyright notice。
4. 排除典籍扫描件、现代校注/翻译、付费产品文案、商标、截图和未明确授权的数据集。
5. 外部算法先进入隔离适配器，只做差分候选；没有专家签字与金标时不能替换当前确定性核心。
6. 运行安全审计、依赖审计、契约测试、浏览器/移动验收和离线回归后，才能进入主线。

## 对当前实现的直接影响

- 继续保留自己的 React/Vite/PWA 与确定性计算架构，不执行整仓替换。
- 知识库优先支持用户本地 Markdown/TXT；项目不内置来源或权利状态不清的典籍全文。
- 采用“文献内容摘要 + 章节/行号 + 原文摘录 + 目标反向引用”的结构化 Citation，比复制外部静态文章页更适合研究用户。
- 视觉上只学习“阅读器、目录、移动列表/正文切换”这类通用机制，不复刻问真八字或任何开源项目的独特视觉表达。
