# 阶段 C：紫微 iztro 顶层许可证双隔离构建告示传播与验真 v1

日期：2026-08-30

## 结论

本工作包把 `iztro@2.5.8` npm 安装树中观察到的顶层 `LICENSE` 正文冻结为一份项目受控的 1,073-byte 候选副本，并在以下两个独立紫微 Vite 构建中传播为同源、可直接读取的独立资产：

- `ziwei-browser-preview`
- `ziwei-browser-workspace`

两个源码 HTML 均在真实 `<head>` 下保留唯一的：

```html
<link rel="license" type="text/plain" href="./licenses/iztro-2.5.8-LICENSE.txt" />
```

受控 verifier 每次在其自有临时目录重新执行两次 Vite build，再对输出树、`index.html`、许可证资产、构建输入 attestation 和非 sourcemap Worker 做端点验真；不读取或复用仓库中既有 `dist`。它在每次构建前后及两次构建之间比较 15 个受控输入，并固定观察 Vite 7.3.6 的 package manifest、launcher、CLI 三个端点及根 lock 的语义身份。临时输出在核对后删除。

这是一份来源／权利治理的机械子证据，不是法律意见、许可清权、专家审定、紫微体系准入或发布授权。

## 机械门

正向门要求：

1. 本地受控副本与安装树顶层许可证均精确匹配 1,073 bytes 与固定 SHA-256；
2. 安装树 `package.json`、CommonJS 入口和顶层许可证三个固定端点匹配预期身份；
3. package-lock closure 的 `iztro@2.5.8` 版本、resolved URL 与 SRI 精确匹配；
4. Vite 7.3.6 的 package manifest、launcher、CLI 三个固定端点同时匹配 bytes 与 SHA-256，根 lock 的请求版本、resolved URL、SRI 与 bin 路径语义匹配；
5. 每次构建前后以及两次构建之间的 15 项受控输入身份相等；子进程不继承 `NODE_*` 或 `VITE_*` 环境变量；
6. 两个真实 Vite config 均通过共享主构建插件发射 held license bytes 和 canonical input attestation；preview attestation 固定 7 项输入，workspace attestation 固定 8 项输入；
7. 两个真实源码 HTML 与两个 fresh build HTML 均只有一个直接 `<head>` 子级、同源、精确路径的 `rel=license`；
8. 两个 fresh build 均只有一个非 sourcemap Browser Worker，并携带当前 adapter 的版本与 SRI 身份标记；这不证明依赖代码已经在浏览器执行；
9. evidence child 必须等于当前 builder 的唯一 canonical pretty JSON；duplicate key 即使被 `JSON.parse` 折叠成同一对象也拒绝；
10. 低层 fixture receipt、clone、同形对象、workspace root 重绑定和重新签摘要后的提权字段均不能构造正式 child。

负向门覆盖许可证缺失、截断、BOM、CRLF、等长篡改、额外许可证资产、空构建、仅 sourcemap Worker、身份标记缺失、`base` 改写、重复／外部／惰性／foreign／属性伪链接、symlink／junction、hardlink、伪 Vite launcher、Vite lock 漂移、构建输入前后不一致、缺失／篡改／伪造／重复 attestation、`NODE_OPTIONS --import` loader、duplicate-key evidence，以及 parent／coverage／rights／expert／release／public／mutation epoch 提权。
