# 首批典籍来源与权利审计（2026-08-01）

## 结论先行

当前生产构建内置典籍正文数量保持为 **0**。本轮只建立来源候选、权利判断方法和构建门，不把“古籍作品已进入公版”误写成“任意现代排印、校点、扫描或数字化文本都可随软件分发”。

权利状态与命理验证状态是两条互不替代的轴：

- `SourceRights` 只回答某个精确正文快照能否保存、引用或随软件再分发。
- Citation / provenance 的复核状态只回答该原文是否足以支持某条规则或字段。
- 一份资料可以合法再分发但尚未形成可靠命理依据，也可以是用户有权本地研究但项目无权将其打包给其他人。

本文是工程审计记录，不构成法律意见。

## 法律与许可基线

《中华人民共和国著作权法》第二十二条规定署名权、修改权和保护作品完整权的保护期不受限制；第二十三条规定自然人作品的相关财产权通常延续至作者终生及死亡后五十年。即便古代作品的经济权利期限已经届满，产品仍应保留作者、版本和改动说明，并继续单独审计现代整理成果。[全国人大：中华人民共和国著作权法](https://www.npc.gov.cn/c2/c30834/202011/t20201119_308796.html)

Wikimedia 使用条款说明，站点文本通常按 CC BY-SA 4.0 与 GFDL 提供，再利用时需要署名、许可链接，并在改编时遵守相同方式共享和标注变更；被导入的文本还可能有额外要求。[Wikimedia 使用条款](https://foundation.wikimedia.org/wiki/Policy%3ATerms_of_Use) [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)

因此，项目台账必须同时记录：作品层权利、所用版本/数字化文本层权利、精确内容哈希、来源页面、取得时间、署名/许可要求和复核记录。

## 生产构建门

任何准备进入 PWA / Android 安装包的正文都必须同时满足：

1. 文件在随包 manifest 中有唯一记录，且文件 SHA-256 与台账完全一致。
2. 古代作品层和现代版本/校点/数字化文本层都已得到独立、明确的权利结论。
3. 分发策略为 `redistributable`，并有至少两个不同复核身份留下可追溯记录。
4. 权利依据、证据链接、司法辖区以及必要的许可证或版权说明齐全。
5. 署名、许可链接、改动说明和 ShareAlike 等义务已有可执行的产品呈现方案。
6. 任一层为未知、受阻、仅限本地，或正文哈希不匹配时，生产构建直接失败。

用户导入的 Markdown / TXT 一律初始化为“用户提供、未核验、仅本机”，普通界面和普通仓储 API 都不得把它提升为随包资料。命理引用的双人核验也不能反向改变其版权状态。

## 下一次允许加入正文的门槛

先选择一部完整性较高、底本信息清楚的作品，固定一个精确文本快照；再逐项完成版本校勘、权利证据、署名页面、许可相容性、哈希和双人复核。只有该单本样板通过构建门后，才扩展第二部，避免一次搬入大量来源不明的古籍。
