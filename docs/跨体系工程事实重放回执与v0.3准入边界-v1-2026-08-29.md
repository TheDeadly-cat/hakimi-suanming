## 1. 结论（原 v1 记录）

旧 `cross-system-readonly-comparison/0.2-draft` 只能证明调用方提交的 JSON 与其自行填写的
`contentSha256` 一致。调用方可以虚构事实、规则身份和来源，再重算摘要而通过；成功结果还曾直接
别名调用方对象，验证后可以被修改。因此旧 `factsFrozen=true` 不能解释为 producer 事实已冻结。

当前已升级为 `cross-system-readonly-comparison/0.3-draft`：候选摘要必须逐字段、逐规则身份、
逐工程依据和逐 receipt reference 与 bundled 工程事实回执 registry 精确一致。registry 由独立
Node 证据工具从当前体系 producer、体系自有 projector、已验证独立 manifest 和来源 requirement
ledger 重新构建。仅重算 envelope `contentSha256`、复制另一体系 receipt、修改 projector／producer／
manifest identity 或提权，都不能生成通过路径。

这只建立两条当前工作区的离线工程重放闭包：紫微和西洋。它不建立领域事实、来源正文、exact quote、
历史执行真实性、现实专家意见、权利法律判断、正式体系准入、浏览器／部署运行时、发布就绪或公开发布授权。

## 4. v0.3 验证和 mutation 边界

v0.3 先对输入建立有界、descriptor-safe 的被动 JSON 快照；accessor、Symbol、自定义 prototype、
稀疏数组、循环、非有限数和资源超限均失败关闭。校验、canonical digest 和返回值只作用于该脱离副本；
成功值递归冻结，不再与调用方对象别名。bundled registry 也在模块初始化时脱离 JSON import 别名并递归冻结；
验收时重算 registry、两份 receipt 及 projected-facts digest，并核对固定体系顺序、状态与 receipt 身份。

候选必须精确绑定 bundled registry：

- 固定 `registryId / registryDigest / receiptId / receiptDigest / receiptClass`；
- 固定本体系 projector 输出的字段、顺序、值和工程回执引用；
- 固定 producer 规则身份和工程 evidence refs；
- 固定 `productionEligible=false / expertTruthClaimed=false / successReceiptIssued=false`；
- 固定无评分、无加权、无多数表决、无模型仲裁、无自动人物合并、无概念等价推断；
- 观察仍是 `manual_explicit_entry_unverified / unreviewed_observation`，不是专家判断。

registry 原始 JSON 的 hash 与 parse 使用同一 Buffer，各被绑定文件也各自使用单次读取 Buffer；但 nested
verifier 会重读，跨文件不是原子快照，两体系重放也不是一个原子 pair。默认发布线仍是 Schema 13，
不存在 mutation epoch，故 `epoch=null`，区间 mutation 与 ABA 均未排除。
