# 阶段 E：紫微公开候选预筛 CLI 运行时边界勘误

日期标签：2026-09-03（仅为不受信本地日期标签）

## 结论先行

本勘误以 append-only successor 方式收窄旧固定 CLI 的声明，不修改或替换既有紫微公开候选预筛五件套。旧机器账的四条公开发现线索、`0/2` 专家、2 条 partial candidate、`0/27` binding 与全部未授权边界均保持原样。

旧 CLI 能拒绝在其模块开始执行时仍然可见的参数、错误 cwd、`NODE_OPTIONS`、`NODE_PATH` 和 `process.execArgv` preload 标记；这只是可见输入卫生检查，不是安全边界。Node 的 preload 在 CLI 模块求值前已经获得任意本地代码执行能力，可以删除这些可见标记后再让旧 CLI 输出 `..._OK`。

因此明确撤回或限定以下表述：

- `allPreloadsRejected = false`
- `wholeProcessOffline = false`
- `cliOutputTrustedAttestation = false`
- `launcherIdentityEstablished = false`
- `loaderIdentityEstablished = false`
- `nodeRuntimeIdentityEstablished = false`
- `hiddenPreEvaluationExcluded = false`
- `visibleInputGuardSecurityBoundary = false`

这不是攻击者获得了新的能力；能够执行 preload 的调用方在 CLI 运行前已经拥有任意本地代码执行能力。本勘误记录的是旧 CLI 不能把自己的输出提升为 hostile-launcher 条件下的可信证明。

## 两条已复现的操作员 PoC

两条复现均没有联网，也没有改动项目文件。它们只在各自 Node 进程内修改可变的启动可见状态。

1. direct `--import`：preload 先执行 `process.execArgv.length=0`，旧 CLI 随后退出码为 0，并输出旧 `ZIWEI_EXPERT_PUBLIC_CANDIDATE_PRESCREEN_OK` 前缀。
2. `NODE_OPTIONS --import`：preload 先删除 `process.env.NODE_OPTIONS` 并清空 `process.execArgv`，旧 CLI 随后同样退出码为 0，并输出同一旧 OK 前缀。

两次旧 stdout 都是 611 bytes，SHA-256 都是 `8098f69663eb58cf04d333ee546f5e38e8ee06833700295e940622591584b5bf`，stderr 都是 0 bytes。这个 hash 只冻结所见输出字节，不使该输出成为可信 attestation。

## 仍可成立的窄声明

在没有 preload、cwd 正确且调用参数为空的普通干净调用中，旧预筛 full loader 仍能机械核验其固定本地工件、上游私有品牌与零实例边界。旧机器账及其公开来源观察不由本勘误重抓或重解释。

新勘误 verifier 自身源码只做静态 token 检查：不得直接导入 `node:http`、`node:https`、`node:net`、`node:tls`、`node:dns`，也不得调用 `fetch(`。这个结论只覆盖固定的 verifier/lib 自身源码，不覆盖 preload、launcher、Node runtime、loader hook、隐藏的求值前代码或整个进程。

新 CLI 使用 scope-explicit 前缀，并在输出中直接给出 `cliOutputTrustedAttestation=false` 与 `wholeProcessOffline=false`。即使调用方隐藏 preload 标记后到达该输出，也不能把它解释为 hostile runtime 的可信证明。

## 仅限模块求值后的 primordial 加固

勘误 verifier 在模块求值时捕获 `WeakSet` 构造器、`WeakSet.prototype.add/has`、`Reflect.apply`、`Object.freeze`、`Object.isFrozen` 与 `Object.values`，其 private brand、deep-freeze 和 summary 路径不再调用 live `WeakSet.prototype.add/has`。定向测试在模块导入后把这些全局入口改成恒真、恒假或抛错实现，假对象仍必须被拒绝；污染前已由 full loader 铸造的真实品牌在导入后污染下仍可验真并生成 summary。污染后重新调用 loader 不承诺成功，允许 fail closed。

这只建立 post-import primordial resilience 的机械测试结论。它不证明模块求值前的 primordial 未被 preload 污染，不证明 launcher、loader 或 Node runtime 身份，也不把 visible input guard 升级为安全边界。`allPreloadsRejected`、`wholeProcessOffline`、`cliOutputTrustedAttestation`、launcher/loader/runtime identity 与 `hiddenPreEvaluationExcluded` 因此继续全部为 `false`。
