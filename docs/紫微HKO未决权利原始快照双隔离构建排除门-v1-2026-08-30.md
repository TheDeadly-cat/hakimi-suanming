# 紫微 HKO 未决权利原始快照双隔离构建排除门 v1

日期：2026-08-30

## 结论

本切片为紫微体系增加了一条 fail-closed 的构建产物排除门：在固定的 `browser-preview` 与 `browser-workspace` 两次全新隔离 Vite 构建中，递归扫描每一个输出文件（包括 JavaScript、二进制 asset 与 source map），拒绝当前 HKO 2023–2028 六份已知响应正文的精确已知表示。

本门只证明两个点时临时输出树中没有观察到这些精确已知表示。它不证明未知编码、分片、重排或其他转码后的正文一定不存在，也不把当前工作区改造成 link-only 存储。

验证器先以 held-handle 方式读取并核对以上两个端点，再逐年核对 gzip bytes、gzip SHA-256、解压后的 raw CSV bytes 与 raw SHA-256。任何身份漂移都会在构建前或构建后 fail closed。

## 排除范围

当前实现扫描六类精确表示：

1. 完整来源证据 JSON bytes；
2. 完整原始快照 fixture JSON bytes；
3. 两个受限 artifact 的工作区相对路径与 basename UTF-8 引用；
4. 六份 gzip Base64 payload 的 UTF-8 bytes；
5. 六份 gzip 二进制 bytes；
6. 六份解压后 raw CSV bytes。

输出树若直接暴露两个固定证据文件的 basename，或只在 JavaScript/source map 内容中留下相对路径或 basename 字符串，也会失败。扫描覆盖递归输出清单中的全部普通文件，而不是只检查主 bundle 或 license asset。

只含资源 URL、年份、byte length 与 SHA-256 的元数据不会因本门被拒绝；这保留了后续 link/hash-only 设计空间，但并不代表当前存储已成为 link-only。

## 定向证伪

`scripts/verify-ziwei-iztro-isolated-build-license-notices.test.mjs` 已覆盖以下失败样本：

- 受限 fixture basename 直接出现在输出路径；
- 伪造或 same-shaped HKO material snapshot 试图进入验证器；
- 两个固定 HKO material 输入任一发生字节漂移；
- 完整来源证据 JSON 被复制到普通 asset；
- 完整原始 fixture JSON 被复制到普通 asset；
- fixture 工作区路径被嵌入 JavaScript；
- fixture basename 被留在 `.js.map` 的 `sources` 中；
- 2023–2028 六个年度的 Base64 payload 分别被嵌入 JavaScript；
- 2023–2028 六个年度的 gzip bytes 分别被写入二进制 asset；
- 2023–2028 六个年度的解压 raw CSV 分别被写入 asset；
- Base64 payload 被嵌入 `.js.map`。

另有正向样本确认：只包含 HKO 资源 URL、年份和 digest 元数据时仍可通过。

## 权利与授权分账

DATA.GOV.HK 当前通用条款允许在其条件下下载、分发和复制数据；HKO 网站条款及商业使用条件又要求商业使用相关材料事先取得书面授权。两套文字对本候选的作品层、版本层、载体层和既有 raw body 存储的具体适用关系仍有歧义，不能由工程测试解决：

- [DATA.GOV.HK Terms and Conditions](https://data.gov.hk/en/terms-and-conditions)
- [HKO Website Conditions](https://www.hko.gov.hk/en/readme/readme.htm)
- [HKO Conditions for Commercial Use](https://www.hko.gov.hk/en/appweb/commercial.htm)
- [HKO Gregorian-Lunar Calendar Conversion Table dataset](https://data.gov.hk/en-data/dataset/hk-hko-rss-gregorian-lunar-calendar-conversion-table)

因此以下状态全部保持为 false：

- `workRightsEstablished`
- `editionRightsEstablished`
- `carrierRightsEstablished`
- `rightsLegalConclusionEstablished`
- `redistributionAuthorized`
- `publicBuildInclusionAuthorized`
- `releaseReady`
- `publicDeploymentAuthorized`

本门也不建立来源正文真实性、领域真值、专家真值、binding freeze 或正式准入。

## 后续需要真实授权的步骤

若目标是严格的 link-only 存储，仍须由用户另行明确授权后执行：

1. 将六份 raw payload 移入权利允许且访问受控的 private vault，或从可公开/可发布工作区材料中移除；
2. 建立不含响应正文、固定 `rawSourceBodiesStored=0` 的 v2 link/hash/retrieval envelope；
3. 用项目原创 synthetic fixture 保留 parser 与边界回放测试；
4. 重新观察并生成不绑定 raw fixture 的版本化紫微 Manifest；
5. 由独立权利复核解决两套条款的具体适用问题。

在这些步骤完成前，不得将本排除门描述为许可结论、公开构建授权、发布就绪或公开发布授权。
