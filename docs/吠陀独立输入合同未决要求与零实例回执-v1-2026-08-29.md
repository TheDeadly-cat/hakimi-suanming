## 1. 结论

本阶段为吠陀体系新增一份项目自写、隔离的 JSON Schema 草案 hakimi.vedic.input/0.1-draft。它只定义 contractVersion 与 13 项输入／计算政策声明的结构，不复用八字、紫微或西洋的体系 ID、历法、规则、producer、来源、权利、专家或发布身份。

13 项要求在子要求账中均为 draft_shape_defined_value_unselected：每项只绑定草案中对应的精确 JSON Pointer；selectedValue/defaultValue=null，instance、evidence、source、rights 和 expert refs 仍为空。requirementsDraftCovered=13 只表示结构覆盖，requirementsResolved=0 明确表示历法、时间精度、DST、时间尺度、星历、sidereal zodiac、ayanamsa、Rahu／Ketu、Bhava 与扰动政策均未完成现实选择、来源冻结或专家审定。

草案禁止 default、example(s) 与外部 $ref，所有实例对象关闭额外字段。它没有样例、真实或合成人物输入，也没有默认推断或生成模型补猜能力。

## 4. 定向验证与独立复核

当前 input 定向结果：draft 21/21、input requirements 33/33，合计 54/54 PASS，0 fail／skip。fact draft 与 fact requirements 的独立结果见 fact 文档，rule draft 与 rule requirements 的独立结果见 rule 文档，parent 结果见产品化聚合账。新增回归覆盖：公开 canonical API 对 getter／Proxy／-0 的被动拒绝、builder 全图冻结、完整 detached／deep-freeze 图检查、CLI scope、ADR hardlink、docs junction、ADS／遍历与大小上限。

独立复核曾确认三项 P2：requirements builder 可变导致旧摘要配新权威位、公开 canonical helper 可执行访问器或折叠 -0、CLI 泛化 ok=true 可被误读为准入。三项均已修复并加入回归；它们此前也没有形成 verifier 或 admission bypass。

本轮另按 P2 威胁模型加固两个 raw parser。入口先以零 trap 的 Proxy 检查与内部 `Uint8Array` brand 拒绝伪装值，再通过 intrinsic `buffer`／`byteLength` 读取内部槽；SharedArrayBuffer、Resizable ArrayBuffer 与已 detached 输入失败关闭，`maxBytes` 对内部字节长度执行且不调用 caller coercion。随后使用 intrinsic `Uint8Array.prototype.set` 复制到私有、固定 ArrayBuffer，解析结果不会随 caller 后续修改原字节而变化。Buffer 与普通／跨 realm Uint8Array control 保持可用。对象 API 继续走 descriptor-based passive JSON snapshot，不通过 stringify 或 raw parser 回退。现有 54/54 与额外不落盘 hostile getter／Proxy／SAB／RAB／detached／maxBytes 探针均未见剩余 P1/P2；该结论只限本轮 input draft／requirements parser 边界。
