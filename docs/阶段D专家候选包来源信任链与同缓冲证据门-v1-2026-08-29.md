## 2. 新增机械边界

`scripts/bazi-expert-review-packet-lib.mjs` 现在：

1. 对 12 个固定 artifact 使用 held handle、`maxBytes + 1` 有界读取，并在读取前、打开后、读取后复核文件 endpoint；拒绝最终 symlink、hardlink、特殊文件和工作区越界。
2. 逐级检查工作区根到目标父目录的目录链；读取前后目录 endpoint 必须一致，工作区内 junction 也拒绝。
3. 每个账本的 SHA-256 与 JSON 解析复用同一个 Buffer，不再分别按路径重读。
4. 在消费来源／权利账的 ID 和 digest 之前，直接执行完整来源候选 verifier 与完整三层权利候选 verifier；工程 Binding 候选账也执行完整 verifier。
5. 先以同一批 snapshot 核对 packet artifact locks，再让账本 parser／verifier 消费这些字节。
6. packet 与三个 JSON 账本拒绝 BOM、非法 UTF-8、重复 JSON key、超限和非对象顶层。
7. 对象 API 先做 descriptor-based 被动 JSON 快照；accessor、Symbol、自定义 prototype、稀疏数组、循环、非有限数和资源超限均失败关闭。成功结果返回脱离调用方、递归冻结的 packet，不保留可变别名。

这些门只证明当前文件端点和固定机械合同。Schema 13 没有 mutation epoch；跨文件不是原子快照，区间 mutation 与 ABA 仍未排除。

## 3. 当前信任链和红态

```text
正式空席 packet 静态边界
  → 12 个 artifact 的同缓冲 SHA-256 锁
  → 工程 Binding 候选完整 verifier
  → 来源 Binding 候选完整 verifier
  → 三层权利候选完整 verifier
  → packet ledger ID/digest 对照
  → 现实专家 intake（当前未开始）
```

当前链在第二步因 `bazi-core` 的保存／当前 SHA-256 不一致而停止。批准 packet 的 ID、semantic digest、创建时间、原始字节长度与 raw SHA-256 现在另有精确 trust anchor；测试已确认同 ID 换成 current-byte artifact lock 并自行重算摘要会以 `PACKET_DIGEST_MISMATCH` 拒绝，不再存在 test-only 自重签成功路径。

现有 packet 是固定空席候选包，不是现实专家意见记录。当前已新增传递绑定的零实例 gap 与七类候选 record preflight；总 bundle 必须同时提供完整 component records，不能只靠虚构 refs 和自报 chronology。未来真实身份绑定、原始意见及仓外封存回执、两席成对独立性核验、分歧清单、reconciliation note 和总 bundle 仍须引用最终冻结 packet 的精确身份；不能直接把真人信息填入当前空席包。详见 [现实专家独立工件零实例合同与准入红账](./阶段D现实专家独立工件零实例合同与准入红账-v1-2026-08-29.md)。
