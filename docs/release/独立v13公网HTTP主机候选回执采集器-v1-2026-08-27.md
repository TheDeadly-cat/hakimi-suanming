# 独立 v13 公网 HTTP 主机候选回执采集器 v1（2026-08-27）

## 结论与边界

本采集器是 provider-neutral 的真实公网 HTTP 观察入口，只产生 `deployed_host_http_receipt_candidate_v1` 未受信候选回执。它不选择托管平台，不修改 checked-in hosting policy，不接入正式 Release Evidence receipt aggregate，也不打开 deployed-PWA v2 admission。

无论候选 HTTP 矩阵是否匹配，回执均固定：

- `trustClass=untrusted_candidate`；
- `status=not_admitted`；
- `realHostVerified=false`；
- 外部部署、公开部署、公开发布、发布就绪、内容真值、专家真值与权利结论全部为 `false`。

当前 `docs/security/hosting-security-policy.json` 必须继续保持 `deploymentPlatform=unselected`、`canonicalOrigin=null`、空 redirect rules、report-only CSP 与关闭的 public release gates。candidate platform/origin 只是本次观察 scope，不能回写或替代 policy 决策。

## 复用与采集矩阵

`scripts/deployed-security-headers-lib.mjs` 的 `createUntrustedDeployedHostCandidatePlan` 只导出现有静态 declarations、完整 document/artifact/Release Evidence probe、四类 HTTP→HTTPS redirect 与两个 hidden-control probe。它不执行 DNS、网络或 admission，也不改变 `validateRealDeployedHostPreflight` / `verifyRealDeployedHost` 的正式前置门。

运行时使用 Node `http` / `https`，不使用 Fetch 的折叠 Headers 视图：

- DNS 先取得全部 A/AAAA 结果，并用现有 public-address validator 拒绝任一 private/reserved/malformed/mixed 结果；IPv4-compatible `::/96`、IPv4-mapped `::ffff:0:0/96`（含压缩或展开写法）、NAT64 `64:ff9b::/96`、Teredo `2001::/32`、deprecated site-local `fec0::/10` 也明确视为不可接受候选地址；
- 每次连接通过自定义 `lookup` 固定到已审计地址，随后复核 socket remote address；
- HTTPS 保留 hostname/SNI 和默认 CA 校验，并记录 TLS protocol、ALPN 与 peer certificate SHA-256 fingerprint；
- 所有请求固定 `GET`、`Accept-Encoding: identity`、manual no-follow、无 retry；
- 原样保留 Node 解析后的有序、多值 `rawHeaders` 与 `rawTrailers`；它们不是 TCP/TLS wire-byte capture；
- 响应必须完整结束，`aborted`、未完成 `close`、timeout、超限 body 或非空 trailers 均失败关闭；
- body 只记录有界流式 size/SHA-256，不把公开 artifact body 复制进回执；
- content probe 独立核对 exact status、header multiplicity、安全头、危险行为头、cache、UTF-8 MIME、identity encoding、Content-Length 与 locked bytes；任意 `Transfer-Encoding` + `Content-Length` 并存均作为 framing ambiguity 拒绝；
- redirect 只接受 301/308 和唯一、可解析后 exact 的 HTTPS Location；
- `/_headers` 与 `/release-evidence.json.sha256` 只接受无 redirect 的 404/410。

## Artifact 与输出协议

采集前后分别运行现有 artifact identity-lock verifier 和 `loadDeployedHostExpectation`。Release Evidence 的 `artifacts.identityLock` 会暴露为 expectation binding，并与显式 candidate lock 的 physical realpath、原始锁文件 SHA-256、`lockDigest`、`artifactSetDigest` 逐项要求同一；初末 attachment 都重新检查。初末 attachment 还同时绑定完整 lock/physical snapshot、Release Evidence、artifact inventory、index/manifest/SW bytes digest，以及 hosting policy 原始字节 SHA-256、canonical SHA-256 和 canonical policy。初末 verifier 错误或投影分叉统一作为 artifact rebound，并在写任何 attachment 前停止。最终 receipt 发布后还会再次复验这些来源、输出目录与精确文件集合；该发布后复验通过之前，writer 不返回成功。

binding/output/artifact/lock 输入必须是规范绝对路径并位于同一显式 binding root。output 与 artifact 在 lexical path 和创建前/后的 realpath 上双向隔离；目录不得是 symlink/junction。输出目录必须新建或为空，失败目录不可续写。

2026-08-28 起，下述终态提交门取代 2026-08-27 的 receipt 发布后 tombstone 机制；`output-discard-required.json` 不再属于 host candidate 的可接受磁盘格式。

成功完成一次观察时先形成 PREPARED 集合：

1. `artifact-initial.json`
2. `http-observations.json`
3. `artifact-final.json`
4. `host-receipt.json`
5. `.host-receipt-publication-pending`

每个已发布文件先在同目录以 `wx`、权限 `0600` 写满并 `fsync`，再用 exclusive hard-link publish，拒绝覆盖并复核路径/句柄/链接数/大小/SHA-256。隐藏 pending 文件固定为 65 bytes：`host-receipt.json` 原始 bytes 的小写 SHA-256 加一个 LF。writer 在 PREPARED 精确五文件状态下，用重新取得的 artifact、PWA manifest、Service Worker、identity lock、Release Evidence、sidecar 与 checked hosting policy 做第三次 endpoint snapshot，并复核 initial/final/post 三个 core、output root identity，以及 receipt、三个附件和 pending marker 的完整 binding。

所有可能传播的来源、输出、Schema 和不可变返回值检查都在终态提交前完成。最后一个可能失败的步骤是同目录 native rename，把 `.host-receipt-publication-pending` 改名为 `host-receipt-publication-commit.sha256`；rename 后立即同步返回，不再执行回调、checkpoint、清理、I/O 或其他可抛错工作。COMMITTED 精确集合仍为五文件，即三个附件、receipt 与 terminal marker。终态 marker 的 `commitsReceiptSha256` 必须等于 raw receipt SHA-256。

`host-receipt.json` 文件名出现本身不是完成标志。终态 rename 前的异常或进程终止最多留下带隐藏 pending marker 的 PREPARED root，独立 loader 必须拒绝；CLI 的 `outputDiscardRequired=true` 只是要求调用方整体废弃该失败 root，不声称磁盘上存在持久 tombstone。rename 已完成但进程尚未来得及把返回值交给调用方时，独立 loader 只能证明当前 COMMITTED 端点机械有效，不能证明历史 writer 调用已被调用方观察为成功。该机制也没有证明目录 `fsync`、断电级持久性、目标名 no-replace 竞态排除、同权限连续 mutation、区间 mutation 或 ABA 排除。

独立 loader 现已落盘为 `scripts/deployed-host-candidate-loader.mjs`，receipt 封闭 Schema 为 `docs/release/deployed-host-http-receipt-candidate-v1.schema.json`。loader 不调用 DNS、HTTP、浏览器、部署或 writer 路径；它只接受 COMMITTED 精确五文件输出，明确拒绝隐藏 pending marker、旧 tombstone、额外或缺失名字，并重新打开当前 Schema、checked policy、artifact、identity lock 与 Release Evidence。五个文件均受 opened-handle、single-link physical identity、稳定 bytes、路径、大小与摘要复核；terminal marker 还必须精确等于 raw receipt SHA-256 加 LF。loader 同时拒绝 symlink/junction、hardlink、非普通文件、路径别名、重复 JSON key、摘要刷新后的权限提升和 current-source rebound。它从 raw HTTP observations 重算既有纯函数 evaluator，但该语义实现与 producer 共享，不能冒充实现多样性的独立复核。

磁盘文件无法保留 writer 的私有 WeakSet transport provenance brand。因此 loader 即使完整接受一个标记为 `node_http_pinned_real_network_v1` 的封包，也只证明当前封包、当前来源和重算语义一致，固定返回 `realNetworkTransportProvenanceVerified=false`、`realHostVerified=false`。真实主机结论仍须由正式 real-host verifier、原始连接证据和后续人工准入独立建立。

## 显式输入与入口

运行前必须显式设置：

- `HAKIMI_DEPLOYED_HOST_CANDIDATE_ORIGIN`
- `HAKIMI_DEPLOYED_HOST_CANDIDATE_PLATFORM`
- `HAKIMI_DEPLOYED_HOST_CANDIDATE_BINDING_ROOT`
- `HAKIMI_DEPLOYED_HOST_CANDIDATE_OUTPUT_ROOT`
- `HAKIMI_DEPLOYED_HOST_CANDIDATE_ARTIFACT_ROOT`
- `HAKIMI_DEPLOYED_HOST_CANDIDATE_ARTIFACT_LOCK`
- `HAKIMI_DEPLOYED_HOST_CANDIDATE_RELEASE_EVIDENCE_ID`
- `HAKIMI_DEPLOYED_HOST_CANDIDATE_RUN_ID`

独立验证既有候选包时必须显式设置：

- `HAKIMI_DEPLOYED_HOST_CANDIDATE_VERIFY_BINDING_ROOT`
- `HAKIMI_DEPLOYED_HOST_CANDIDATE_VERIFY_OUTPUT_ROOT`
- `HAKIMI_DEPLOYED_HOST_CANDIDATE_VERIFY_RECEIPT`
- `HAKIMI_DEPLOYED_HOST_CANDIDATE_VERIFY_ARTIFACT_ROOT`
- `HAKIMI_DEPLOYED_HOST_CANDIDATE_VERIFY_ARTIFACT_LOCK`
- `HAKIMI_DEPLOYED_HOST_CANDIDATE_VERIFY_RELEASE_EVIDENCE_ID`

纯离线合同测试：

```text
npm.cmd run test:deployed-host-candidate-collector
```

只读验证既有候选包：

```text
npm.cmd run verify:deployed-host-candidate
```

未来只有在明确授权真实网络观察后才可运行：

```text
npm.cmd run capture:deployed-host-candidate
```

测试仅注入合成 DNS 与 HTTP observation，不访问网络、不运行浏览器、不部署。当前 collector、writer 与独立 loader 定向测试为 33/33，覆盖来源、cwd、锁、全部四个成功输出、extra/missing name、hardlink、artifact/policy rebound、关闭 claim 提升、同步刷新 attachment/receipt digest 后伪造 HTTP evaluation，以及把完整 synthetic 包连同全部摘要一致地改标为 real-network 后仍固定关闭独立实现性、transport provenance、real-host、admission 与授权的反例。合成输出使用 `verificationKind=synthetic-offline-candidate-contract`、`networkCompleted=false`，不能冒充真实网络候选。真实网络分类不接受调用方字符串：只有模块内默认 DNS + 默认 pinned transport 的完整 collector 入口才能给 HTTP document 加私有 WeakSet provenance brand，writer 同时要求该 brand 与 schema-validated Release Evidence expectation；直接调用 exported writer 永远不能制造真实网络分类。磁盘 loader 无法恢复该进程内 brand，所以即便原始包的 observation label 自述 real-network，也只记录为未经证明的候选标签，权威 wrapper 仍固定 provenance/claims 为 false。真实入口即使完成矩阵仍只是未签名 candidate；可信 transport provenance、provider deployment receipt、正式 admission 与发布授权仍需独立后续版本和人工决策。
