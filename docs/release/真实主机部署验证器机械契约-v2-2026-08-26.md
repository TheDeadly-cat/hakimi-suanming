# 真实主机部署验证器机械契约 v2（2026-08-26）

## 结论

本阶段收紧的是 deployed-host verifier 自身的 fail-closed 契约，不是一次真实部署验证。

托管策略继续保持：

- `deploymentPlatform: unselected`
- `canonicalOrigin: null`
- CSP 为 `Content-Security-Policy-Report-Only`
- `realHostHeadersVerified: false`
- `cspBlockingModeVerified: false`
- `publicDeploymentAuthorized: false`

因此，mocked-host 回归即使完整通过，也只能建立“验证器能拒绝已建模的坏响应”；不能建立真实 HTTPS 主机、CSP 浏览器阻断、PWA/SW 公开 origin、部署、回滚、发布就绪或公开发布授权。

## 两个入口必须分离

验证器分为两个不可互换的入口：

1. 可注入 `fetch` 的 contract 入口，只用于确定性 mocked-host 测试。该入口可以得到 `mockedContractVerified: true`，但 `realHostVerified` 必须恒为 `false`。
2. CLI 使用的真实网络入口，不接受调用者注入 `fetch`，固定使用启动时捕获的 Node 原生网络实现。它还必须在发请求前要求公开 HTTPS canonical origin、已选择的平台，以及 `/`、`/sw.js`、`/release-evidence.json`、代表性深链四类 canonical HTTP→HTTPS 永久重定向。

把一个 HTTPS 字符串传给 mock 入口，不能改变其证据类型。测试代码、fixture、localhost 或调用者提供的 Response 均不得冒充真实主机。

## 预期身份只能来自本地产物

远端响应不能自证“自己就是正确产物”。验证器从本地正式 Release Evidence 与对应 artifact root 读取预期身份，并先复核本地文件的路径、大小和 SHA-256。随后才把远端响应逐字节与本地预期比较。

真实 CLI 的固定顺序为：

```text
selected platform / canonical origin / redirect preflight
→ 既有 formal Release Evidence verifier（含 receipts 与当前源树绑定）
→ 本地 evidence Schema 和 artifact inventory 再复核
→ deployed-host 网络矩阵
```

checked-in policy 仍为 `unselected / null / redirectRules: []`，所以当前真实 CLI 会在 artifact 读取、Git-backed formal verifier 和任何网络访问之前失败关闭。本阶段测试没有调用正式 verifier，也没有读取 Git 状态。

网络前还必须完成以下交叉绑定，任一处不能用 Evidence 自填的布尔值代替：

- Release Evidence `policyFiles` 中的 policy 路径与原始字节 SHA-256；加载后的 canonical policy、policy ID 与 canonical SHA-256 在真实入口再次精确比较，禁止“按 policy A 加载、按 policy B 验证”；
- `release.channel=default-v13`、`evidenceIdBound=true`、`builtEvidenceId=evidenceId`、`manifestVersion=1`；
- Evidence release 字段与已逐文件复核的 artifact identity lock 中 descriptor、manifest digest、build version、evidence ID 精确相等；
- `index.html` 中唯一 release meta、完整 11 字段 v13 descriptor、精确 v13 storage manifest 与原始序列化摘要；
- `sw.js` 通过 JavaScript AST 而不是字符串/注释匹配读取唯一顶层 `CACHE_VERSION`、`RELEASE_DATABASE`、`LEGACY_BRIDGE_DATABASE`，并与 index/Evidence 身份相等。

policy 与三份解析用 Buffer 都在入口复制；每次运行前再次按 artifact inventory 重算三份 Buffer 的 SHA-256。仅完成 Schema 与本地产物加载的 expectation 不会进入真实入口的内部 weak-set；只有模块内部实际执行 formal Release Evidence verifier 成功的加载路径才会获得该资格。

远端绑定范围包括：

- `release-evidence.json` 原始字节；
- `index.html`；
- `manifest.webmanifest`；
- `sw.js`；
- Release Evidence artifact inventory 中的全部公开文件；
- HTML 深链路由必须返回同一份已锁定 `index.html`。

部署控制文件（当前只有 `_headers`）仍受本地 artifact inventory 约束，但按 policy 明确列为非公开路径，不能因为真实主机不暴露它而误判为缺失公开资源。

## 每个公开响应都要独立验证

每个 probe 都必须同时满足：

- 手动处理重定向；canonical HTTPS 路径不得发生意外跳转；
- 精确 HTTP 状态；
- 响应最终 URL 与请求目标一致；
- policy 中的全部安全头逐路径存在且值匹配；
- HSTS 固定为 `max-age=31536000`；它建立的是响应头基线，不是 preload 或首次访问绝对抗降级证据；
- 禁止 `Clear-Site-Data`、`Link`、`Refresh`、cookie 与未声明 reporting headers 等托管层行为头；这条门单独保护 mutation epoch、外部 preload 与隐私边界；
- 按最长、唯一命中的 route rule 校验 `Cache-Control`；
- 按文件类型白名单校验 MIME；文本型 MIME 若声明 charset，只接受唯一 `utf-8`；
- 优先流式读取并在超过锁定大小时立即取消，硬上限为 64 MiB；最终大小和 SHA-256 必须与本地预期一致。
- 请求固定 `Accept-Encoding: identity`，返回缺省或显式 `identity` 以外的 content coding 均失败。

`/`、`/index.html`、静态路由、动态路由代表路径、Service Worker、PWA Manifest、Release Evidence 和全部公开 artifact 不能互相借用一个根响应的结论。

`_headers` 与正式 `release-evidence.json.sha256` 被精确列为 non-public；真实主机必须对两者返回不重定向的 404/410。sidecar 仍在本地按原始 Evidence 字节和文件名精确复核，但不能因存在于 artifact root 就静默成为公开文件。其他历史 local Evidence sidecar 不在白名单内，会使本地产物闭集失败。

真实入口在 HTTP 前解析 canonical hostname 的全部 A/AAAA；只要存在内网、回环、链路本地、文档、基准、组播或其他保留地址，便失败关闭。输出单列 `targetOriginSyntaxEligible` 与 `dnsPublicAddressSetVerified`。这减少私网/hosts 绕过，但不是 DNSSEC 或连接级 DNS pinning 证明，不能外推为网络基础设施权威。

## HTML 与 Manifest 只作附加声明门

字节身份是第一道门；静态解析不能替代它。附加来源门至少拒绝：

- `<base>`、import map、meta refresh、inline event handler；
- inline executable script；
- 外部、协议相对、降级 HTTP、带 userinfo 或其他非 root-relative 资源 URL；
- 不在锁定 artifact inventory 中的脚本、样式、图标或 Manifest 资源；
- `background`、`srcset/imagesrcset`、`ping`、`attributionsrc` 与未按 `rel` 白名单声明的 link 属性；
- CSS escape、`@import`、`url()`、`image()/image-set()` 等当前已知静态加载语法。

输出将这项精确命名为 `htmlManifestDeclaredResourcesVerified`，不再声称“全部静态来源闭合”。即使静态 denylist 通过，`inlineCssBrowserNetworkVerified`、`javascriptRuntimeNetworkVerified`、`serviceWorkerBrowserRuntimeVerified` 与 `cspBrowserEnforcementVerified` 仍固定为 `false`；它们只能由独立 Chrome/Edge 运行时网络观测与浏览器回执建立。

## 输出必须分账

稳定 JSON 输出分别记录：

- policy 是否有效；
- target origin 是否合格、是否真的尝试/完成网络、public HTTPS、路径矩阵、redirect、headers、危险行为头、cache、MIME、release/application identity 和公开 artifact set；
- CSP blocking header 与浏览器 enforcement；
- mocked contract、real host 与 public release gate；
- 每个 probe 的错误码，不输出响应正文或敏感值。

CLI 另列 `realHostPreflightPassed / formalReleaseEvidenceVerified / artifactExpectationLoaded / deployedHostVerifierInvoked`，因此 preflight、formal Evidence、产物加载与真实网络失败不能被压成同一个“通过/失败”。mock 中 `publicHttpsVerified` 必须为 `false`，即使 fixture URL 长得像公开 HTTPS。

任一网络异常、超时、过大 body、未知 policy 字段、缺失 cache rule、错误 MIME、重定向、hash 漂移或响应头漂移都必须使严格门失败。CLI 仍应输出失败分账并返回非零退出码。
