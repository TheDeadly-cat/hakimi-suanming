# 既有 `dist/web` 默认 v13 本地同产物预检（2026-08-26）

## 结论先行

本轮只对工作区中已经存在的 `dist/web` 做本地后置锁定与运行时预检，没有重新构建。严格结果为 **失败**：PWA 矩阵中 Edge 通过、Chrome 在同一点连续失败两次；Web v1 连续流在 Edge 和 Chrome 上均因既有产物 UI 与当前测试契约不一致而失败。

因此，这份旧产物不能成为当前 Release Evidence 候选，也不能建立当前源码构建闭环、发布就绪或公开发布授权。

## 预检范围与禁止外推

本轮允许并实际执行：

- 对既有 `dist/web` 写入一次临时后置 identity lock；
- 用应用内浏览器检查桌面与 `390×844` 页面可见性、只读导航和控制台；
- 让正式 release artifact Playwright 配置只预览这份锁定产物；
- 在本机安装的桌面 Edge 与 Chrome 中运行 PWA 和 Web v1 流；
- 测试后再次逐文件复核产物身份。

本轮没有执行：全仓 typecheck、默认 Web build、正式 Release Evidence generator、公开 HTTPS 主机、安全响应头、部署、正式 Release 或真实数据回滚。内容真值、专家真值、来源权利和法律判断也不由本预检建立。

## Chrome / Edge 严格矩阵

本机版本：Edge `151.0.4129.101`；Chrome `151.0.7922.174`。

### PWA：严格门失败，且 Chrome 失败可重复

命令：`npm.cmd run test:release:pwa-artifact`

| 尝试 | Edge | Chrome | strictGatePassed |
| --- | --- | --- | --- |
| 首轮 | `1/1 passed` | `0/1 failed` | `false` |
| 原样复核重跑 | `1/1 passed` | `0/1 failed` | `false` |

Chrome 两次都在 15 秒内无法达到：

```text
swReady = true
serviceWorker.controller = present
swBootSignalSent = true
```

失败 trace 同时显示页面应用启动已完成、`data-sw-registered=true`，且 `/sw.js` 返回 HTTP 200；但 worker 没有形成 active controller，`navigator.serviceWorker.ready` 对应信号始终未建立。本轮证据足以认定当前环境中的 Chrome PWA 门可重复失败，但不足以在没有新产物对照的情况下把根因唯一归于浏览器、旧产物或当前测试契约。

Edge 的单项通过不能替代 Chrome，也不能把严格矩阵提升为通过。

### Web v1 连续流：两浏览器同点失败

命令：`npm.cmd run test:release:web-v1-artifact`

| Edge | Chrome | strictGatePassed |
| --- | --- | --- |
| `0/1 failed` | `0/1 failed` | `false` |

两者都在匿名离线 Markdown 文件交付步骤等待当前契约按钮 `已核对，允许再次下载` 时超时。失败截图中的既有产物仍显示旧控件 `下载文件` 与 `关闭`；当前测试还要求后续 `关闭文件交付`。这是一条直接的“旧产物与当前测试契约漂移”证据，不应通过放宽 locator 或把失败标成 flaky 来绕过。

受限文件继续未被读取或修改。本轮也未执行全仓 typecheck 或默认 build。
