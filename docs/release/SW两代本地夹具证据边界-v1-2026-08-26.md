# Service Worker 两代本地夹具证据边界 v1

> 历史版本说明：本文件记录 v1 合同。2026-08-27 起的当前机械身份、源码绑定和验证数字见 `SW两代本地夹具证据边界-v2-2026-08-27.md`；不得把本页旧合同 ID 或旧静态发现记录当作当前结果。

## 当前状态

`service-worker-two-generation.spec.ts` 是本地、随机 loopback origin、合成数据、临时构建的行为夹具。当前配置已静态固定为：

- 浏览器项目顺序：`msedge`、`chrome`；
- 每个浏览器 3 个场景，串行执行，`retries=0`、`forbidOnly=true`；
- Playwright 可清理的 `outputDir` 精确限制在系统临时目录 `hakimi-bazi-sw-upgrade-results`；canonical wrapper 会在启动 Playwright 前再次核对，reporter 也会复核每个 project 的实际生效目录；
- 手工持久上下文必须按 Playwright project 选择真实品牌 channel；
- profile 子目录在运行前必须不存在；
- 每条 observation 启动后都通过 CDP `Browser.getVersion` 分别确认 `Edg/*` 与 `Chrome/*`，不得靠同项目其他场景的品牌结果补齐；
- 结果只可写为 `sw_two_generation_fixture_contract_v1 / local_synthetic_fixture_only`。

本轮只完成契约测试和 Playwright 静态发现 6 项；没有执行浏览器场景。实际命令会先生成 stable A、healthy B、broken B 三份目标化 Web 构建，而当前接手窗口禁止触发可能读取受限生产文件的构建。因此不能登记 Edge 或 Chrome 运行通过。

这些场景自行启动手动 persistent context；Playwright config 的自动 trace/screenshot 不适用于它们，因此当前契约不声明自动诊断附件。未来若执行真实浏览器取证，必须对手动 context 显式启动 tracing 并在失败路径显式截图，之后才能把相应附件写入独立运行账。

## 三个夹具场景的精确含义

1. 已确认 A 在同源服务器切换到健康 B 时不混入 B HTML；B 安装并受控接管后可离线冷启动。
2. broken B 已经成为 controller，但研究路由启动失败；随后断网时由仍在运行的 B worker 返回最近已确认的 A shell cache。
3. B 的预缓存资源缺失导致安装失败并清理残缺 cache；A 保持 active，随后仍可离线冷启动。

第二项不是 `A→B→A` 回滚：恢复的是 A 的 shell cache 字节，controller 仍是 broken B。第三项也不是部署回滚：B 根本没有成功安装。任何报告都必须保留这两个区别。

## 独立结果账

专用 reporter 只接受 Edge、Chrome 各 3 个单次 expected pass；缺浏览器、skip、retry/flaky、失败、额外项目或写账失败都会使夹具 strict gate 为 false。即使夹具 strict gate 为 true，以下字段仍固定为 false：

- `realHttpsHostVerified`
- `deployedArtifactVerified`
- `providerDeploymentVerified`
- `rollbackVerified`
- `releaseEvidenceVerified`
- `releaseReady`
- `publicDeploymentAuthorized`
- `publicReleaseAuthorized`

该 summary 不使用 Release Browser receipt id，也不得进入默认 v13 的正式预部署回执集合。

## 不成立的结论

本夹具不绑定当前正式 Release Evidence、artifact identity lock、公开 HTTPS origin、provider deployment、真实 v13 用户数据、现实回滚操作者或接受者。它不能证明：

- 真实 HTTPS PWA 或操作系统级安装；
- 已部署产物字节与候选产物相同；
- 真实 A→B→A 或 v13→v16-shadow→v13 回滚；
- mutation epoch 行为；Schema 13 不具备该能力；
- 发布就绪、公开部署授权或公开发布授权。

未来真实 deployed-PWA 或 rollback evidence 最多可以把本夹具作为 `advisory-only` 场景谱系引用；不得反向让本夹具继承真实部署或回滚身份。
