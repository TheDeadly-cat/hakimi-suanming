# 独立 SW A→B 更新候选证据机械门 v1（2026-08-27）

## 1. 结论与边界

本合同只定义一个面向未来真实运行回执的、离线可重算的 `SW A→B update candidate v1` 机械门。它不表示当前已经有可用的公开 HTTPS 主机、可信 provider/host、真实 Edge/Chrome 运行、部署成功、回滚完成、发布就绪或公开发布授权。

即使输入、附件、A/B artifact roots 和所有 digest 内部一致，终局仍固定为：

- `trustClass = untrusted_candidate`
- `status = not_admitted`
- `executionAdmission = closed_missing_https_origin`
- `strictGatePassed = false`
- CLI 退出码 `1`

部署、发布、内容真值、专家主张、权利法律判断、Schema 晋级等 authority 全部固定为 `false`。本合同不是正式 Schema 13 Release Evidence Receipt，不属于正式 receipt allowlist；其 capture/test/verifier 命令不能由正式 receipt 的 npm/lifecycle 命令闭包触达。正式 `check:release-governance` 会导入候选合同库以验证这些关闭边界，因此本文件不声称候选 source/module graph 完全不可达；现有机械门也没有递归冻结所有正式本地命令的 module import graph。

## 2. 固定发布身份与能力边界

A、B 两个 artifact 都必须分别固定：

- `channel = default-v13`
- `dbGeneration = legacy-v13`
- `targetSchema = 13`
- `migrationId = null`
- `mutationEpochCapability = absent_schema13`
- `epoch = null`

Schema 13 只能证明取证端点的完整 v13 fingerprint 相等，不能据此推导区间内从未写入，也不能排除 ABA（写入后恢复）。因此合同固定 `intervalNoMutationVerified = false`、`abaResistance = absent_schema13`，禁止伪造 `epoch = 0` 或其他 epoch。

## 3. A/B artifact 与主机字节

离线 verifier 必须同时收到两个不同的 artifact 根：

```text
--artifact-a-root <path>
--artifact-b-root <path>
```

两根必须是互不嵌套、物理身份不同的闭集目录；verifier 会锁定并复验 root identity，持有每个文件句柄到终局，并重新枚举闭树。每根至少包含 `index.html`、`manifest.webmanifest`、`sw.js`；其完整 inventory、文件大小、SHA-256、URL path 和 artifact-set digest 都必须重算。A/B 的 `releaseEvidenceId`、`buildVersion`、`artifactSetDigest`、SW SHA-256、identity lock、物理 root 必须全部不同。

每个 artifact 还必须有独立的 identity-lock、Release Evidence binding 和远端完整 raw-body capture。六条治理绑定同时持有 release decisions、release generation history、hosting security policy、正式 Release Evidence Schema、候选 policy 和候选 Schema。Release Evidence 文档必须先通过正式 `release-evidence.schema.json` 全文校验，再严格绑定当前四份正式 policy files、完整 13 条默认 v13 receipt ID/命令、浏览器 summary、owner-controlled gates、identity-lock 和 artifact inventory；PR6 自己的 candidate receipt 或一条伪 receipt 不能替代正式 receipt set。远端 capture 必须覆盖该 root 的精确闭集，逐文件绑定 canonical HTTPS URL、采集时间、HTTP 200、零 redirect、`identity` encoding、大小、SHA-256 和 base64 raw bytes。各浏览器观测的 controller source、远端 `sw.js` raw bytes、对应本地 locked `sw.js` 必须三方相等。

这些本地附件只建立候选内部绑定；它们不把 provider、host 或 Release Evidence 提升为可信来源。

## 4. 一次共享部署切换与双浏览器形状

合同冻结为一个 global attempt：Edge 和 Chrome 都先在各自 fresh persistent profile 中启动并停留于 A，然后共享一次 provider A→B switch。不得让第二个浏览器在主机已经切到 B 后补录“全流程”，也不得跨浏览器复用 receipt、profile、process、client 或附件。

global deployment ledger 不是孤立的自报事件表：A/B host-stable 时间必须精确绑定各自远端 raw capture；Edge/Chrome 各自的 A-client-ready 事件分别绑定对应 receipt；installing、waiting、断网、activate/claim、旧 A 写拒绝、进程关闭、离线重开和离线路由完成事件必须是两份 receipt 相应事件的确定性时间投影。任一独立改写都会 fail closed。

每个浏览器在首段同一 OS process、同一物理 profile、同一 browser context 中必须精确存在两个 A WindowClient。两者必须同时满足：

- distinct CDP `targetId`
- distinct SW `event.source.id` / `clientId`
- 各自独立 256-bit challenge nonce 与 challenge digest
- A 阶段 `document=A/controller=A`
- B `activate + clients.claim` 后各自恰好一次 `controllerchange`，变为 `controller=B`

随后保留一页 `document=A/controller=B`，另一页 reload 为 `document=B/controller=B`。旧 A document 的写拒绝必须发生在 B 已 activate/claim 之后。

verifier 还拒绝 Edge/Chrome 复用 client ID、CDP target ID 或 challenge nonce，并要求 retained-old-A slot 的 client identity 连续。但现有 census/challenge payload 仍是 future collector 提供的规范化 JSON，没有保留原始 SW `message` event 与 CDP target enumeration 事件；因此终局固定 `twoClientRuntimeProvenanceVerified=false`，这些绑定不能单独证明现实中确有两个 WindowClient。

## 5. 精确 15 事件时间线

每个浏览器 receipt 必须按下面顺序逐项、无增删地记录 document tags、controller tags、installing/waiting/active tag、网络状态、page count 和 process state：

1. `fresh_profile_started_online`
2. `two_artifact_a_clients_controlled`
3. `artifact_b_update_requested`
4. `artifact_b_installing_observed`
5. `artifact_b_waiting_observed`
6. `network_interrupted_during_update`
7. `artifact_b_activation_and_claim_observed`
8. `one_a_document_reloaded_to_b`
9. `stale_a_production_write_rejected`
10. `all_pages_closed`
11. `browser_process_closed`
12. `persistent_profile_process_reopened_offline`
13. `offline_root_opened`
14. `offline_deep_link_opened`
15. `final_v13_snapshot_recorded`

中断网络发生在 B waiting、A active 且两页仍为 A controller 的更新过程中；B activation/claim 及后续阶段继续离线。

## 6. 进程重开候选 shape 与 B 离线冷启动

未来合格 collector 对“重开”的原始证据必须绑定 runner 持有的 OS process id、creation time、wait/exit observation 和物理 profile root：旧 process 已退出，随后以同一物理 persistent-profile root 启动一个身份不同的新 process。关闭 Page、创建新 Page 或只关闭 browser context 都不算 process restart；当前 v1 离线合同尚未取得这些原始证据，限制见本节末段。

候选 shape 要求新 process 在首次 navigation 前已离线。`/` 与 `/help` 两个 document response 必须：

- controller 为 B；
- `fromServiceWorker = true`；
- `networkForwarded = false`；
- 分别保留实际 request URL 与实际命中的 cache-entry URL，允许 `/help` 由 `/` 的 app-shell cache key 响应；
- 保留 response body 的 base64 raw bytes，并独立重算 SHA-256；
- 命中已核验且 URL 唯一的 B cache entry；
- response raw bytes、B cache raw bytes 与本地 locked B artifact bytes 三方相同。

B cache name 必须精确为 `hakimi-shell-<B buildVersion>`，并保留 `/__hakimi_cache_meta__` raw body；metadata 必须绑定同一 cache name、`legacy-v13 / 13 / null` 完整 descriptor 和未确认 boot 状态。

同时，一个未缓存 canary 必须在离线状态失败。仅 DOM 标志、页面 meta、BFCache、memory cache 或 SW 网络透传不构成离线证据。本 v1 合同没有保留 CDP 原始 response provenance，也没有独立列举并冻结两次导航产生的所有子资源请求；终局因此固定 `serviceWorkerResponseProvenanceVerified=false`、`cacheApiProvenanceVerified=false`，不能把 document-response 三方绑定外推成“真实 SW/cache 来源已认证”或“完整页面全部子资源已逐项验证”。

同样，当前 `process-and-profile-reopen` 仍是 Profile digest/时间投影，没有保留旧 PID/creation tuple、runner-held wait handle、exit observation、relaunch spawn fact、物理 profile-root BigInt 身份和 offline transition ack。终局固定 `osProcessRestartProvenanceVerified=false`；在未来 collector 补齐这些原始事实前，本合同不能把两个 process digest 写成“真实 OS 进程重启已证明”。

## 7. 旧 A 页生产写拒绝

旧 A document 在 `controller=B` 后必须实际调用 production repository / DBCore 写路径。候选附件不再只复制 receipt summary，而必须同时保存 invocation、错误对象投影、transaction audit、写前/拒绝后/最终完整 snapshot 和三次 sentinel 查询。合格附件至少绑定：

- `writePath = production_repository_dbcore`
- 实际错误类型 `ReleaseDatabaseWriteLockedError`
- 从真实错误对象派生的 `errorInstanceOf = true`、constructor 名和 prototype chain
- `databaseAreReleaseWritesLocked = true`
- transaction commit count 为 `0`
- 写前、拒绝后、最终完整 v13 snapshot fingerprint 相同

按钮 disabled、DOM reason、测试替身或自造 reason code 均不算。离线 verifier 可以证明这些被冻结的 runtime-fact bytes 彼此一致，却不能单凭 JSON 自行证明它们确实来自某次真实浏览器对象；生产 collector、真实浏览器运行与独立审阅仍是另一账。本合同创建时不声称产品已经自动具备同 Schema takeover 的 stale-client 写锁；后续生产源码机制与本地定向验证见《B阶段同Schema控制器接管写栅栏本地实现证据（2026-08-27）》。该后续证据仍未绑定当前发布 artifact 或真实浏览器 runtime，未来真实 runner 若不能取得上述生产路径证据，就必须 fail closed，不能生成“通过”回执。

## 8. Attempt、附件和闭集

每份候选必须使用 256-bit `runId` / `attemptId`，并在声明为 fresh 的 private root 写入 attempt marker。marker 精确绑定 private root、attachments root、A root、B root、run/attempt 和 marker digest，并贯穿 evidence、browser receipts、attachments 与终局 summary。离线 verifier 没有外部已用 attempt registry，不能证明历史新鲜性，也不能阻止整包逐字节重放；因此终局明确固定 `attemptFreshnessExternallyVerified=false`、`bundleReplayResistanceVerified=false`。marker 只能阻止跨 attempt/跨 root 重绑定，不能被写成“已证明单次使用”。

附件角色为固定闭集：6 个 shared role，以及 Edge/Chrome 各 16 个 per-browser role，共 38 个文件。每个文件都是 strict JSON envelope，精确包含 `schemaVersion`、`attachmentType`、`role`、`browserProject`、`runId`、`attemptId`、`payload`、`payloadDigest`。verifier 不只校验路径、大小、SHA-256 和 attachment digest，还会按角色解析 payload，并逐字段投影回 receipt。

所有附件必须具备 canonical workspace-relative path、唯一 realpath/物理身份、`nlink = 1`，不得包含 dot segment、重复路径、跨角色复用或额外文件。输入、marker、附件、治理文件和 A/B artifact 文件的真实 file handle 会保持到终局，并在关闭前重新 stat、重读和重算 hash；A/B artifact tree、attachments tree 和 private tree 还会在终局重新枚举。这能发现普通替换或增加文件，但不能形成对同权限主动并发进程的原子 filesystem snapshot：逐个复验后的路径仍可能再次被竞争替换。因此终局固定 `concurrentFilesystemMutationResistanceVerified=false`，只有独占 ACL、不可变 snapshot 或 handle-relative 消费才能关闭该账。

## 9. 离线 verifier

命令形状固定为：

```powershell
node scripts/verify-sw-ab-update-candidate.mjs `
  --input <candidate-evidence.json> `
  --attachments-root <closed-attachments-root> `
  --private-root <isolated-private-root> `
  --artifact-a-root <immutable-artifact-a-root> `
  --artifact-b-root <immutable-artifact-b-root>
```

参数必须全部出现且只出现一次。验证失败输出 fail-closed JSON；内部一致时输出候选终局 JSON，但两种情况退出码都固定为 `1`。任意外部 wrapper 当然可以吞掉退出码；这里的机械保证仅是精确冻结的正式 receipt allowlist、npm/lifecycle 命令闭包和治理检查不会接纳该 wrapper 或候选命令，不能泛化为操作系统层面的不可包装性。

机械入口：

- Policy：`docs/release/sw-ab-update-candidate-policy.v1.json`
- JSON Schema：`docs/release/sw-ab-update-candidate-v1.schema.json`
- Schema loader：`scripts/sw-ab-update-candidate-schema.mjs`
- 离线 verifier：`scripts/verify-sw-ab-update-candidate.mjs`
- 语义库：`scripts/sw-ab-update-candidate-lib.mjs`
- 合成磁盘夹具：`scripts/sw-ab-update-candidate-fixture.mjs`
