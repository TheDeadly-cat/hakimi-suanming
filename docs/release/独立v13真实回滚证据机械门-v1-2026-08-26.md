# 独立 v13 真实回滚证据机械门 v1

日期：2026-08-26

## 结论

本轮建立的是后部署、私有、离线复核的工程回滚证据契约。它把 baseline A、candidate B、rollback observed A 的产物身份、真实 HTTPS 主机、Chrome/Edge 实际 Service Worker 控制器、获批现实 v13 数据副本、部署操作和不同演员签名绑定到同一 run。它不执行部署或回滚，也不证明当前已经完成真实演练。

当前状态仍为失败关闭：托管平台未选择、canonical origin 为空、受信演员注册表为空、当前工作区没有两份正式产物及现实三阶段回执。独立代码复核还发现当前下游通过路径仍依赖签名后的声明型 JSON，不能把它当成原始运行时事实。因此 policy 新增 `executionAdmission: closed_missing_trusted_raw_evidence`；即使临时配置主机和演员，CLI 仍会在产物准入前以 `ROLLBACK_EXECUTION_ADMISSION_CLOSED` 停止。

这意味着本轮完成的是 Schema、policy、失败账、字节绑定骨架和显式阻断线，不是可签发 `passed` 的真实回滚 verifier。打开执行准入必须发布新 policy/version 并重新独立审查，不能只把几个布尔值改成 `true`。

## 与预部署 Release Evidence 分账

预部署 Release Evidence 的 13 项回执回答“这一份默认 v13 产物是否满足当前工程候选资格”。回滚证据必须在部署后才能取得，回答“真实主机上的 A→B→A 是否确实发生并恢复”。把回滚回执塞入同一次预部署 evidence 会形成时间循环，因此两者保持独立：

- baseline 和 candidate 各自先取得正式 Release Evidence、产物 identity lock 和不可覆盖的 formal verification receipt。
- 回滚 evidence 再绑定两套正式身份、三个真实主机阶段、两个浏览器各自完整 A→B→A 记录和两次部署操作。
- rollback observed 必须逐字节回到 baseline 身份；candidate 必须与 baseline 确实不同。

## 失败关闭条件

以下任一情况不得产生 `passed`：

- 仍使用 `unselected` 平台、空 origin、HTTP、loopback、私网、mock 或 staging 替代公开 HTTPS canonical origin。
- baseline 与 candidate 相同，或 rollback observed 只恢复旧页面 cache、实际控制器仍是 candidate Service Worker。
- 任一产物、Release Evidence、sidecar、formal receipt、identity lock、policy 或原始 receipt 的字节绑定不一致。
- Chrome/Edge 不是精确各一份现实运行结果，出现跳过、重试、flaky、额外项目或伪造产品身份。
- 实际 controller source、远端 `sw.js` 和产物 lock 不能交叉一致，或回滚后仍有 waiting/installing candidate。
- 数据不是获批只读或脱敏 v13 副本，审批过期，私有包未加密，保存了明文/密钥，三个 HMAC 承诺不一致，或出现 raw IndexedDB、release pointer、epoch 绕过写入。
- 操作者与验收者相同、演员不在受信注册表、现实身份未绑定、Ed25519 签名无效，或验收决定不是 `accept`。
- status、failure、gates、evidence digest、evidence ID 或 sidecar 不能由原始字节重新计算。

## 尚未获准的原始证据能力

以下能力当前全部固定为 `false`，是打开执行准入前的开发清单，不是待操作员手填的验收框：

- 对 baseline/candidate formal Release Evidence 重新执行完整语义验证，或建立不可伪造的可信验证回执。
- 解析并重算原始 DNS/HTTP/TLS、Chrome/Edge CDP controller source、provider deployment operation receipt。
- 用隔离安全输入重算加密私有包的投影和 HMAC；当前只可登记承诺，不可声称已证明源数据不变。
- 由治理根签名 actor registry，并绑定现实身份凭证摘要和独立性审定；不同 actorId/keyId 不能替代现实独立性。
- 每阶段即时冻结独立 observation digest，部署 B 绑定 A checkpoint，回滚绑定 B checkpoint；最终 session 只能聚合既有 checkpoint。
- Chrome/Edge 分别取得 baseline 和回滚后的离线冷启动、深路由、只读导出及实际 `response.fromServiceWorker` 原始记录。

## v13 mutation epoch 边界

固定身份继续为 `legacy-v13 / targetSchema 13 / migrationId null`。Schema 13 不具备 mutation epoch 字段，因此证据只能记录 `epochSupport: absent_schema13`，所有 epoch 值为空。完整性依靠只读来源、A/B/A 三阶段 HMAC 承诺、零 raw-write/version-pointer 变更和原始浏览器回执复核；不得用 `0` 冒充不存在的 epoch。

## 权限与证据账

当前 verifier 不会产生通过。即使未来在新版本中完成上述原始证据能力并通过，也只建立一次特定 run 的工程回滚执行证据。它不建立内容真值、专家真值、来源许可或法律结论，不建立现实演员独立性的法律判断，不建立发布就绪，也不改变 `publicDeploymentAuthorized=false` 与 `expertClaimsAuthorized=false`。公开发布仍需所有外部门分别闭环并由所有者明确授权。
