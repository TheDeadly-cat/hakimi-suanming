## 2026-08-28 终态提交门补充

本节取代下方“provider / host 候选 receipt 发布后的终点复验”所记录的 2026-08-27 post-publication callback/tombstone 机制；下方旧段只保留为当时点的历史说明，不能作为当前磁盘格式或成功语义。

- Host PREPARED 与 COMMITTED 都是精确五文件：三个附件、`host-receipt.json`，以及二选一的 `.host-receipt-publication-pending` / `host-receipt-publication-commit.sha256`。
- Provider PREPARED 与 COMMITTED 都是精确七文件：五个附件、`provider-deployment-candidate-receipt.json`，以及二选一的 `.provider-deployment-candidate-receipt-publication-pending` / `provider-deployment-candidate-receipt-commit.sha256`。
- 两类 65-byte marker 都是对应 raw receipt 的小写 SHA-256 加 LF。writer 在 PREPARED 状态完成全部来源、输出、Schema、路径、物理身份、摘要和不可变返回值构造；最后以同目录 native rename 把 pending 改名为 terminal marker，并立即同步返回。

- host/provider/PWA composition v1 现在冻结两个 `terminalGateBinding` 及 Host 5 / Provider 7 文件身份；Provider A→B→A sequence 逐包冻结 `terminal-commit`，统一 held identity 从 15 增为 17。rollback/provider sequence composition 仍独立且保持 `not_admitted`。
- Provider sequence CLI 现在把磁盘候选发布与 JSON/stdout 呈现分账：writer 返回后的呈现失败仍非零退出，但固定保留 `candidatePublicationCompleted=true`、`sequenceCandidateWritten=true`、`stdoutPresentationCompleted=false`、`publicVerifierRequiredAfterWriterReturn=true`，不得再误导调用方把 exact-one 已提交包当成“未写入”重试。

该门关闭的是“writer 在 receipt 发布后失败，而旧 exact set 仍可被 loader 接纳”的进程内状态机缺口。它没有建立目录 `fsync`、断电级持久性、目标名 no-replace 竞态排除、跨进程连续 epoch、同权限 interval mutation/ABA 排除，也不证明历史 writer 返回已被调用方观察。它更不提升真实网络、真实主机、provider 身份、部署、回滚、浏览器/PWA、内容、专家、权利法律、发布就绪或公开发布授权。

## 正式 Release Evidence 的文件身份边界

- artifact inventory 不再静默忽略 symlink、junction/reparse point、非普通文件或 hardlink；任一出现即失败关闭。
- artifact root 的词法路径必须与 realpath 相等，包含通过祖先目录别名进入 root 的情形。
- raw receipt、browser summary 与 artifact identity lock 都由同一个持有句柄读取出的 Buffer 同时完成摘要与解析/比较，不再分别读取两次。
- `index.html` 的稳定快照还会与 artifact inventory 中的 size/SHA-256 交叉一致。
- 这些检查关闭持久 alias 与普通双读竞态，不构成 handle-relative/no-reparse 文件系统，也不排除同权限进程在多个端点之间完成并恢复一次 ABA。

## mutation boundary 的正式投影

Release Evidence `artifacts.mutationBoundary` 与 formal verification receipt 现在必须精确携带同一 8 字段对象：

```json
{
  "schemaVersion": 1,
  "boundaryType": "release_artifact_endpoint_snapshot_boundary_v1",
  "coveredReceiptIds": ["backup", "boot", "pwa", "web-v1-flow"],
  "endpointSnapshotsMatched": true,
  "verificationScope": "endpoint_snapshots_only_no_interval_mutation_epoch",
  "mutationEpochCapability": "absent_schema13",
  "intervalMutationExclusionClaimed": false,
  "abaMutationExclusionClaimed": false
}
```

generator 只在四份 canonical raw receipt 的前后 artifact snapshot 均匹配时生成该对象；formal verifier 从原始 receipt 独立重算，不信任 Evidence 自述。deployed-host、deployed-PWA v2/v3 与 rollback 消费者都逐字段复核 Release Evidence 与 formal receipt 的投影。既有 `gates.artifactIdentityStable` 只作为兼容别名保留，其含义是 identity lock 与四项 endpoint snapshot 均匹配，不能解释成执行区间无 mutation 或无 ABA。

## provider / host 候选 receipt 发布后的终点复验（2026-08-27 历史机制，已由上节取代）

两条独立候选链都保持 `untrusted_candidate / not_admitted`，且只允许程序调用方注入 receipt-publication checkpoint；不存在对应环境变量或 CLI 开门。

### Provider 候选

最终 receipt 发布后重新验证：

- raw action response 与 final readback 的稳定字节快照；
- artifact tree、artifact identity lock、Release Evidence 与 hosting policy expectation；
- binding/raw/artifact/output directory lock；
- 精确 5 个 attachment 加最终 receipt 的目录集合、路径、大小与 SHA-256。

### Host 候选

最终 receipt 发布后重新验证：

- artifact、PWA manifest、Service Worker、artifact identity lock；
- Release Evidence、sidecar 与 checked hosting policy；
- initial/final/post-publication 三个完整 artifact/expectation core；
- output directory lock；
- 精确 3 个 attachment 加最终 receipt 的目录集合、路径、大小与 SHA-256。

最终 receipt 的 hard-link 一旦成功，writer 会在任何后续 `await` 前同步锁存 `receiptDestinationPublished=true`；receipt 写入本身的临时链接清理、root lock、held-read binding 与 intended binding 比对也在同一失败 guard 内。任一 checkpoint 异常、来源漂移、receipt/attachment 漂移或额外/缺失输出都会拒绝成功，并排他写入固定正文 `output-discard-required.json`：

```json
{
  "schemaVersion": 1,
  "recordType": "candidate_output_discard_required_v1",
  "failureStage": "after_receipt_publication",
  "usableReceiptWritten": false,
  "outputDiscardRequired": true
}
```

若该 tombstone 自身无法安全发布，则以独立 `*_DISCARD_TOMBSTONE_FAILED` 错误失败，仍不返回可用 receipt。该机制覆盖进程内可捕获异常，但没有预先布置 crash-safe sentinel；进程在 receipt hard-link 后被强制终止时不能保证来得及写 tombstone。因此任何候选目录仍必须经过独立 exact-set/receipt loader，不能把文件名出现本身当作成功。成功端点复验也不是一个跨多文件、跨网络、跨进程的连续 mutation epoch。

两类预发布 receipt 文档本身都不能自述发布后的复验结果：它们必须先以固定 bytes 发布，随后才能检查该发布端点。因而成功语义属于 writer 的最终返回和独立 loader 的重算，不属于 receipt 文件“已经存在”这一事实；这也是强制终止残余必须显式保留的原因。

Host 候选此前只有 writer 的进程内终点复验，文档所要求的崩溃后独立消费入口实际缺失。本轮已新增封闭 `deployed-host-http-receipt-candidate-v1` Schema 和只读独立 loader：它重开当前 Schema/policy/artifact/identity lock/Release Evidence 与精确四文件输出，执行 opened-handle、single-link identity、摘要、receipt/attachment、artifact snapshot、HTTP plan/evaluation 和时间链重算。磁盘包不能保存 writer 的私有网络 provenance brand，因此 loader 明确输出 `realNetworkTransportProvenanceVerified=false`、`realHostVerified=false`；它与 producer 共享既有纯 evaluator，也不声称实现多样性的独立语义验证。

Provider A→B→A sequence writer 另采用预置 sentinel：新建私有 output root 后先同步写入固定 `output-discard-required.json`，再发布 sequence；独立待完成态 verifier 在 sentinel 仍存在时持有两文件并验证 exact-two 集合、当前两包重组、固定 bytes、摘要与重叠文件系统 epoch。writer 仅在这些检查和自身终点复核全部通过后，把删除 sentinel 作为最后一个可能失败的发布步骤。sentinel 成功布置后的目录重绑定或可捕获异常会保留随目录移动的 sentinel，正式 exact-one verifier 因而不能重新接纳判废现场；若失败早于 sentinel 成功同步，则错误账明确 `discardSentinelArmed=false`，且此时 sequence 尚未发布。writer 不把 sentinel 删除后的最终集合冒充已被独立复验，明确要求调用方返回后再运行正式持久化 verifier；断电级目录持久性、同权限连续 mutation 与 ABA 仍未证明。
