# PR6 运行时客户端原始采集候选 v1（2026-08-27）

## 结论

本轮没有改写已经冻结的 `SW A→B update candidate v1`。新增的是一个物理与语义上独立的、只覆盖客户端身份观察的 partial raw-capture 家族；它用于为未来真实 PR6 collector 提供生产侧只读 challenge 和宿主 CDP 探针原语。

即使 8 个 Edge/Chrome × initial/post-claim × 双 slot 观察全部内部一致，终局仍固定为：

- `trustClass = untrusted_raw_capture_candidate`
- `status = capture_incomplete`
- `executionAdmission = closed_missing_https_origin`
- `usableForCandidateAssembly = false`
- verifier CLI 退出码 `1`

它不是现有 38 项 PR6 候选附件，不得直接或间接替代 `sw_ab_update_candidate_attachment_v1`，也不属于默认 v13 正式 Release Evidence receipt allowlist。

## 已实现观察面

生产 Service Worker 新增 `SW_AB_RUNTIME_CHALLENGE_V1` 只读消息：仅在 nonce 为 256-bit canonical challenge、存在 `event.source.id` 且存在 MessagePort 时，回显同一 nonce、`event.source.id`、当前 build version 与完整 `legacy-v13 / targetSchema 13 / migrationId null` descriptor。它不调用 `skipWaiting`，不修改 cache，不访问数据库，也不改变启动确认。

发布治理同时冻结 challenge 唯一区段与完整 normalized `sw.js` 源码摘要；因此保留区段字节、却在区段前后增加 shadow handler 或副作用也会失败关闭。定向 SW lifecycle 测试另对合格和拒绝 challenge 路径都断言 `skipWaiting` 零调用。

当前 probe 对调用方传入的 page adapter 执行两项不可信观察：

1. 保持同一个页面 CDP session，在 challenge 前后各调用一次 `Target.getTargetInfo`，要求 target、URL、attached 状态与 `page.url()` 全程不变，并冻结两份 exact 投影；
2. 在页面主世界通过 MessageChannel 发出宿主随机 nonce，并冻结 SW challenge request/response 与 `event.source.id`。

probe 使用模块私有 capture brand；evidence builder 只接受经过该不可信 probe 函数路径产生的 8 个 capsule。采集顺序固定为 phase-major：先完成 Edge/Chrome 的全部 `initial-a` 双 slot，再开始 Edge/Chrome 的全部 `post-claim` 双 slot；最后一个 initial 时间必须严格早于第一个 post 时间。原先按浏览器完成 initial→post、再进入另一浏览器的 project-major 顺序会被拒绝，因为它与主候选“一次共享 A→B 切换且两个浏览器都已在 A”相矛盾。该 brand 不认证调用方传入的 page adapter，`callerSuppliedPageAuthenticityVerified` 永久为 false。离线 verifier 再重算 tuple、顺序、跨浏览器 phase barrier、origin、A/B build binding、challenge 前后 target 投影、target/client pseudonym、nonce、descriptor、连续性和全部 digest。Edge/Chrome 原始 client/target 不得重用；同一浏览器、同一 phase 的双 slot 必须分别具有不同 target/client；retained slot 的 raw target/client 跨 phase 保持，reload slot 的 target 保持而 source client 必须变化。

## 明确未证明

`page.evaluate` 和 SW structured-clone response 仍处于浏览器内容边界，CDP 数据也只保留了 challenge 前后的 host-side response projection，并非完整 transport transcript。当前导出的 probe 明确接受调用方 page adapter；纯合成或恶意 adapter 也能走完这条代码路径。模块私有 brand 只能用于阻止 evidence builder 直接接收任意普通对象，不能证明 page adapter、浏览器内容或 CDP transport 真实，也不能抵抗同权限进程或阻止整包重放。因此下列字段全部固定为 false：

- `callerSuppliedPageAuthenticityVerified`
- `runtimeCollectorProvenanceVerified`
- `osProcessRestartProvenanceVerified`
- `twoClientRuntimeProvenanceVerified`
- `serviceWorkerResponseProvenanceVerified`
- `cacheApiProvenanceVerified`
- `attemptFreshnessExternallyVerified`
- `bundleReplayResistanceVerified`
- `concurrentFilesystemMutationResistanceVerified`

本 v1 还没有 OS child-process handle/creation tuple、Service Worker target/source transcript、CDP offline ack、document response body、CacheStorage 原始字节、全请求闭包、同 Schema stale-A 生产写拒绝、provider switch 或 TLS/host raw response。因此它不能组装现有 PR6 candidate，更不能证明真实 Chrome/Edge、PWA 更新、部署、回滚、发布就绪或公开发布授权。

后续独立家族已增加 8 个完整 decoded API object tuple + manifest 的 hardened bundle writer/loader，并从这些文件重算本 v1 evidence；但它明确不是 CDP wire transcript，仍固定全部 runtime/browser provenance 与 admission 为 false。详见 [PR6 运行时已解码 API transcript 候选边界](./PR6运行时已解码API-transcript候选边界-v1-2026-08-27.md)。

当前尚未生成同时含 challenge 协议的冻结 A/B artifact；所以本轮也没有运行浏览器、网络或公开 HTTPS capture。
