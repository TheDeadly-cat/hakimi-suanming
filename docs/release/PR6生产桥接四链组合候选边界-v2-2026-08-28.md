# PR6 生产桥接四链组合候选边界 v2（2026-08-28）

## 结论

本 family 只建立一个独立的、离线的、机械不受信任的四链 producer-bridge composition candidate。它把候选证据、两链组合、已解码 API transcript、采集器临时签发以及 producer bridge 的机械绑定放在同一份 v2 合同中，但不把任何一项升级为正式 Release Evidence、运行时准入、部署或公开发布授权。

旧四链 v1 合同继续保持 `producerBridgeStatus = producer_bridge_absent`，其 policy、Schema、实现与 authority 边界均不因本 v2 family 而改变。v2 是独立 family，不覆盖、改写或追认 v1。

## 冻结的机械事实

- `schemaVersion = 2`；发布身份仍为 `legacy-v13 / targetSchema 13 / migrationId null`。
- `producerBridgeStatus = producer_bridge_present_mechanically_untrusted`，但 `trustedProducerBridgeVerified = false`。
- runtime 主输入只能是 `<bridgeRoot>/01-derived-runtime-client-capture.json`；调用方不得另传或替换 runtime capture 输入。
- bridge public loader 的 endpoint fingerprint 必须保持 `outputs` 两个业务 JSON、独立 `terminalGate`、两个 bridge sources 与 issuance fingerprint 的精确形状；v2 把 `terminalGate` 映射到 `100-producer-bridge-publication-commit.sha256` 的逻辑路径并纳入全链 physical-separation 集合，缺失 marker identity 或与其他逻辑端点发生物理 alias 都会失败关闭。
- 来源清单精确为 14 个互异 JSON：v2 自身 policy/Schema、旧两链 policy/Schema、候选 policy/Schema、runtime policy/Schema、transcript policy/Schema、issuance policy/Schema、bridge policy/Schema。raw 与 canonical SHA-256 分别冻结，不能用重排、空白、BOM 或重绑定绕过。
- `runAttemptIdentifiersMatched = true` 只表示被注入样本中的标识符机械相等；同时必须保持 `runAttemptCoordinationStatus = run_attempt_coordination_absent`、`runAttemptCoordinationVerified = false`、`candidateProducerBoundToIssuanceAttempt = false`。
- `candidateAndBridgePrimaryInputsHeldAcrossIssuance = true`、`issuanceFilesHeldAcrossCompositionBranches = true`；但 `allEvidenceFilesContinuouslyHeldAcrossCaptureAndComposition = false`。
- Schema 13 没有 mutation epoch：`mutationEpochCapability = absent_schema13`、`epoch = null`，且 continuous epoch、同权限修改排除、区间修改排除与 ABA 排除均为 false。
- 所有外部执行 attempts 全为 false；provenance 与 authority 全部保持 false；CLI 对有效机械候选仍以 JSON-only 输出并返回 exit code 1。

## 治理隔离

本 family 只允许两个 standalone package scripts：一个 focused test，一个 verifier。不得增加 writer、producer、capture、pre/post lifecycle、通用别名或 formal aggregate 别名；不得从正式 receipts、Release Evidence、migration/Quick/Release CI 的 `run` 命令或其他正式 consumer 导入、执行或间接到达。

`migration-ci.yml` 对 policy、Schema 与本文档只增加 path-only trigger，不增加执行步骤。完整正式 npm/lifecycle/workspace closure 继续保持 `84` 个 visited scripts 与 canonical SHA-256 `eaba293e79453b250ce1d3520989da0dad184843e40dd28a9231c296f2bc9092`，v2 不进入该 closure。

## 仍未关闭的缺口

自然 candidate run/attempt coordinator 仍不存在。因此，即使 v2 能在 injected/synthetic fixture 中得到完全一致的八 tuple 投影和桥接绑定，也不能声称 producer 缺口、自然生产可达性或 PR6 的真实运行时/发布缺口已经关闭。

本轮未运行浏览器、网络、真实 HTTPS、公开主机、部署、全仓 typecheck 或默认 Web build，也未读取受限的 `apps/web/src/lib/local-user-data-cleanup.ts`。全部 provenance/authority 继续为 false，尤其 `publicDeploymentAuthorized=false`、`publicReleaseAuthorized=false`、`contentTruthAuthorized=false`、`expertClaimsAuthorized=false`、`rightsLegalConclusionAuthorized=false`。
