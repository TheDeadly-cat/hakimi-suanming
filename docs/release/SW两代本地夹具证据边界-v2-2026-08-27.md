## 同一次运行身份

canonical runner 每次生成新的 256-bit 随机 `attemptId`，通过专用环境字段交给 reporter。reporter 在开始与结束时验证该值没有变化，并把它写入独占 `wx` summary；runner 读取后要求 summary 的 `attemptId` 与本次调用精确相等。缺失、格式错误、跨运行复用或执行中变化都会 fail closed。

这只防止旧 summary 或其他运行结果被当前 runner 接纳；它不是浏览器、artifact 或部署身份。

## 精确能力边界

该集合是刻意选定的 critical set，不是完整 transitive source graph。特别是：

- 没有由 bundler 证明全部模块依赖闭包；
- 没有绑定 stable A、healthy B、broken B 的实际构建目录、逐文件 inventory 或最终服务字节；
- 没有把同一 artifact 的身份跨 Edge/Chrome 运行回执对齐；
- 没有生成 current `dist/web` identity lock；
- 没有执行真实浏览器、PWA、HTTPS host、provider switch 或回滚；
- 没有取得正式 Release Evidence。

因此，`complete_transitive_source_closure_verified` 与 `fixture_product_artifact_bytes_bound` 均明确列入 `doesNotEstablish`。关键源码集合通过只能写作“当前本地关键源码快照闭合”，不能写作“浏览器运行通过”“构建产物已绑定”“接管安全已证明”或“发布就绪”。

## 三个场景的解释保持不变

1. 健康 B 受控接管、拒绝 stale A 的 ResearchDatabase 写，并验证本地离线冷启动。
2. broken B 已是 controller 时返回最近已确认的 A shell cache；这不是 worker 回滚。
3. B 安装失败时 A 保持 active；这不是部署回滚。

即使未来本地 fixture 真正执行通过，它仍不得进入默认 v13 的正式 Release Browser receipt 集，也不得继承真实 HTTPS、provider、rollback actor、内容真值、专家真值、权利法律结论或公开发布授权。
