# B 阶段真实执行前置审计（2026-08-28）

## 1. 结论

当前工作区尚不能开始真实的公开 HTTPS A→B 浏览器取证。阻断项不是某一个测试未通过，而是现实执行输入尚未成立：托管平台仍未选择、canonical origin 为空、当前没有两份可发布且带独立 identity lock 的 legacy-v13 Artifact，SW A→B candidate 也没有 production producer/runner。

本审计只登记当前文件和入口的可用性，不选择平台、不创建部署、不启动网络或浏览器，也不把旧产物、合成 fixture 或离线 verifier 记为真实运行证据。

固定发布身份继续为：

```text
channel: default-v13
dbGeneration: legacy-v13
targetSchema: 13
migrationId: null
mutationEpochCapability: absent_schema13
epoch: null
```

Schema 13 没有 mutation epoch。任何真实运行也只能记录 `epoch=null`；不得用 `0` 代替不存在的 epoch，且端点摘要相等不能外推成 interval mutation 或 ABA 排除。

## 2. 当前外部决策仍关闭

权威文件当前固定为：

| 文件 | 当前值 | 影响 |
| --- | --- | --- |
| `docs/security/hosting-security-policy.json` | `deploymentPlatform = "unselected"` | 没有可执行 provider driver 或受信 provider 身份 |
| `docs/security/hosting-security-policy.json` | `canonicalOrigin = null` | 不能运行公开 DNS HTTPS host、PWA 或 A→B origin 取证 |
| `docs/release/web-v1-release-decisions.json` | `publicDeploymentAuthorized = false` | 工程代码和候选回执不得解释为部署授权 |
| `docs/release/web-v1-release-decisions.json` | `legacy-v13 / 13 / null` | 禁止借 B 阶段把 v15/v16 晋级为默认发布代 |

在上述值由所有者明确决定并单独授权前，任何脚本都不得自行选择平台、猜测域名、读取第三方后台、复用浏览器登录态或执行外部写入。

这份目录不能充当真实 A 或 B，原因是：

## 4. 现有 runner 能力分账

### 4.1 Deployed-PWA candidate

现有入口：

```text
npm run capture:deployed-pwa-candidate
apps/web/playwright.deployed-pwa-candidate.config.ts
apps/web/e2e/deployed-pwa-candidate.spec.ts
```

它要求显式提供公开 HTTPS origin、binding/output/artifact roots、仓外 identity lock、Release Evidence ID 和 run ID，并运行真实 Edge/Chrome 的单一已部署 Artifact PWA/离线采集。它不会构建 Artifact、不会部署、不会执行同一 origin 的 A→B 切换，也不会生成 SW A→B candidate 的 38 个附件。

### 4.2 Storage-v13 matrix candidate

现有入口：

```text
npm run capture:storage-v13-matrix-candidate
scripts/run-storage-v13-matrix-candidate.mjs
apps/web/e2e/storage-v13-matrix-candidate.spec.ts
```

wrapper 会为一次 Playwright 调用生成独立 attempt ID；该矩阵面向单一锁定 legacy-v13 Artifact 的 CRUD、导出、恢复、取消和语义见证，不执行 A→B 部署切换，也不与 collector issuance 的 session 共享 attempt authority。

### 4.3 Service Worker two-generation fixture

现有入口：

```text
npm run test:e2e:sw-upgrade
scripts/run-sw-two-generation-fixture.mjs
apps/web/e2e/service-worker-two-generation.spec.ts
```

它会在系统临时目录重新构建 stable A、healthy B、broken B，并由 spec 内部的 loopback HTTP switch server 切换 generation。它能验证本地行为配方，但证据类固定为 synthetic/local fixture；不能替代公开 HTTPS、provider deployment、远端 A/B 原始字节或正式 Release Evidence。

### 4.4 SW A→B candidate 与 live issuance

SW A→B candidate 当前只有合成 fixture、离线 verifier 和 composition；没有 production candidate writer/spec/reporter。完整 v1 要求精确 38 个附件、Edge/Chrome 各一份 receipt、每浏览器 15 个事件、共享 14 个部署事件、fresh persistent profile、真实进程重开、stale-A production write 拒绝、离线路由、Cache API 和远端 A/B 字节。

collector issuance 已有：

```text
begin
→ 8 × collectNextSwAbUpdateRuntimeCollectorTupleFromPage({session, page})
→ finalize / abort
```

但非测试代码当前没有调用者。issuance 自己生成并以模块私有 WeakMap/WeakSet 绑定 run/attempt authority；deployed-PWA 和 storage runner 的 caller-provided/generated IDs 不能反向证明它们与 issuance 属于同一次现实执行。

因此，单独新增一个接收普通 JSON 或复制 `session.runId/attemptId` 的 coordinator 只能证明字符串相等，不能证明 candidate producer 自然绑定同一 attempt。本审计不建议新增这种自证层。

## 5. 开始真实执行前必须由所有者提供或授权的输入

### 5.1 外部目标与权限

1. 明确 `deploymentPlatform`；
2. 明确 canonical public DNS HTTPS origin；
3. 明确 provider account、project、site/host 身份；
4. 指定允许使用的已授权部署方式和凭据边界；
5. 明确授权对该目标执行 A 部署、B 部署和必要的远端读取；
6. 明确授权真实 branded Edge 与 Chrome、外网、persistent profile、断网、全部页面关闭和浏览器进程重启；
7. 若包含 B→A 回滚，必须另行授权，不能从 A→B candidate 自动推导。

不得把“转入 B”本身解释成第三方账户写入、公开部署、使用现有登录会话或回滚授权。

### 5.2 两份不可变 legacy-v13 Artifact

A、B 必须各自提供并冻结：

```text
artifactRoot
releaseArtifactIdentityLockPath
releaseEvidenceId
buildVersion
artifactSetDigest
serviceWorkerSha256
manifestSha256
sourceTreeDigest
packageLockSha256
```

还必须满足：

- A 与 B 物理根、文件身份、buildVersion、artifactSetDigest 和 Service Worker 字节不同；
- 两者都固定 `legacy-v13 / 13 / null`；
- identity lock 位于 artifact root 外；
- artifact root 不含本地 Evidence sidecar、临时文件、trace、profile 或测试输出；
- browser、host、provider 和 Release Evidence 全部引用同一份已锁定字节，不在中间重建。

### 5.3 Fresh 输出根

执行前需明确且不存在的独立根：

```text
candidate binding root
candidate private root
candidate attachments root
collector issuance run root
producer bridge root
browser profile roots for msedge and chrome
provider/host raw receipt roots
```

这些根不得相互重叠、不得位于 A/B artifact root 内、不得覆盖旧 attempt。失败后的根保留为 discard-required 证据，不原地修复或复用。

## 6. 获得授权后的真实顺序

```text
冻结 A/B Artifact 与 identity locks
→ 为同一次执行 begin issuance，取得不可伪造 session
→ 在同一公开 origin 部署 A
→ Edge 与 Chrome 分别以 fresh persistent profile 建立两个 A client
→ phase-major 采集四个 initial-a tuple
→ 一次全局切换到 B，并记录 provider/host 原始回执与远端字节
→ 两浏览器完成 install / waiting / claim / stale-A write 拒绝
→ phase-major 采集四个 post-claim tuple
→ 两浏览器离线、全部页面关闭、进程退出并以同一 profile 重开
→ 采集 root / deep-link / uncached canary / cache / v13 data 事实
→ finalize issuance
→ 发布 producer bridge
→ 只读验证 candidate、issuance、bridge 与 composition
→ 独立保留原始浏览器/provider/host证据
```

production candidate writer 必须与现实采集器同批落地，只接受一次性 branded provider/browser envelopes 和 issuance session；不得接受调用方提供的 runId、attemptId、浏览器事实 JSON 或“已通过”布尔值。
