# Service Worker 两代本地夹具产物字节身份边界 v3（2026-08-27）

## 当前结论

本轮把本地两代 Service Worker 夹具从“仅冻结有界关键源码”推进到“具备逐字节产物身份和只读响应快照机制”。固定发布身份仍为：

```text
dbGeneration = legacy-v13
targetSchema = 13
migrationId = null
releaseEvidenceId = unbound-local-build
schemaVersion = 3
fixtureContractId = sw_two_generation_fixture_contract_v3
evidenceClass = local_synthetic_fixture_only
status = static_contract_only_not_executed
```

本轮没有运行 Vite 构建、Playwright、Edge、Chrome 或 Service Worker 浏览器场景。因此没有生成本项目 stable A / healthy B / broken B 的实际 artifact set digest，也没有取得一次 `strictGatePassed=true` 的浏览器 summary。当前成立的是机制与纯 Node 合同，不是实际项目产物或浏览器运行证据。

## runner 所有的共享产物集

canonical runner 在自己的系统临时目录中创建唯一 `artifact-builds` 根，并在启动 Playwright 子进程前按固定角色顺序构建一次：

1. `stable-a / none`
2. `healthy-b / none`
3. `broken-b / research-route`

未来执行时，Edge 与 Chrome 必须读取同一组目录和同一 artifact-set SHA-256；spec 不再为每个 project 自行构建，也不再删除或替换产物。reporter 要求该根与独占 summary 路径处于 runner-owned 同一临时父目录。runner 是唯一清理者，并继续对删除范围做系统临时目录内的边界校验。

runner 在浏览器子进程开始前和退出后分别从原始字节重算；reporter 在 `onEnd` 独立重算；spec 在每个浏览器 project 的 `beforeAll` 重新载入并要求 digest 与 runner 传入值精确相等。artifact digest 不接受 annotation、attachment 或测试正文自报。

## 逐文件原始字节身份

`apps/web/sw-two-generation-artifact-identity.ts` 对每代输出目录递归建立不可变 inventory：

```text
algorithm = sha256
inventoryDomain = hakimi-sw-two-generation-artifact-inventory-v1
setDomain = hakimi-sw-two-generation-artifact-set-v1
inventoryTuple = [canonicalPosixPath, byteLength, rawByteSha256]
inventoryOrder = path byte/code-unit order
evidenceId = unbound-local-build
```

loader 拒绝相对根、root escape、非普通文件、symlink、改变实际路径的 link/reparse traversal、大小写碰撞、非 ASCII 安全路径、反斜杠、百分号编码和非规范 POSIX 路径。散列和后续服务使用同一次读取保存的原始 `Buffer`，不做 UTF-8、换行或 JSON 归一化。

每代必须同时满足：

- `index.html`、`sw.js`、唯一入口 chunk、唯一 research route chunk 和精确代际 marker 均存在；
- marker 原始文本精确为 `<generation>\n`；
- index 中的 build version、release descriptor、storage manifest、manifest digest 和 `unbound-local-build` 元数据自洽；
- Service Worker 的 cache version 与 release descriptor 精确绑定，且不含占位符；
- 三代 build version、inventory digest、index SHA、Service Worker SHA 和 marker SHA 两两不同；
- healthy B 与 broken B 的 research-route 内容 SHA 不同；
- 三代 release descriptor SHA 和 storage manifest SHA 相同，并继续解析为 `legacy-v13 / 13 / null`。

固定角色顺序进入域分隔的 artifact-set digest，因此交换 A/B 角色会改变或拒绝集合身份。

## 响应字节与 TOCTOU 边界

每个成功 snapshot 都由模块私有 `WeakMap` 注册；公开对象不暴露 `Buffer` 或可伪造的读取闭包。调用者每次取得的是保存字节的副本，修改副本不能影响后续响应。伪造或 spread 后的 snapshot 会被拒绝。

fixture switch server：

- 只接受同一 branded artifact-set 内的 generation；
- 在请求开始时捕获完整 active generation/failure-path 状态；
- 只从模块私有 snapshot 取响应，不在请求期重新 `stat/readFile` 构建目录；
- 拒绝百分号路径、encoded slash/backslash、路径逃逸和未知 failure path；
- `/` 与 HTML fallback 显式映射到 inventory 内的 `index.html`；
- GET 返回保存的原始字节，HEAD 不返回 body，二者的 `content-length` 与 inventory size 一致；
- 请求日志记录 artifact path、size、file SHA 和 artifact-set SHA。

纯 Node 负例已验证：snapshot 后覆盖或删除磁盘文件仍返回原始保存字节，后增文件仍不可见，调用者修改返回副本不会污染内部状态，伪造 snapshot、SW SHA alias、healthy/broken research SHA alias、角色交换、digest 篡改以及 shared root 的 extra/missing generation 均 fail closed。

## v3 summary 的窄 claim

严格 summary 新增完整 `artifactSetIdentity`，每个 `msedge` / `chrome` project 还必须记录相同的 `artifactSetCanonicalSha256`。只有 attemptId、21 文件关键源码身份、两个项目的精确三场景结果、运行产品、fresh profile、source location 和 artifact identity 全部通过时，以下两项才可为 true：

```text
localSyntheticFixtureVerified
localFixtureArtifactSetBoundToAttempt
```

该 claim 只表示 canonical 本地合成夹具运行与其共享的原始产物集合在同一次 attempt 中闭合。它不表示浏览器消费了 inventory 每一个文件，更不表示真实 HTTPS/CDN 响应字节、正式 artifact lock、部署、provider、回滚或 Release Evidence 已验证。
