# 独立 v13 公网 PWA 候选回执采集器 v1（2026-08-27）

## 当前结论

本轮只实现了平台无关的公网 HTTPS 浏览器候选回执采集代码、路径安全与纯离线合同测试；没有运行网络、Chrome、Edge、部署或默认构建。当前没有现实浏览器回执，也没有建立真实主机、PWA runtime、部署、回滚、发布就绪或公开发布证据。

当前采集结果固定为 `deployed_pwa_browser_runtime_receipt_candidate_v3`。它是未签名、未受信的候选 envelope，只能交给 `docs/release/deployed-pwa-evidence-policy.v3.json` 的离线一致性复核器；它不打开 `closed_missing_https_origin`，也不改变 `publicDeploymentAuthorized=false`、`expertClaimsAuthorized=false` 或任何发布授权账。已冻结的 v2 八附件合同仍作为历史关闭版本保留，不在原地改义。

对应的独立复核边界见 [独立 v13 真实 HTTPS / PWA 离线语义候选门 v3](./独立v13真实HTTPS-PWA离线语义候选门-v3-2026-08-27.md)。

## 固定工程边界

- 发布身份固定为 `legacy-v13 / targetSchema 13 / migrationId null`。
- `apps/web/playwright.deployed-pwa-candidate.config.ts` 只接受显式环境输入；缺少任一输入即在加载配置时失败。
- 配置固定 `msedge`、`chrome`、fresh persistent profile、`workers=1`、`retries=0`、`repeatEach=1`、`forbidOnly=true`，且没有 `webServer`、构建命令或本地 preview。
- fresh profile binding digest 只绑定规范绝对 profile 路径，不混入浏览器项目名；因此 Edge/Chrome 若误用同一路径会得到同一 digest，并被 v3 verifier 的跨浏览器独立性门拒绝。
- 执行前通过现有 `release-artifact-identity` verifier 检查本地产物目录及 identity lock；浏览器 context 成功关闭后、写任何回执前再执行一次。两次的完整 lock、Release Evidence ID、buildVersion、artifact-set digest、descriptor、PWA Manifest binding、SW binding、lockDigest，以及 binding/artifact/lock 的 `realpath/dev/ino/birthtime`、lock size/nlink/字节 SHA-256 必须完全一致；最终 verifier 自身失败也统一进入 artifact rebound 失败账。
- 案例必须通过正式 UI 的“演示排盘 → 生成 → 保存并打开”流程创建。采集器不直接向 IndexedDB 写入；Case/Revision 指纹只使用 `readonly` 事务读取两个既有记录，并且只输出规范化 SHA-256，不输出记录正文。
- 路由集合精确为在线 `/`、离线 `/settings/data`、离线精确 Case/Revision、离线 `/help` 冷启动和离线 `/help` reload。每条同时绑定 Playwright `Response.fromServiceWorker()` 与 CDP `Network.responseReceived.response.fromServiceWorker`；五个实际 CDP request ID 必须唯一，时间必须为严格递增的 canonical UTC ISO。

## Controller source 失败关闭

页面源码本身不能证明 Service Worker 实际执行源码。采集器因此必须通过 CDP `Target.*` 附着 exact `service_worker` target，并通过 `Debugger.scriptParsed` 绑定 `${origin}/sw.js` 后调用 `Debugger.getScriptSource`。当前安装的 Playwright `launchPersistentContext` 实现会返回 BrowserDispatcher 并把 default context 绑定回 Browser，正常路径使用 browser-level CDP session；代码仍保留 page CDP session 的 Target-domain fallback，以避免未来 transport 返回 `context.browser() === null` 时无条件永久失败。

此 CDP transport 尚未在现实 Chrome/Edge 上运行验证。初始在线阶段与五条路由全部结束后的离线阶段会分别重读唯一 root registration、controller/active 状态、waiting/installing、build message 和 `Debugger.getScriptSource`；恢复 online 后再次抓取远端 `/sw.js`。所有多时点 runtime/source/remote bytes 与 locked artifact 必须一致，否则以 `DEPLOYED_PWA_CANDIDATE_SERVICE_WORKER_REBOUND` 或字节不一致失败关闭。远端请求显式发送 `Accept-Encoding: identity`，固定 `maxRedirects=0`、`maxRetries=0`，并要求 exact URL/HTTP 200；任何非空且非 `identity` 的 `Content-Encoding` 都拒绝，远端字节不得冒充 controller source。

BrowserContext request 账本覆盖 `http/https/ws/wss`，每个现有及新建 Page 另监听 Playwright WebSocket 事件。只有 context 成功关闭后账本才冻结，`unexpectedExternalRequestCount` 必须从冻结集合的真实长度派生且精确为正零；调用方字面伪造、字符串、负零或非整数均被 writer 拒绝。

## 可安装性与 Manifest 分账

v3 在初始在线首页和离线矩阵结束、恢复 online 后分别通过 page CDP session 调用 `Page.getInstallabilityErrors` 与 `Page.getAppManifest`。两次 installability errors 和 manifest parse errors 都必须为空；manifest URL 必须精确为 `${origin}/manifest.webmanifest`；两次浏览器返回内容及完整 processed manifest 必须稳定。processed manifest 的 `id/startUrl/scope` 必须解析为 `${origin}/`，`display` 必须为 `standalone`。

同一两个时点还通过 BrowserContext request 独立抓取远端 `/manifest.webmanifest` 原始字节，固定 `Accept-Encoding: identity`、`maxRedirects=0`、`maxRetries=0`、exact URL/HTTP 200，并只接受 hosting policy 已列出的 `application/manifest+json` 或 `application/json`。远端初末字节必须一致，并与 artifact lock 中的 Manifest size/SHA-256 完全相同。浏览器返回的 `data` 另记自身 UTF-8 SHA-256，只与远端原始 JSON 做严格解析后的 canonical 语义比较；不得把浏览器字符串叫作远端原始字节，也不得用其中一份填充另一份。

原始 JSON 必须是无 BOM 的严格 UTF-8、无重复 key，并固定 `id/start_url/scope='/'`、`display='standalone'`。这些检查只建立当前候选包内部的安装资格与 Manifest 一致性，不证明 OS 已完成安装，也不证明真实主机、浏览器运行、部署或公开授权。

## 输出与完整性标志

必须显式设置：

- `HAKIMI_DEPLOYED_PWA_CANDIDATE_ORIGIN`：无端口、路径、查询或 fragment 的公网 DNS HTTPS origin；loopback、IP、`.local` 和 `localhost` 均拒绝。
- `HAKIMI_DEPLOYED_PWA_CANDIDATE_BINDING_ROOT`：绝对绑定根。
- `HAKIMI_DEPLOYED_PWA_CANDIDATE_OUTPUT_ROOT`：绑定根内的绝对、规范 ASCII 相对路径。
- `HAKIMI_DEPLOYED_PWA_CANDIDATE_ARTIFACT_ROOT`：绑定根内的已锁定 default-v13 artifact 根。
- `HAKIMI_DEPLOYED_PWA_CANDIDATE_ARTIFACT_LOCK`：artifact 根之外的 identity lock。
- `HAKIMI_DEPLOYED_PWA_CANDIDATE_RELEASE_EVIDENCE_ID`：与 lock 和页面相同的 `hre1-...` ID。
- `HAKIMI_DEPLOYED_PWA_CANDIDATE_RUN_ID`：8–64 字符的规范 run ID。

输出根与 artifact 根在 canonical path 上不得相等或任一方向嵌套；创建目录前先从 output 最近既有祖先的 realpath 投影目标并与 artifact realpath 双向隔离，创建后再复核，避免 alias 在失败前改写 artifact。输出根必须预先不存在，或当前精确项目子目录必须为空。目录必须是非 symlink/junction 的物理目录；binding/output/project 三层会冻结并复核 `realpath/dev/ino/birthtime`。文件使用同目录临时文件完整写入和 `fsync`，再以 exclusive hard-link publish，随后删除临时链接并确认目标是 `nlink=1` 的普通文件。每次摘要读取使用单一 FileHandle，并在读前后核对 handle/path 的文件身份、大小、链接数与 realpath。任何既有目标都拒绝覆盖。

每个项目目录只有十份 v3 raw attachments 和最后写入的 `browser-receipt.json`。新增角色精确为 `browser-manifest-audit` 与 `remote-pwa-manifest-body`；前者保存浏览器报告，后者保存远端原始 Manifest bytes。所有 runtime 校验、恢复 online、context.close、网络账冻结、最终 artifact 重验和 envelope 预计算均先完成；writer 发布 receipt 后不再执行 `testInfo.attach` 或其他 collector 动作。可恢复的 post-link 错误会先核对文件身份并删除 writer 自己发布的 receipt，故正常报错只留下必须整体废弃的十附件目录。

`browser-receipt.json` 的存在只是候选完整性的必要条件，不是单独充分条件。异常进程终止或文件系统故障仍可能留下临时文件、额外 hard link 或未经完成返回的 receipt；消费方必须继续复核目录闭集、普通文件、`nlink=1`、每个 binding/digest 与完整 v3 envelope，任何不符均整体废弃，不能复用或补写。这里的“原子”只指单文件 exclusive publish，不表示整个十一文件目录事务原子，也不把 receipt presence 冒充崩溃安全的目录提交。

当前 v3 consumer 已把 Evidence 引用的 artifact identity lock、formal receipt、host receipt、两浏览器 receipt 与二十份 raw attachments，以及可选 provider deployment receipt 汇总为 canonical path set，并在读取前与成功返回前各递归枚举一次 `receiptsRoot`：实际普通文件集合必须与该引用集合精确相等。额外普通文件、discard tombstone、临时文件、缺失引用、重复或非规范路径都失败关闭。两次枚举只是 file-set endpoint snapshots；终点没有重新持有并读取全部 receipt bytes，因而结果固定声明 `receiptBytesTerminallyRevalidated=false`、`overlappingFileHandleEpochEstablished=false`，不声称区间 mutation 或 ABA 排除。

## 可运行入口与本轮证据

- 纯离线合同测试：`npm.cmd run test:deployed-pwa-candidate-collector`
- 只覆盖新增 TypeScript 边界：`npm.cmd run typecheck:deployed-pwa-candidate-collector`
- 将来经明确 staging 与外部执行授权后采集：`npm.cmd run capture:deployed-pwa-candidate`

本轮只运行纯离线合同测试和这条采集器的定向 TypeScript 检查；它覆盖 env parser、artifact/output 双向隔离及创建前拒绝、目录与文件物理身份、完整 artifact snapshot rebound、拒绝覆盖、候选 receipt builder、多时点 SW/Manifest rebound、installability 与 parse errors、processed/raw Manifest 分账、锁定字节、重复 JSON key、外部账本 exact count、重复 request ID、非规范时间、capture ID 词汇及 config/spec 静态合同。合成输入只测试 builder，不代表浏览器执行，更不能作为 deployed-PWA v3 通过证据。

即使未来两个项目都产生 receipt，这些文件仍只是 candidate。只有在独立、后续版本中建立并审定可信 writer/parser、现实 HTTPS host、provider deployment receipt、正式 Release Evidence 绑定及外部授权后，才可讨论新的 admission；不得修改当前 v2 或 v3 policy 来把本候选直接解释为受信结果。
