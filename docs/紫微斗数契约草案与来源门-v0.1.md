# 紫微斗数契约草案与来源门 v0.1

> 日期：2026-08-10  
> 状态：能力探针；隔离 Node/Browser Worker、独立 Revision 文件竖切与 `4218` Browser 资料库竖切已可运行，未实现生产排盘或正式产品入口  
> 发布边界：不进入 `apps/web`、现有八字数据库、full v1.2、路由、Service Worker 或普通构建产物；普通 `npm run build` 仍为 `legacy-v13 / targetSchema 13`

## 1. 本轮产物

隔离包 `packages/ziwei-doushu-contracts-draft` 固定了紫微适配器必须提供的：

- 公历或中国农历输入、0～12 的时辰索引、排盘用性别参数和原始出生来源引用；
- 精确上游版本/提交与 npm 完整性、依赖图摘要、适配器/Worker 摘要、隔离执行方式、完整规则快照、162 项星曜注册表、十天干四化 manifest，以及 20×12 亮度全表；
- 历法、命身宫、按子至亥规范排序的十二宫、本命星曜、四化和十二段大限的稳定字段 ID；
- 大限顺逆依据、虚岁口径、五行局起点、连续十年区间及所绑定宫位干支；
- 来源目录、五类事实 provenance、工程样例证据级别、`ziwei-calculation-receipt/0.3-draft` 计算回执和可重算的 canonical JSON SHA-256 门；
- 十二宫/十二支唯一、13 个时辰槽严格匹配、越过验证范围即拒绝、回执与 profile 身份绑定等失败关闭条件。

契约包、`packages/ziwei-iztro-adapter-draft`、`packages/ziwei-fortel-differential-draft` 与 `packages/ziwei-workspace-artifact-draft` 的 `exports` 均固定为空。四者能参与独立 typecheck 和定向单测，但生产代码不能按包名导入。契约单测中的手写样例仍是 `synthetic_contract_fixture`；另有锁定 `iztro@2.5.8` 的隔离 Node 工程适配器，可在每次计算时新建一次性 Worker，并只在完整 Schema 与 canonical digest 门通过后返回 `upstream_regression` 工件。包内 Browser Worker 预览复用同一冻结规则快照与事实 Schema，返回完整的 Browser 专属工程工件：input、规则、facts、provenance/evidence、执行身份与四层摘要俱全，但它不是、也不能冒充 Node fixture receipt。主线程只有在重算四层摘要并核对当前九文件源码图后，才从验真 facts/rule snapshot 本地派生十二宫显示。Fortel 差分入口会通过受审的草案间窄桥再次运行固定 iztro 适配器，同时在另一个 fresh Worker 中运行 Fortel；外部 JSON 即使能重算无密钥摘要，也不能替代这次新鲜引擎运行。

workspace 草案现在保留两条不混淆的路径。Node demo 仍把完整 Node fixture 包在独立 UUID `studyId / revisionId / parentRevisionId` 的内容寻址 Revision 中，通过显式内存 Store 演示重开和 canonical UTF-8 JSON 单份导出/导入。新 Browser 研究预览固定运行在 `http://127.0.0.1:4218/`，直接保存已验真的完整 Browser 工件，而不是把 Node fixture 冒充浏览器产物；它使用独立 IndexedDB `hakimi-ziwei-browser-workspace-draft`（version 1），不进入 `apps/web` 或八字资料库。计算不会自动保存，用户明确保存后才能进入不可变资料库；重开会重新核对保存字节、索引、内容地址与完整父链，不会重新排盘。该路径不证明历史 Worker 身份或专家真值，也没有进入生产数据库。

## 2. 已冻结的关键决定

1. `sexForCalculation` 只是术式参数，不代表、更不能反推出用户性别身份。
2. 时辰索引 `0` 与 `12` 分别保留早子、晚子；13 项索引必须与冻结的地支和半开民用区间完全一致。`23:00-24:00` 中的 `24:00` 只表示区间终点，真实瞬时应写为次日 `00:00`，输入字段不接受 `24:00`。未知时辰以后走候选集协议，当前单盘输入直接拒绝。
3. `civilContext.usedForCalculation` 当前只能是 `false`，`solarTimeAdjustment` 当前只能是 `none`。民用时间、时区与坐标只保留审计上下文，不参与本草案计算；未来若据此推导时辰，必须同时冻结 IANA 时区、DST 分支、坐标和调整算法。
4. `fixLeap`、年分界、运限年分界、晚子换日、年龄分界、算法派别和天/地/人盘都属于规则，不属于出生事实。
5. 四化不能只写“默认”：规则快照必须保存十天干各一次的完整 `lu/quan/ke/ji → starId` manifest、不可变定位、条目数、内容摘要和来源，并核对本命事实与出生年干对应表项。规则快照同时保存 162 项上游键↔项目 `starId`↔唯一 zh-CN 显示名注册表，以及按项目子至亥顺序展开的 20×12 亮度全表；四化、亮度和本命事实中的星曜 ID 都必须在注册表内。
6. 十二宫数组固定按项目的子至亥顺序保存；不得直接复制 iztro 从寅宫开始的上游数组索引。当前星曜只允许 `scope: natal`，不能混入大限或流年星曜。
7. 大限必须记录 `directionBasis`，明确以出生年支阴阳 × 排盘用性别解析顺逆，并同时绑定出生年干支与规则 ID；再按五行局的虚岁起点保存十二个连续十年区间。每段还要绑定顺逆序对应宫位的角色、天干和地支；当前不把候选实现的规则伪装成跨派统一标准。
8. 五个启用事实族 `calendar`、`palaces`、`natal_stars`、`transformations`、`major_periods` 都必须至少有一条 provenance。
9. 上游全局可变配置不能在多规则并发中复用。当前 Node 适配器固定 `fresh_worker_per_calculation`：每次新建 Worker、写入并回读核对完整 profile、只计算一次，再等待唯一回执与正常退出；超时、中止、额外消息、配置失配或非零退出均失败关闭。
10. 当前只描述本命结构与静态大限区间；“当前年龄”“当前大限”和流年/月/日/时必须成为带明确 `asOf` 的另一个版本化产物。
11. 不保存第三方 class、中文显示名或上游数组索引；事实 ID 使用 `ziwei.star.*` 等稳定命名空间。
12. 契约 `0.1.0-draft.3` 使用项目定义的 `sha256-canonical-json-v1`：字符串、布尔值、有限数字与 `null` 使用 JSON 编码；数组保持原顺序并拒绝空洞或附加属性；普通对象按 JavaScript UTF-16 code unit 顺序排序键；`undefined`、`bigint`、symbol、访问器、循环引用、非有限数字和非普通对象一律拒绝。它不是对 RFC 8785 或其他外部 canonical JSON 标准的暗示。
13. 四个投影无自引用：`inputSha256` 覆盖完整输入；`ruleSnapshotSha256` 覆盖除自身摘要外的完整规则快照；`factsSha256` 覆盖完整事实；`artifactSha256` 覆盖顶层身份、输入、带新算规则摘要的规则快照、事实、provenance、evidence 及回执元数据，只排除回执中的 `inputSha256`、`ruleSnapshotSha256`、`factsSha256`、`artifactSha256` 四个值。规则摘要先算，再进入整件投影。
14. `ziweiNatalFixtureDraftSchema` 仍只做同步结构与交叉字段检查。唯一摘要成功门是异步 `verifyZiweiNatalFixtureDraft`：它先校验 Schema，再要求原始 JSON 与 Schema 规范化结果完全一致，最后通过运行环境原生 WebCrypto 重算并逐项比对四个 SHA-256；`digestVerification` 固定为 `recomputed_sha256_canonical_json_v1`。包不引入密码学依赖，也不使用自写 SHA-256；运行环境缺少 WebCrypto 时失败关闭。任何一步失败都不得接入后续适配器。
15. 摘要门能发现输入、规则、事实、provenance、evidence 与回执元数据被改写，但散列没有密钥：任何能改内容的人也能重算摘要。因此它不证明作者身份、上游实际运行、专家审核或命理真值；这些仍分别需要签名/受信执行证据与具名复核。
16. Browser 资料库的保存、恢复和清空都绑定同一个 mutation epoch/CAS；Revision 只允许 create-only，重用身份写入不同字节、内容地址碰撞、缺父、跨 study 父链、谱系环、陈旧 epoch、容量不足或事务中止均失败关闭。`clearAll` 是唯一删除例外，并且只清空独立紫微草案库。

## 4. fixture 证据门

每条样例必须把声明范围和证据状态分开：

| `truthStatus` | 可声明范围 | 进入专家计数 |
| --- | --- | --- |
| `synthetic_contract_fixture` | 仅 `fixture_structure`；即使摘要真实可重算，手写值和占位 commit 也不得称为上游回归 | 否 |
| `official_calendar` | 仅 `calendar_resolution` | 否 |
| `upstream_regression` | 精确上游版本的行为回归 | 否 |
| `differential_diagnostic` | 两个实现的差异诊断 | 否 |
| `expert_reviewed_rule` | 至少两名不同、具名审核者明确签署 `rule_profile` 的规则范围 | 仅被签署范围；仍不自动代表整盘真值 |

当前结构与摘要单测已经覆盖：13 个时辰槽及错配拒绝、验证范围边界、`rule_profile` 双人复核、162 项唯一星曜注册表、完整十干四化 manifest、20×12 亮度表与本命 scope、水二局从虚岁 2 岁起的大限连续区间、出生年支阴阳 × 性别的方向依据、五类 provenance、固定 canonical JSON/SHA-256 向量，以及对结构上仍合法的 input、rules、facts、provenance、evidence 篡改逐类拒绝。手写 fixture 会在测试中生成真实摘要，再由唯一验证门复算通过。

当前适配器已用真实 `iztro@2.5.8` 输出建立少量 `upstream_regression`，并覆盖新 Worker 身份、相同输入事实确定性、篡改 profile、预先中止，以及首版明确拒绝“闰月 × 晚子时”。Fortel 差分另锁定 32 节点 package-lock 闭包、适配器/Worker 摘要和一次性 Worker；当前每份报告固定为 84 个命名字段检查，并分别标记 `match / different / unsupported`，总分固定不存在。普通午时种子可得到 77 项同名事实相同、7 项定义未对齐；庚年种子稳定单列化科 `太阴 / 天府`。晚子两端分别采用次民用日与原民用日，当前比较入口以 `UNSUPPORTED_LATE_ZI_POLICY` 失败关闭，不把由定义差异导致的日干支和主星落宫计为普通实现差异。报告的结构/摘要读取门只证明内容自洽，不认证历史 Worker 身份；需要执行证据时必须调用 fresh 复现门，重新启动 iztro 与 Fortel，并只比较输入、具名检查、稳定源码/闭包身份和投影摘要，返回本次新报告。历史请求 ID、Worker ID、时间戳和 iztro 整件摘要明确不在可复现认证范围。回归还证明：把 iztro 星位篡改后重新计算全部无密钥摘要，虽然结构门仍可自洽，差分入口会因新鲜 iztro 重算的事实摘要不同而拒绝。这里的“相同”不等于专家验证，“不同”也不裁定错误。官方历法门从 DATA.GOV.HK 发布的香港天文台 2023–2028 六份年度 CSV 还原原始字节并复核 size/SHA/BOM/换行，连续解析 2,192 日、74 个文件内农历月界和 5 个 `12/31→01/01` 跨文件接缝；26 个春节、闰月进出及普通月界日期再与隔离 iztro 输出比较。该证据严格只覆盖公历与农历日期 `calendar_resolution`，不外推为时辰、干支、紫微规则或专家真值。契约还会把时柱地支反查到冻结的时辰槽，并逐星按宫位地支核对 20×12 亮度表；表外星曜只能使用 `null_brightness`，规则表不能只保存却不约束输出。完整 fixture 门仍要覆盖：非法/缺失时辰、立春前后、`00:00`/`01:00`/`23:00` 边界、更多男女顺逆、语言切换不改变事实摘要、上游升级差异清单，以及后续 profile 的天地人盘。`24:00` 只测试为晚子半开区间的终点表示，不作为可输入瞬时。
