# Web v1 发布章程与兼容范围 v0.1

- 状态：工程执行基线；其中标记为“负责人待确认”的事项不是最终业务或法律决定
- 生效日期：2026-08-21
- 对应本地提交：`6c5f5edf90f9e8eec51362725339f033a7985ad6`
- 产品：哈基米八字研究台
- 发布对象：八字 Web/PWA 主应用

## 1. 章程目标

在不丢失现有浏览器数据、不让应用壳、Service Worker 与数据库代际错配、不把工程一致性冒充专家真值的前提下，收口一个可安装、可离线、可备份、可恢复、可回滚并能解释自身发布身份的 Web v1。

本章程先冻结发布范围和失败关闭边界。它不授权 Schema 晋级、数据库迁移、生产部署、公开发布、许可选择或专家签字。

## 2. 产品定位

Web v1 定位为面向简体中文八字学习者与研究者的本地优先研究工具，不定位为“权威算命”“专家已验证成品”或自动决策系统。

允许对外陈述的能力必须与证据类型一致：

| 证据类型 | 可以证明 | 不可以证明 |
| --- | --- | --- |
| 工程测试 | 代码在指定输入和环境下满足工程合同 | 命理规则具有现实专家真值 |
| 浏览器测试 | 指定浏览器场景通过 | 未执行浏览器、真机或长期运行环境也受支持 |
| 来源审计 | 声明可追溯到指定来源与定位 | 来源内容可商业重分发，或争议规则已被专家裁决 |
| 专家审核 | 具名审核范围内的专业结论 | 未审核规则、其他流派或全部产品结论 |
| 权利审核 | 指定材料在指定用途下可使用 | 项目源码许可或其他材料的权利状态 |

工程差分、哈希、回执、CI 绿灯和浏览器同构均不得写成专家真值。没有现实审核签字的内容保持 `candidate`、`engineering_only` 或 `withheld`，不得伪造 `verified`。

## 3. Web v1 范围

### 3.1 首发范围

- 八字 Web/PWA 主应用及现有本地优先研究闭环。
- 可信时间输入、候选排盘、不可变 Revision、案例研究、运限研究、事件绑定、个人知识库和研究查询。
- IndexedDB 本地存储、完整备份预检、恢复、隐私清理和只读恢复。
- Service Worker、离线应用壳、深链启动、升级协调和失败关闭。
- 设置或诊断界面能够准确显示发布代、Schema、数据库和只读状态。
- 桌面 Chrome 与 Edge 作为首发正式浏览器；响应式布局继续覆盖手机宽度，但不据此声明真机支持。

### 3.2 非目标

- 不把 Schema 15 或 16 晋级为普通默认构建。
- 不把紫微斗数、西洋占星、跨术数比较或 AI 草案接入八字正式主壳、正式导航、生产数据库或八字 full v1.2 备份。
- 不增加账号、云同步、服务器数据库、付费、iOS 或社区能力。
- 不在本阶段引入 Android APK、Capacitor 或 WebView 正式支持声明。
- 不把加密备份塞入当前发布收口；当前只允许准确声明明文备份风险。
- 不做全仓架构重写、大文件统一拆分、路由库替换或视觉系统重写。
- 不把 AI/BYOK 设为 Web v1 核心依赖或发布门。

## 4. 冻结发布身份

普通构建的默认发布身份继续冻结为：

| 字段 | 冻结值 |
| --- | --- |
| `dbGeneration` | `legacy-v13` |
| `databaseName` | `hakimi-bazi-research` |
| `targetSchema` | `13` |
| `minReadableSchema` | `13` |
| `maxReadableSchema` | `13` |
| `migrationId` | `null` |
| `acceptedCommittedMigrationIds` | `[null]` |

下列行为不属于本章程授权范围：

- 通过环境变量、`localStorage`、开发者工具或临时 UI 开关改变普通发布身份。
- 绕过 mutation epoch、CAS、冻结、租约、影子迁移、备份预检或 Service Worker 门控直接写 IndexedDB。
- 让主入口在设置运行时代际前静态求值 storage 值。
- 将 v13、v14、v15 或 v16 数据破坏性降级或原地覆盖。
- 仅回滚 JavaScript，而不同时核对应用壳、Service Worker、数据库读取范围和发布描述符。

Schema 16 保持隔离候选。它只有在真实发布历史、支持来源、当前提交迁移矩阵、回滚演练和发布证据全部闭环后，才能另行提出晋级决策；历史测试记录不构成自动晋级授权。

## 5. 数据兼容策略

| 来源 | Web v1 当前策略 | 证据状态 |
| --- | --- | --- |
| 无旧数据库 | 允许按冻结身份创建 v13 数据库 | 需绑定当前候选构建复验 |
| 正式 v13 数据库 | 必须继续可读、可备份、可恢复 | 唯一已知发布来源；真实分发范围仍需负责人确认 |
| v13 full v1.2 备份 | 必须在写入前完整预检，成功时原子恢复 | 需绑定当前候选构建复验 |
| v14 / v15 数据库 | 不因代码中存在 descriptor 就推定为真实用户来源 | 负责人待确认发布历史；未知时失败关闭 |
| v16 数据库 | 不允许普通 v13 构建猜测兼容或反向写入 | 隔离候选，不是默认发布 |
| 未知 Schema / migrationId | 进入只读恢复或明确阻断 | 必须失败关闭 |

任何兼容来源只有同时具备真实分发记录、固定 fixture、迁移或读取测试及回滚路径，才能进入正式支持表。

## 7. 隐私、安全与权利边界

- 产品无账号、无云同步；隔离边界依赖浏览器 origin、profile 和本地设备。
- 完整备份包含出生资料、笔记、事件、研究资料及附件，是未加密敏感文件；压缩不等于加密。
- 导出前必须明确提示备份内容、未加密状态和可信保存位置；清站点数据不得成为默认恢复操作。
- 生产托管平台尚未确定。公开部署前必须确定 HTTPS、CSP、`frame-ancestors`、`Referrer-Policy`、`Permissions-Policy`、MIME 防护、缓存与回滚配置的落点。
- 项目自身许可尚未确定。当前不得宣称项目开源；正式公开分发、外部贡献或商业合作前必须由负责人选择开源许可、source-available 许可或版权保留方案。
- 第三方来源的“可审计引用”“可执行验证”“可随产品重新分发”是三个不同状态，必须分别记录。

## 8. 发布门

### 8.1 v13 Web v1 候选门

- 发布身份与本章程第 4 节完全一致。
- 工具链版本被机器可读配置锁定，并使用锁文件安装。
- 快速 CI 至少覆盖边界检查、typecheck、单元测试和普通构建。
- 备份、恢复、隐私清理、离线、深链、旧 Service Worker、双标签页和启动失败关闭得到与当前提交绑定的证据。
- Release Evidence 至少绑定 Git SHA、lockfile 摘要、发布描述符摘要、工具链与浏览器版本、测试结果和最终构建文件摘要。
- 公开部署前完成托管安全配置、许可决定、隐私文案和回滚演练。
- 专家与内容权利状态独立记录，不以工程门替代。

### 8.2 Schema 16 晋级附加门

- 负责人确认真实用户运行过的全部数据库代际和构建身份。
- 每个允许迁移来源都有真实证据、固定 fixture、失败关闭用例和回滚方案。
- 当前提交重新通过支持矩阵内的跨 Schema、多标签页、旧 Service Worker、中断、容量、备份与恢复门。
- 原 v13 数据库保持只读可恢复，不把 v16 数据反向写回 v13。
- 晋级作为独立发布决策审批，不与 UI 功能、内容扩张或安全头修改混为一个变更。

任一附加门缺失时，Schema 16 继续保持候选，普通构建仍为 v13。

## 9. 当前已知治理缺口

截至本章程建立时，以下事项仍未闭环：

- storage 在缺少运行时配置时仍隐式使用 Schema 14，而普通 Web 构建固定为 Schema 13；修复必须先建立唯一、类型安全的发布清单，并单独回归启动与迁移边界。
- 发布身份、表清单和缓存代仍分散在发布协议、Vite 配置、storage、Service Worker 与文档中。
- 仓库没有提交级 CI 工作流，历史测试记录没有自动绑定当前提交和最终产物。
- 根 `package.json` 尚未声明 `packageManager` 与 `engines`。
- 项目自身 LICENSE、SECURITY、Issue/PR 模板和当前发布状态页缺失。
- 真实 v14/v15 分发历史、生产托管平台、许可策略和固定 Android 真机范围仍需负责人确认。

这些缺口不得通过修改说明文字伪装为已完成。

## 11. 工作拆分与顺序

1. 锁定工具链、许可策略和仓库治理文件。
2. 建立分层 CI，先绑定当前 v13 普通构建证据。
3. 建立唯一 `ReleaseStorageManifest`，只表达现有身份，不改变默认行为。
4. 移除 storage 隐式默认并强化主入口静态导入边界。
5. 生成机器可读 Release Evidence，重新运行支持范围内的迁移和浏览器门。
6. 补齐启动恢复体验、明文备份提示和公开托管安全配置。
7. 根据真实代际历史与门禁结果，另行决定继续发布 v13 或提出 v16 晋级。
8. 最后执行发布与回滚演练，归档构建产物和证据。

数据库代际、Service Worker 协调、备份恢复和用户体验修改应拆分审查，不得打包成无法判断数据影响的单次大改。

## 12. 变更控制

下列变更必须更新本章程或建立具名决策记录：

- 默认 `dbGeneration`、数据库名、`targetSchema`、migrationId 或允许读取范围变化。
- 正式浏览器、Android、AI、云同步或服务器能力进入范围。
- 项目许可、生产托管平台、隐私模型或备份机密性承诺变化。
- 紫微、西洋占星或跨术数草案申请进入正式主壳。
- 专家审核状态或内容商业分发权发生变化。

若代码、构建产物、测试证据和本章程发生冲突，发布必须停止；不得选择对发布最方便的一份作为“真相”。
