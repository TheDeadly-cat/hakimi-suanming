## 1. 审计结论边界

本表只审计当前关系事实包实际执行的规则，不代表 P0-03 已验收。

- **代码确定性通过**：表示同一合法四柱与同一规则配置会产生稳定、去重、排序固定的事实；输入校验、完整/不完整集合、自刑和无断语词测试已经通过。
- **命理顾问确认**：表示规则成员表、流派口径及展示措辞已有可追踪的顾问裁决。目前全部规则均为“未确认”，上游开源常量也不能替代顾问裁决。
- P0-03 仍缺：关系规则顾问裁决、按项目十二类配额补齐并现实复核 360 例，以及面向关系事实与完整四柱的独立外部差分及差异归因。当前固定 `UTC+08:00` 的 20,000 例只完成内部完整排盘双跑和公历→农历日期字段对照，不能替代上述关系规则验收。
- 本包只陈述成员关系，不判断合化、力量、旺衰、喜忌或事件结果。

“可用于 v1 展示”含义：

- **是（事实）**：可显示关系成员和来源，不得追加推断。
- **是（候选）**：必须显示“待复核”或“不完整集合”状态。
- **仅研究模式**：不进入普通用户默认结果，可供研究者检查规则来源。
- **否**：在顾问裁决前不建议进入 v1 界面。

## 2. 来源审计

### 2.1 lunar-typescript 1.8.6

固定版本提交：`0f3e95d15e31f1a7c7b93d624542649347328a20`

公开常量来源：

- `LunarUtil.CHONG`、`CHONG_GAN_4`、`HE_GAN_5`、`HE_ZHI_6`
- <https://github.com/6tail/lunar-typescript/blob/0f3e95d15e31f1a7c7b93d624542649347328a20/src/lib/LunarUtil.ts#L809-L814>

审计结果：

- `HE_GAN_5`、`HE_ZHI_6`、`CHONG` 是对称伙伴表，关系包在模块初始化时复制并校验长度、成员域和双向对称性。
- `CHONG_GAN_4` 虽公开，但 1.8.6 的 I18n 注册遗漏使其保留 `{tg.geng}` 一类占位符；关系包先通过公开 `I18n.getMessage` 翻译，再校验并复制。
- `CHONG_GAN` 是黄历冲煞目标干表，不是天干四冲，本包未使用。
- 上游没有可直接用于四柱关系的三合、三会、刑、自刑、害、破公开表。

## 4. 包内版本化规则

共同代码状态：`embedded_table_pending_consultant_review`。  
共同表版本：`hakimi-relations-core:embedded-tables@1.0.0`。  
共同顾问状态：**未确认**。

三成员规则的 `completeness`：

- 三个不同成员齐全：`complete_set`。
- 只出现两个不同成员：`incomplete_set`，并明确列出 `missingMembers`。
- 只有一个成员：不输出。
- `incompleteSetPolicy = complete_only` 可完全关闭二缺一输出。
- 重复支只增加参与柱位，不会伪装成缺失的第三个不同成员。

## 5. v1 展示门槛汇总

| 关系 | 当前建议 | 展示约束 |
|---|---|---|
| 天干五合、地支六合、地支六冲 | 可进入事实层 | 只显示成员、柱位、来源，不显示合化或结果判断 |
| 完整三合、完整三会 | 可作为待复核候选 | 必须显示 `complete_set` 与待顾问复核状态 |
| 不完整三合、三会 | 可作为研究候选 | 文案必须明确“缺一成员”，不得简称为已形成三合/三会 |
| 六害 | 可作为待复核候选 | 不输出方向性和结果解释 |
| 天干四冲、三刑、子卯刑、自刑 | 仅研究模式 | 等待流派、方向性及成立条件裁决 |
| 六破 | 暂不展示 | 先裁决寅亥、巳申以及统一六对口径 |

## 6. 后续验收证据

关系事实包的工程测试通过不等于 P0-03 完成。后续至少需要：

1. 顾问对本表每个规则 ID 给出“接受、修改、弃用”及理由。
2. 建立不少于 360 条金标，覆盖每个规则、重复柱位、不完整集合、无关系和多关系同盘。
3. 在已冻结的 20,000 例内部排盘/公农历字段诊断之上，增加关系事实与完整四柱的独立外部差分，区分上游差异、规则表差异、集合完整度差异和排序差异。
4. 将顾问裁决固化为新的规则表版本；不得直接覆盖 `embedded-tables@1.0.0`。
5. v1 界面按本表展示门槛过滤，并保留 `algorithmId`、`tableVersion`、`verificationStatus`、`sourceRefs` 与 `knownGaps`。
