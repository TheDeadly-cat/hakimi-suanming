# 紫微内容 v0.3：十四主星命财官迁位置化候选与证据（2026-08-12）

## 1. 本轮结果

在 4218 紫微隔离工作台的十四主星基础语义之上，新增第一批真正区分位置的问题域内容：

1. 以十四主星为行、命宫／财帛宫／官禄宫／迁移宫为列，冻结恰好 56 条位置化候选；每一条都是单独撰写，不用一套泛化模板替换宫名。
2. 用户选择命宫后，三方四正的四张事实卡会直接显示当前盘面命、迁、官、财四宫命中的位置化短解；默认工程样例实际显示 5 条，因为迁移宫有紫微、天府两颗主星。
3. 用户改选非核心问题宫位时，其他八宫不会借用这 56 条内容，`palaceCandidateContent` 固定返回 `null`。
4. 每条包含主星与宫位稳定 ID、位置观察、该宫专属“位置合参”提示、古典落宫篇目与现代宫位资料定位，以及待专家复核／隔离候选／禁止直接结果和评分的声明。
5. 这 56 条只进入主线程只读显示投影；没有改 Worker 事实、Browser 工件、Revision、IndexedDB Schema、保存事务或 mutation epoch 协议。

这一步完成的是“同一颗星落在不同核心宫位时，用户看到不同的可审阅观察”，不是吉凶直断，也不是紫微专家真值。

- 推导方式：`editorial_synthesis_of_star_theme_and_palace_domain`

## 4. 本轮来源与版权审计

### 4.1 宫位问题域

- [iztro 宫位系统](https://docs.iztro.com/zh_TW/learn/palace)把本命盘宫位限定为态度与观念层，明确指出本命盘本身没有简单好坏；其中命宫用于观察本质属性，财帛宫看财务态度而非财富金额，官禄宫看做事方式，迁移宫看进入外部环境的呈现。
- 原页面保留作者版权和署名要求。本项目只核对四个问题域后重新组织候选短句，没有复制其段落或表达结构；UI 为每条候选提供来源链接。

### 4.2 古典落宫定位

- [《紫微斗数全书》卷二](https://zh.wikisource.org/wiki/紫微斗數全書/卷二)按十二宫分节，并在命、财帛、迁移、官禄四节逐星列出十四主星，证明传统文本确实把“星”与“落宫位置”分开组织。
- [《紫微斗数全书》卷三](https://zh.wikisource.org/wiki/紫微斗數全書/卷三)另说明先看命、身，再参迁移、财帛、官禄三方，为本轮优先做命财官迁提供结构性依据。
- [维基文库总页](https://zh.wikisource.org/zh-hans/紫微斗數全書)将清朝原作标为公有领域，同时页面转录文本受 CC BY-SA 4.0 约束。本轮只登记篇目和星名定位，没有复制古典段落。

古典文本含有财富、灾祸、疾病、职业、性别等强断语。本轮全部排除，只把“哪颗星在哪个宫位有独立条目”当作内容定位依据。

### 4.3 现代产品形态交叉核对

- [十二宫指南](https://starnum.com.tw/blog/zh-CN/basics-12-palaces-guide-pillar)用“宫位是舞台、星曜是演员”说明同一颗星落在不同宫位需要换问题域，并要求合看辅煞、四化和三方，而非单星下结论。
- 该页面只用于研究产品如何解释“星 × 宫位”的信息层级，没有进入逐条来源注册表，也没有复制其文案。

现代网页、古籍转录和项目编辑候选是三种不同证据；它们都不能替代用户或专家审稿。

## 5. 代码与失败关闭边界

### 5.1 注册表门

模块初始化时要求：

- 条目数量必须恰为 56，14 个冻结主星各有四宫且每宫恰有 14 条；
- `contentId`、`starId × palaceRoleId` 和 56 段位置短句分别唯一；
- 主星 ID 与 v0.2 基础语义注册表的中文标签必须一致；
- 每条恰有两个有效来源引用；
- 位置短句不得包含“你、一定、必然、注定、保证、终身、大吉、大凶、发财、富贵、适合”等个人化、绝对化或结果化措辞。

### 5.2 投影门

- 只有 `category:"major"` 且宫位角色是 `life / wealth / career / travel` 才查位置化注册表。
- 核心宫主星缺条目或标签不一致时直接抛错，不显示半套内容。
- 其他八宫及所有辅／杂曜固定得到 `palaceCandidateContent:null`。
- UI 找不到某条候选的来源注册项时停止渲染，不生成无来源内容。

### 5.3 保存门

- 新候选没有新增 Store、写字段或事务分支，不写回 Browser 工件与 Revision。
- 应用内浏览器只执行计算、宫位切换和查看；开始与结束时 Revision 均为 0、资料代次均为 5，没有点击保存。
- Edge 自动门执行原有保存／恢复／并发冲突流程，仍经过既有 mutation epoch 比较和原子事务；没有直接改 IndexedDB。
