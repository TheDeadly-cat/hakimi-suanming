# S0 内部工程竖切说明 v0.1

> 历史快照：本文保留 S0 当时的能力边界。当前工程版已新增 IANA/DST 归一化、太阳时对照、固定 +08 节气/本地日时混合适配、核心分区备份与 PWA 失败新代回滚。当前状态以 [README](../README.md) 和 [v1 验收矩阵](./v1功能验收矩阵-v0.1.md) 为准。

> 日期：2026-08-01  
> 状态：可运行工程预览，不是 MVP，不是 v1  
> 产品顺序：Web/PWA 先行；之后优先 Android；不做 iOS 与付费

## 1. 本阶段要证明什么

```text
打开工作台
→ 输入一个明确的公历分钟时间
→ 绑定版本化工作规则
→ 调用真实历法适配层
→ 展示四柱与复算元数据
→ 事务化保存 Case + Revision
→ 刷新或离线重开
→ 得到同一结果哈希
```

S0 的价值是验证计算、契约、存储、PWA 与响应式架构能连成一条真实链路。页面持续显示“工程预览”，不得称为稳定排盘或完整 v1。

## 3. 当前主动限制

1. 只计算公历、分钟精度、`Asia/Shanghai` 墙上时间。
2. 不使用 `Solar.fromDate()`，避免宿主时区改变输入。
3. 尚未解析历史 DST、UTC 瞬时点、经纬度修正或真太阳时。
4. 上游所有命盘字段都标为 `experimental / engineering_preview`。
5. 不输出旺衰、格局、调候、用神、神煞或 AI 解读。
6. 对照台只实现同盘 23:00 / 00:00 两规则复算。
7. PWA 已按构建指纹切换缓存并预缓存当前路由资源，但尚不具备完整 v1 的升级失败回滚与数据迁移保证。

## 4. 当前自动化基线

- `npm run typecheck`：TypeScript 严格检查；
- `npm test`：契约、规则、哈希、换日、存储事务、矩阵交互与 PWA 静态契约；
- `npm run build`：生产构建与路由级代码拆分；
- `npm audit --omit=dev`：生产依赖漏洞检查。

真实浏览器离线验收使用全新站点源：首次在线安装后停止本地服务器，在无服务器响应的状态下完成演示排盘、得到 `ecb1696c…59d4c0`、写入 IndexedDB、打开案例深链并再次刷新；四柱、规则快照与结果哈希保持一致。

单元测试里的排盘值只用于上游适配回归，不计入 360 例人工裁决金标准。

## 5. 达到 v1 前仍必须完成

以 [v1 功能验收矩阵](./v1功能验收矩阵-v0.1.md) 为唯一完整通过线，尤其包括：

- 完整时间规范化、公农历/闰月、未知时辰与真太阳时；
- 360 个金标准输入、超过 900 条断言和每次发布至少 20,000 个差分样例；
- 运限到流时、事件验证、案例检索/保存视图、批量导入；
- 四盘/多修订/多规则对照、典籍全文与反向引用；
- PNG/PDF/Markdown/研究表格导出与匿名化；
- 全量备份、跨浏览器恢复、PWA 原子升级和回滚；
- 无障碍、容量、隐私与 Android Capacitor 迁移门。

任一项未通过时，不能把 S0、测试版或某个可操作页面改名为 v1。
