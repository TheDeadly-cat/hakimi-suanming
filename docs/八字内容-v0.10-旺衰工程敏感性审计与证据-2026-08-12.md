# 八字内容 v0.10：旺衰工程敏感性审计与证据

日期：2026-08-12

状态：Web v1 已把当前旺衰候选的权重、阈值与月令重复计权风险展开为六个只读工程审计场景；没有选定正式替代规则，没有签发专家旺衰结论，也没有据此自动判十神、神煞或总体吉凶

## 1. 本轮结论

当前 `hakimi-bazi-strength-ten-god-candidate/0.1.0` 能给出明确的身强身弱候选及因素账，但它原先只有单一路径：

- 月令主气计 4 权重；
- 非日主透干计 2 权重；
- 每支第一藏干计 2 权重，其余藏干计 1 权重；
- 支持侧占比按 `0.25 / 0.43 / 0.57 / 0.75` 四个阈值分成五档。

源码审计确认，月支第一藏干既作为“月令主气”计 4，又在一般藏干循环中再计 2。经典文本可以支持“月令重要，同时不能脱离全局”的研究方向，却不能证明项目当前的 `4/2/1` 数值、重复计权或四个阈值。因此，本轮没有把另一套权重包装成更正确的门派，而是新增 `hakimi.bazi.strength_sensitivity_review/0.1.0`，让用户和专家直接看见不同工程假设是否会改变结论。

固定演示盘 `乙亥 / 甲申 / 辛巳 / 壬辰` 的本轮结果：

| 工程场景 | 支持侧 | 泄耗克侧 | 支持占比 | 分档 |
| --- | ---: | ---: | ---: | --- |
| 当前 0.1.0 候选 | 11 | 14 | 44.0% | 相对中和 |
| 月支主气去重 | 9 | 14 | 39.1% | 偏弱 |
| 去重后等权出现 | 5 | 9 | 35.7% | 偏弱 |
| 不计月令加权项 | 7 | 14 | 33.3% | 偏弱 |
| 省略透干 | 11 | 8 | 57.9% | 偏强 |
| 省略一般藏干 | 4 | 6 | 40.0% | 偏弱 |

六个场景出现 3 种分档与 2 种支持/泄耗方向，所以该演示盘标记为 `direction_sensitive`，界面直说“支持/泄耗方向对工程假设敏感”。这说明当前模型不能把单一分档伪装成无争议真值；它不证明六个场景中的任何一个就是正确门派规则。

### 2.1 实际使用的资料角色

- 用户提供的[周易天地八字排盘页](https://www.zhouyi.cc/bazi/sm/)只作为“输入后立即看到命盘与相关内容”的产品路径参考，不作为权重、阈值或断语来源。
- [《滴天髓阐微》](https://zh.wikisource.org/zh-hant/%E6%BB%B4%E5%A4%A9%E9%AB%93%E9%97%A1%E5%BE%AE)“衰旺”相关文本用于确认：旺衰不能只机械等同于得令，月令与年、日、时的得失需要合看。
- [《三命通会》卷五](https://zh.wikisource.org/zh-hans/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83/%E5%8D%B7%E4%BA%94)用于确认十神生克定义及月令、位置、强弱、组合与转化需要共同审视。
- [《渊海子平》](https://zh.wikisource.org/zh-hans/%E6%B7%B5%E6%B5%B7%E5%AD%90%E5%B9%B3)用于复核藏干、气势与“轻重较量”属于传统讨论范围。

项目既有 CText 来源 ID 继续保留在规则包中，但本轮在线打开 CText 直链时收到 HTTP 403，不能把该次失败请求写成“本轮成功读取”。Wikisource 可访问文本只支持展示假设与挂起裁决，不支持以下数值声明：

- 不支持月令必须为 4 权重；
- 不支持透干和主藏干必须同为 2 权重；
- 不支持月令主气必须同时作为月令项和一般藏干项累计；
- 不支持 `0.25 / 0.43 / 0.57 / 0.75` 是经典或专家批准阈值；
- 不支持把工程敏感性场景命名为真实流派。

## 3. 新协议与失败关闭

### 3.1 共用分档模块

`packages/bazi-interpretation/src/strength-thresholds.ts`

- 把原先藏在 `index.ts` 中的五档分类器与标签提取为共用纯函数；
- 原有阈值和边界包含关系保持不变；
- 对负数、`NaN` 与无穷值失败关闭；
- Profile 明示阈值证据类为 `engineering_candidate_thresholds`，审阅状态仍为 `candidate_pending_expert_review`。

### 3.2 六场景只读审计

`packages/bazi-interpretation/src/strength-sensitivity-review.ts`

投影固定包含六个场景：

1. `baseline_current_candidate`：原样复现当前候选；
2. `deduplicate_month_main`：保留月令项，移除同一月支主藏干的再次计权；
3. `equal_presence_deduplicated`：去重后所有剩余因素等权为 1；
4. `without_month_command_bonus`：移除独立月令项，保留月支主藏干的一般出现；
5. `without_visible_stems`：暂时省略所有透干；
6. `without_hidden_stems`：暂时省略所有一般藏干，保留独立月令项。

每个场景公开纳入/排除因素 ID、原权重、应用权重、支持与泄耗克合计、支持占比、分档、宽方向及是否同基线一致。所有场景均固定：

- `officialRuleCandidate:false`；
- `selectedOfficialScenarioId:null`；
- `expertStrengthVerdict:null`；
- `overallGoodBad:null`；
- `result:null`。

校验器会拒绝：

- 因素 ID 重复；
- 非正或非有限权重；
- 场景缺失或场景 ID 重复；
- 纳入与排除集合未完整覆盖原因素账；
- 应用权重与纳入因素不一致；
- 场景汇总、分档与因素账不一致；
- 基线未精确复现现有候选；
- 来源 ID 在原解释结果中不存在；
- 任一敏感性场景被提升为正式规则；
- 任一专家结论、总体吉凶或最终结果被非空写入。

投影只读取 `BaziInterpretationResult`，不修改命盘、Revision、规则快照或输入解释结果。

## 9. 待用户与命理专家裁决

界面现在直接列出四个最小问题：

1. 月令主气与同一月支主藏干是否应同时计权；若同时计权，边界依据是什么？
2. 透干、藏干与月令之间应采用怎样的相对权重，哪些反例会推翻当前 `4/2/1` 候选？
3. `0.25 / 0.43 / 0.57 / 0.75` 分档阈值是否有可复核案例集支持？
4. 从格、专旺、化气、合化、刑冲、调候等结构应在何时使基础旺衰结论失效或改写？

后续如果要把敏感性审计推进为专家规则，至少需要：明确流派与版本、逐条权重裁决、阈值边界案例、特殊格局反例、独立复核人和可重放的金标记录。没有这些输入前，可以声明“当前候选的工程敏感性已经公开并可复核”，不能声明“身强身弱已获专家确认”“某个替代场景就是正式规则”或“十神神煞吉凶已经据此定案”。
