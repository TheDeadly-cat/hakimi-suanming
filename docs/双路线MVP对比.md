# 哈基米产品双路线 MVP 对比

> 目的：把“中国大陆文化自我探索版”和“海外中文命理解读版”展开成两款实质不同的产品，并定义各自边界。  
> 状态：已确定 B 为先行主产品，A0 为独立辅产品；大陆路线不代表已获得合规结论。
> **后续更新：** 当前只推进 B 专业研究版，A0 与付费不进入本轮实施；最新基线见 [产品方向更新 v0.2](./产品方向更新-v0.2-专业研究版.md)。

## 1. 先看结论

| 决策维度 | A：中国大陆候选版 | B：海外中文候选版 |
| --- | --- | --- |
| 工作名 | 哈基米东方生活志 / 哈基米人生地图 | 哈基米命理 / Hakimi Life Map |
| 产品实质 | 传统历法文化学习、生活记录、开放式自我反思 | 八字排盘、可解释的命理解读、AI 追问和阶段复盘 |
| 与“算命 App”原愿景的距离 | 较远，必须放弃预测与付费命书 | 较近，可以保留个性化解释 |
| 首版主渠道 | 境内响应式 Web/PWA，但预审通过后才能公开发布 | 全球响应式 Web/PWA |
| 收费 | 只研究文化课程、阅读和记录工具，且先做实质预审 | 可测试专题报告、短期问答权益和后续会员 |
| 最大风险 | 即使换名，实质功能仍可能被认定为网上算命 | 多地区隐私、支付、客服与获客成本 |
| 推荐条件 | 业务必须服务大陆，并接受产品实质转型 | 核心愿景是现代命理解读，愿意先服务海外中文用户 |

**当前决定：** B 海外中文命理解读版先行验证；A 也做，但默认从 A0 文化与生活志版开始，使用独立内容、数据、支付和发布平面，不把 B 通过地区开关伪装成 A。

## 2. 路线 A：中国大陆候选版

### 2.1 产品定义

一款 18+ 的传统历法文化学习和生活反思工具。它展示干支、节气、历法等可核验知识，帮助用户记录当下状态和目标；不声称预测未来，也不根据命理输出吉凶结论。

### 2.2 两个风险层级

#### A0：相对保守的验证版

- 不要求出生日期和时辰；
- 以今日节气、历法知识、主题阅读和个人日记为主；
- AI 只解释文化概念、总结用户自己写下的内容、提出开放式问题；
- 不展示个人八字、流年、合盘或“你的命格”。

这条路线最容易与“自我探索工具”保持一致，但离原始算命产品最远。

#### A1：需要专项预审的文化排盘版

- 用户可输入出生日期、时间和城市；
- 只展示历法转换、四柱结构和有出处的概念说明；
- 不生成性格、感情、财富、健康或未来预测；
- 不销售个人命书或运势报告；
- 必须先让律师和属地主管部门判断产品实质是否仍属于网上算命。

不能把 A1 当作已经安全的默认方案。

### 2.3 核心页面

1. **首页 / 今日历法**：日期、节气、文化条目、今日记录入口；
2. **文化图谱**：干支、五行、节气等知识路径；
3. **问哈基米**：仅做知识解释和开放式反思；
4. **生活志**：情绪、事件、目标和每周复盘；
5. **我的**：年龄提示、同意记录、数据导出和删除。

A1 在预审通过后才增加“历法档案”页面，并严格限制为结构和知识说明。

### 2.4 第一次体验

```text
选择“了解一个文化概念”或“做一次生活复盘”
  → 浏览一条带出处的历法文化内容
  → 选择当前想记录的生活主题
  → 回答 3 个开放式问题
  → AI 只总结用户自己表达的重点
  → 用户确认、修改并保存为一页生活志
  → 选择下次回顾时间
```

### 2.5 明确不做

- 不出现“测算、吉凶、今日运势、近期有灾、改命转运”等能力；
- 不回答“什么时候发财、会不会离婚、能不能治好”等问题；
- 不卖付费预测、命书、合盘、法事、符咒或开运物；
- 不面向未成年人；
- 不将“传统文化”作为隐藏算命功能的包装。

### 2.6 留存闭环

```text
文化内容进入
  → 一次结构化自我记录
  → 用户自己设定下一步行动
  → 每周回顾变化
  → 形成个人生活志时间线
```

留存来自用户自己的记录与复盘，不来自“每天来查看吉凶”。

## 3. 路线 B：海外中文候选版

### 3.1 产品定义

一份可以追问的东方人生说明书：由确定性程序完成八字排盘，由可追溯的规则层组织解释，再由 AI 以温和、不绝对的语言帮助用户理解和复盘。

### 3.2 核心页面

1. **首页 / 此刻**：当前关注主题、继续对话、近期记录；
2. **我的命盘**：四柱、五行和核心结构，术语逐层解释；
3. **问哈基米**：围绕命盘证据和真实问题连续交流；
4. **人生地图**：性格、关系、事业、阶段主题等报告；
5. **我的**：出生档案、购买权益、AI 标识、隐私与删除。

### 3.3 第一次体验

```text
选择当前最关心的主题
  → 输入出生日期、时间和城市
  → 系统说明数据用途与不确定性
  → 确定性程序生成命盘
  → 先展示 3 条可追溯的核心观察
  → 用户标记“有共鸣 / 不确定 / 不符合”
  → 围绕一条观察继续追问
  → 登录保存命盘、反馈和对话
```

不知道出生时辰时，只展示不依赖时柱的内容，并明确降低解释范围。

### 3.4 免费与付费候选

**免费价值：**

- 完整基础排盘；
- 3 条真正有信息量的解释；
- 每条解释的“为什么这样说”；
- 少量追问；
- 数据导出和删除永远不收费。

**验证后再测试的收费对象：**

- 一次事业、关系或年度主题报告；
- 限定时间的连续追问权益；
- 有稳定周期价值后再测试会员；
- Web 与未来 App 共用后端权益，避免重复购买和平台割裂。

价格不是本轮要拍板的事项，先验证用户愿意为什么价值付费。

### 3.5 明确不做

- 不承诺“最准”；
- 不给死亡、疾病、投资收益和灾祸的确定性预测；
- 不用负面结果制造付费压力；
- 不替用户决定是否结婚、离婚、辞职、投资或停止治疗；
- 不同时上线多种术数；
- 不在首版做社区和真人老师市场。

### 3.6 留存闭环

```text
首次命盘洞察
  → 围绕真实问题追问
  → 保存自己的理解或行动
  → 一段时间后回来复盘
  → 形成个人事件与洞察时间线
```

留存不能只靠每日运势通知，而要靠“这款产品记得我，并帮助我看到变化”。

## 4. 两条路线共用的系统底座

不论选择哪条路线，都可以共用以下能力：

- 响应式 Web/PWA；
- 账号、游客模式和跨设备同步；
- 历法与时区标准化模块；
- 可版本化的知识库与内容规则；
- 模型供应商适配层；
- AI 输入输出审核、标识与审计记录；
- 同意、导出、更正和删除；
- 服务端统一的订单与权益模型；
- 设计令牌和品牌组件。

但两条路线不能在生产环境中共用同一套提示词和功能开关后随意切换。地区、内容、支付与数据边界需要可验证的隔离。

## 5. 跨端页面原则

### 手机端

- 底部导航不超过 5 项；
- 一次只展示一个主要结论或任务；
- 长报告拆成章节和卡片；
- 表单先给最少字段，解释为什么收集；
- 分享图和导出内容保留 AI 标识与来源说明。

### 网页端

- 使用相同信息架构，不另造一套产品；
- 左侧导航，中间阅读或对话，右侧显示依据和术语解释；
- 支持深链接到具体报告章节；
- 优先适配长报告、搜索、打印和 PDF 导出；
- 账号、命盘、记录和权益与手机浏览器完全一致。

### A 路线的具体导航

手机端只保留四项：**今天、历法、记录、我的**。“问哈基米”不是无限制聊天入口，只作为知识页和记录页中的上下文操作，例如“解释这个概念”或“整理这段记录”。

网页端采用左侧导航与双栏工作区：左侧为日期、知识目录或记录列表，右侧为正文、出处和编辑区。AI 整理结果与用户原文并列，不能覆盖原始记录。

“今天”与“历法”页面不出现宜忌评分、吉凶颜色、生肖运势、择日建议或“今日适合做什么”等预测性组件。

### B 路线的具体导航

手机端保留五项：**今天、命盘、问哈基米、报告、我的**。“今天”不做随机每日运势，而是优先显示继续上次对话、本周复盘和收藏洞察。

网页端采用三栏：左侧为导航与人物档案，中间为命盘、报告或对话，右侧可折叠栏显示出生资料准确度、当前引用的命盘证据和记忆开关。用户应始终能看见回答依据，而不是只看到一段 AI 文案。

## 6. 原型验证方式

选择路线后，不立即开发完整后台。先制作 5 个可点击页面和真实内容样稿：

1. 首页；
2. 建档或主题选择；
3. 第一份结果；
4. AI 对话；
5. 保存或付费页面。

同时准备：

- 20 条允许输出；
- 20 条拒绝或安全改写输出；
- 3 套营销文案；
- 8～12 名目标用户访谈；
- 大陆路线的律师与属地预审材料。

## 7. 第一轮验证问题

### 用户价值

- 用户能否用自己的话说出产品是什么？
- 第一份结果是否提供了普通聊天机器人无法替代的结构？
- 用户是否愿意继续问一个真实问题？
- 用户是否知道哪些内容是计算、规则和 AI 表达？
- 用户是否愿意一周后回来回顾？

### 风险与信任

- 用户是否误以为产品能确定预测未来？
- 出生时间不知道时，降级提示是否清楚？
- 用户能否找到数据删除入口？
- 高风险问题是否稳定拒绝或改写？
- AI 内容在页面和导出中是否有清晰标识？

## 8. 已定实施顺序

1. 先做 B 的五页原型、海外地区核验和计算适配层样机；
2. 同期只做 A0 的一页文化原型与能力白名单，用来验证品牌共用和实质隔离；
3. B 验证通过后进入 MVP；A0 在独立预审和验收通过后发布，不与 B 同日首发；
4. A1 只有在具体页面、输出、数据与收费对象完成实质预审后才立项。
