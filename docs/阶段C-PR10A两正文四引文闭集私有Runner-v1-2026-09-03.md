## 1. 范围

本 runner 把既有 PR10A current-line verifier 已固定的两份正文、四个 quote ref 暴露为一个精确的双 profile 调度闭集，而不改变既有单条 SMT runner。**每次调用只选择一个 profile、读取一份正文并核验该 profile 的两条 quote；单次 receipt 不能证明另一 profile 已执行。**

支持闭集是 `2 source profiles / 4 quote refs / 3 conceptual topics / 2 current bindings`；单次 receipt 只观察 `1 source body / 2 quote refs / 2 conceptual topics / 1 current binding`，并固定 `allSupportedProfilesVerifiedByThisReceipt=false`。四个 quote ref 不是四个 Binding，成功核验正文完整性也不产生 Binding freeze；正式计数继续为 `0/12`。

## 2. 私有输入

私有根必须在 workspace 外，且只能有两个单层普通文件：

```text
authorization.json
source-body.utf8.txt
```

CLI 不接受路径参数；私有根只从 `HAKIMI_BAZI_PR10A_PRIVATE_ROOT` 环境变量取得。authorization 的 `scope` 必须与两个固定 profile 之一逐字段、逐顺序相等，并明确绑定 source candidate digest、正文 SHA-256／byte count／code-unit count，以及两条 quote 的 candidate／rights digest、line／character locator、quote SHA-256 和长度；跨来源、漏项、增项、重复、交换顺序或任一身份漂移都会失败关闭。DTT 与 SMT 正文分别使用各自的精确 byte size 和固定 SHA-256；DTT 不再受旧单条 runner 的 128 KiB 上限阻断。

authorization 仍只是一份结构化自我声明，不证明声明人身份、归属、合法持有或法律权限。它被归类为 `private_off_repository_person_derived_input`。receipt/stdout 不保存 authorization ID、原始摘要、字节数，也不使用 authorization bytes 派生 requestId；结果明确固定 `anonymousReceipt=false / safeToPublish=false`。

## 3. 核验顺序

1. 检查私有根在 workspace 外，逐级拒绝可见 symlink／junction；
2. 预检精确两文件库存；
3. held handle 有界读取 authorization，严格 UTF-8／无重复键解析并选中唯一固定 profile；
4. 按该 profile 的精确正文长度执行 `maxBytes + 1` held-handle 读取；
5. 生产路径先核对固定正文 SHA-256，再复用现有 current-line capability 和 verifier，对同一内存正文依固定顺序核验两条 quote；
6. 要求两份 current-line process-local brand、binding／subject／source／rights tuple、正文 identity 与 quote scope 全部精确匹配；
7. 重新打开并复核 authorization、正文、目录 identity 和完整库存；
8. 只生成该单 profile 的脱敏 batch receipt；receipt 分开写明支持闭集与本次实际观察，不会写入仓库或私有根。

测试用 fixture receipt 使用独立 WeakSet 品牌，不能通过 production receipt 检查；合成正文即使长度正确也必须在生产路径的固定 SHA-256 门失败。
