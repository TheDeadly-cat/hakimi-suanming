## 4. 机械门做了什么

`scripts/bazi-v17-manifest-drift-decision-lib.mjs`：

1. 对保存 manifest 与专家候选包执行严格 UTF-8、无 BOM、无重复 JSON key、大小、工作区边界和原字节 SHA-256 检查；各自的 hash 与 parse 使用同一读取 Buffer。
2. 调用当前 manifest builder，以保存 manifest 的 `createdAt` 只读重建 expected preview，并逐组件、逐文件比较保存／当前摘要。
3. 要求正式 manifest verifier 当前精确以 `MANIFEST_MISMATCH` 失败，专家候选包 verifier 精确以 `ARTIFACT_DRIFT` 失败；若两者意外通过或换成其他失败原因，D0 账本本身失败。
4. 精确锁定 4 个组件／7 个组件－文件漂移条目（6 个唯一物理路径）和一处专家包级联漂移；新增漂移、摘要变化、owner decision、重签授权、RC 晋级或未知字段即失败关闭。
5. 若保存 manifest 被替换成当前预览，D0 不会把它静默视为完成；旧 D0 观察必须退役，并在明确授权后建立新的候选身份证据。

当前 manifest builder、正式 verifier 和直接文件观察不是一个跨文件原子事务。嵌套 verifier 会重新读取文件；Schema 13 没有可用 mutation epoch，因此 `crossFileAtomicSnapshot=false / mutationEpochReceipt=null / intervalMutationExcluded=false / abaExcluded=false`。

本门没有接入根 `prebuild/pretest/pretypecheck`，因为修改 `package.json` 会改变本次待决 `rights_bundle` 漂移本身。是否把 D0 verifier 接入正式 lifecycle，必须随 `package.json` 的所有者处置一并决定。
