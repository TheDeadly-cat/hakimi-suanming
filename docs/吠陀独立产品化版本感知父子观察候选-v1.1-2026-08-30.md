# 吠陀独立产品化版本感知父子观察候选 v1.1

日期：2026-08-30

## 结论

本轮按“优先推进其他体系”进入吠陀独立产品化，但没有改写既有父要求账，也没有把两个后置 child 投影进正式父账或中央 registry。

新增工件只解决一个机械问题：在一个版本感知、明确非原子的观察候选中，同时固定并复核：

1. 历史父要求账 v1；
2. 父账之后形成的四个固定无真人输入结构诊断拒绝 evidence；
3. 父账之后形成的高风险表达 requirements-only policy child。

它不是正式父账 v1.1，不是 supersession receipt，不是 owner decision，不是准入回执，也不是 Release Evidence。

## Current 品牌边界

三个直接上游现有公共接口均没有可消费的私有 current capability brand。因此候选记录：

- directCurrentContextCount = 3；
- upstreamCapabilityBrandCount = 0；
- 三份上下文分别完成固定 raw 身份、canonical materialization 和各自 current verifier 比对。

只有新候选自己的固定路径完整 loader 可以向其窄结果 envelope 签发模块私有 WeakSet 品牌。品牌 WeakSet、JSON parse/stringify、Reflect.apply、Reflect.ownKeys、property descriptor 与 freeze/isFrozen 原语来自独立 clean realm；clean JSON 值会被动复制回当前 realm。允许投影会先冻结，再进入可能调用 Proxy detector 的规范化路径；最终结果在签发品牌前还会与允许的全红投影完整等值复核，并用根对象与 authority 红门写入探针确认实际不可变。品牌谓词则再次被动递归确认 envelope 全图已冻结且无 accessor。这样可避免已覆盖的 ambient WeakSet、JSON.parse/stringify、Object.freeze、Reflect.ownKeys、util.types.isProxy 副作用或伪造 clean-realm freeze 向量晋级红门、漏冻嵌套红门或留下可变 envelope。以下对象均无品牌：

- builder 返回的完整候选；
- 固定路径 reader 返回的完整候选；
- 纯 object verifier 返回值；
- persisted JSON 对象；
- clone、spread、自重签对象；
- 其他 query-string 模块实例签发的结果。

该品牌只表示本次固定路径 endpoint 机械观察闭包通过，不表示返回后仍 current，不表示跨文件原子性，也不表示任何权威。它尤其不证明 loaded module bytes、Node loader 或 runtime launcher 的身份；三项 CLI 字段仍明确为 false，不能把已覆盖的具体污染回归外推为任意预加载代码执行下的运行时完整性证明。

## Mutation epoch 与观察边界

每份直接上下文和候选自身均用 held file descriptor 读取；open/read/fstat/close 使用模块初始化时捕获的 `node:fs` 静态 fd 原语，而不调用可变的 FileHandle prototype 方法。代码按已打开文件的固定尺寸直接填充私有缓冲区，并额外探测文件增长，raw hash、严格解析和 canonical materialization 检查消费同一缓冲区。读取前后还会复核普通目录链、mode 文件类型和文件 endpoint。读取路径不再调用可被导入后污染的 Buffer.prototype.subarray。

仍必须保持：

- endpointSnapshotOnly = true；
- crossFileAtomicSnapshot = false；
- parentAndChildrenAtomicSnapshot = false；
- mutationEpochAvailable = false；
- mutationEpochReceipt = null；
- intervalMutationExcluded = false；
- abaExcluded = false。

这轮没有创造不存在的 mutation epoch，也没有把三个先后 endpoint snapshot 冒充同一原子父子快照。

## 分账

这份候选只增加工程 endpoint 观察证据，不增加：

- 浏览器或真实运行时证据；
- 内容真值或命理权威；
- 来源正文、exact quote、locator 或 binding；
- 作品层、版本层、载体层许可结论；
- 现实专家身份、资质、独立性、原始意见或专家真值；
- 发布就绪、部署与回滚确认；
- 公开发布、公开部署或专家主张授权。

## 定向验证

新增测试为 23 / 23；随后全部吠陀定向测试为 550 / 550，14 个吠陀 CLI 均 exit 0。新增测试覆盖：

- fixed loader 唯一私有品牌与跨模块品牌隔离；
- 三份 direct context 的 raw/semantic identity 和 current verifier；
- candidate、父账、输入 child、高风险 child 的自重签晋级攻击；
- 0/8、0/38/open、0/2、3、3/7 与 null/null/null 精确分账；
- duplicate key、escaped duplicate key、BOM、非法 UTF-8、错误 typed array、Proxy、SharedArrayBuffer、resizable/detached buffer；
- accessor、Symbol、自定义 prototype、稀疏数组、cycle、alias、非有限数和 -0；
- hardlink、链接目录链和不安全路径；
- 同长度磁盘恶意候选与 import 后 Buffer.subarray、FileHandle.prototype.read 字节替换攻击；
- import 后 WeakSet/Reflect prototype poisoning，以及 import 前 ambient WeakSet/JSON.parse/JSON.stringify/Object.freeze/Reflect.ownKeys、util.types.isProxy 副作用和伪造 vm freeze factory 的精确向量；
- direct artifact 不变时的 ADR 与输入 execution closure 传递上游漂移；
- CLI 模块根固定路径、额外 operand、可见 NODE_OPTIONS/NODE_PATH/execArgv 拒绝，以及中性全红输出；
- CLI 明确保持 loadedModuleByteIdentityVerified、nodeLoaderIntegrityVerified、runtimeLauncherIdentityVerified 全为 false；
- apps、packages、中央 registry、旧父账和两个 child 无反向引用。

这些测试不是完整应用启动、Chrome/Edge、PWA/Service Worker、公开 HTTPS 主机、现实专家审定、来源许可结论或公开发布授权。

补充执行中央 system-admission registry 校验时，它在八字 domain manifest 与当前组件闭包不一致处提前失败；对应测试为 1 / 9 通过、8 项被同一上游八字错误遮蔽。因此不能把中央 registry 全门称为通过。本轮没有修改 registry、八字 manifest 或其失败条件；新吠陀候选仍未接入 registry。
