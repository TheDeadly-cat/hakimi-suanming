## 0. 已定产品顺序与市场边界

2026-08-01 已确定采用 **B 为主、A 也做但独立推进**：

- **B 主产品先行**：面向一个待选定的海外中文市场，保留八字排盘、专题解释与 AI 追问；发布前按该地区复核隐私、内容、支付和消费者保护规则。
- **A 辅产品独立推进**：默认先做 A0，即传统历法文化学习、生活记录与非预测性自我反思；不收集出生资料，不输出个人命盘。A1 个性历法结构只有在具体页面和输出完成实质预审后才讨论。
- 两条产品线可共用经审计的计算适配层、设计令牌和工程工具，但必须独立构建、独立部署，并隔离内容、提示词、数据、支付、分析和发布权限。
- 不做同日双首发，也不依赖 IP 或一个运行时开关把 B 临时变成 A。

当前决定见 [产品决策记录](./产品决策记录-2026-08-01.md)，证据与路线对比见 [外部验证报告](./外部验证报告-2026-08-01.md)。以下功能规划主要描述产品愿景；进入开发时按 B 与 A0 的能力清单分别实现。

## 1. 一句话产品定义

**境外候选定义：** 哈基米命理是一份会持续更新的东方人生说明书：用可靠的排盘程序生成命理结构，再由 AI 把专业术语转化为温和、可理解、可行动的个人洞察。

**大陆候选定义：** 哈基米人生地图是一款传统历法文化学习与自我反思工具：展示可核验的历法结构，解释概念来源，再用开放式问题帮助用户记录和理解自己的生活。

它不承诺预测确定未来，也不使用恐惧营销。用户最终获得的不是一句“吉或凶”，而是：

- 我当前更值得关注什么；
- 为什么我可能反复遇到某类问题；
- 面对事业、关系和生活选择时，可以怎样观察和行动；
- 哪些内容属于传统文化解释，哪些只是可能性而非事实。

## 2. 推荐定位

### 2.1 三种可选方向

| 方向 | 核心价值 | 优点 | 主要风险 |
| --- | --- | --- | --- |
| 专业命理工具 | 精确排盘、专业报告、流年大运 | 专业壁垒和付费意愿较高 | 学习门槛高，内容与算法要求高 |
| AI 自我探索陪伴 | 个性化解释、连续对话、生活复盘 | 人群更广、复访更自然 | 容易变成普通聊天机器人 |
| 娱乐社交产品 | 测试、合盘、卡片分享、趣味互动 | 易传播、获客路径多 | 留存和信任可能较弱 |

### 2.2 当前推荐

境外版采用 **“专业命理底座 + AI 自我探索陪伴 + 轻量分享”**：

- 专业底座负责可信度；
- AI 解释和长期记忆负责体验与留存；
- 分享卡片与合盘负责传播；
- 不把娱乐玩法放在产品核心。

大陆候选版采用 **“历法文化知识 + 非预测性反思工具 + 个人记录”**，不以吉凶、运势预测、改命转运或付费命书为实际卖点。即便这样也不能预设一定能够审核通过。

### 2.3 品牌调性

- 现代东方，而不是老派“金龙、罗盘、神秘大师”视觉；
- 温暖但不幼稚，专业但不居高临下；
- 可以保留“哈基米”的亲近感，用一只陪伴型角色引导用户；大陆候选版不建议继续使用“算命”作为正式产品名；
- 语言多使用“倾向、可能、值得观察”，少使用“注定、必然、绝对”。

## 3. 目标用户与使用场景

### 3.1 第一目标用户

品牌关注人群为 **15～35 岁、正处于关系或职业选择期、对东方文化与自我探索感兴趣，但看不懂传统命盘的中文用户。** 完整个性化 B 产品首版只面向 18～35 岁；15～17 岁只进入不收集出生资料、无个人预测、无付费和无长期记忆的文化学习模式。

### 3.2 用户真正想完成的任务

1. 认识自己：希望得到一份有结构的性格与能力说明。
2. 理解阶段：想知道为什么最近工作、关系或情绪反复出现某种模式。
3. 辅助思考：面对选择时需要新的观察角度，而不是替自己做决定。
4. 获得陪伴：希望系统记得背景，后续交流不必每次从头开始。
5. 分享连接：希望和伴侣、朋友讨论关系差异，但不被简单贴标签。

## 4. 首版命理范围

### 4.1 推荐先做八字

首版只建立一个核心引擎，建议采用八字，原因是：

- 出生信息输入相对清晰；
- 能形成稳定的结构化排盘结果；
- 性格、关系、事业和阶段主题都可以从同一基础数据展开；
- 后期可自然扩展大运、流年、合盘和专题报告。

这里的“先做八字”只代表领域引擎优先级：境外版可用于个性化解释；大陆候选版是否展示八字、流年或合盘，以及如何展示，必须以预审结果为准，不能因为计算是确定性的就推定内容合规。

### 4.2 首版明确不做

- 不同时开发八字、紫微、塔罗、星座和周易占卜；
- 不提供“彩票号码、股票涨跌、疾病诊断、寿命、灾祸”等结论；
- 不开放真人“大师入驻”市场；
- 不生成无依据的化解商品或付费消灾方案；
- 不把 AI 自由生成的内容当作排盘结果。

## 5. 核心产品闭环

```text
低门槛建档
  → 获得第一份个人说明书
  → 针对一个现实问题继续提问
  → 收到可保存、可回顾的阶段洞察
  → 每日/每周回来记录与复盘
  → 解锁更深入的专题报告或关系功能
```

这个闭环比“进入首页看一句今日运势然后离开”更有长期价值。

## 6. MVP 功能范围

### 6.1 必须有

下表是境外命理解读版的 MVP。大陆候选版需要将“初始报告、AI 深度提问、报告收藏”等改造成历法知识、开放式反思和个人记录，不保留预测性结论与付费命书。

| 模块 | 首版能力 | 验收重点 |
| --- | --- | --- |
| 账号与访客体验 | 游客先体验，保存时再登录 | 不让注册阻断第一次价值体验 |
| 出生档案 | 公历/农历、日期、时间、地点、时区、性别或可选表达 | 对未知出生时辰提供明确降级方案 |
| 确定性排盘 | 四柱、十神、五行等结构化结果 | 相同输入始终得到相同结果，并有测试样例 |
| 初始报告 | 核心特质、优势、挑战、关系、事业、当前主题 | 先给摘要，再逐层展开，避免信息轰炸 |
| AI 深度提问 | 基于命盘与当前报告进行连续对话 | AI 不重新计算命盘，不替用户作重大决定 |
| 报告收藏 | 保存、查看历史、继续追问 | 网页与手机数据同步 |
| 安全与隐私 | 同意、导出、删除、风险问题处理 | 用户能够删除出生档案和历史记录 |

### 6.2 应该有，但可排在第二个迭代

- 每日或每周主题；
- 年度主题报告；
- 单张结果卡片分享；
- 消息提醒；
- 第二份人物档案；
- 双人关系观察或合盘。

### 6.3 暂不进入 MVP

- 社区广场；
- 实时语音或数字人；
- 多流派自由混算；
- 命理师交易平台；
- 复杂积分、抽卡和虚拟币体系。

## 7. 页面与导航

### 7.1 手机端底部导航

1. **今日**：阶段主题、继续上次对话、最近报告。
2. **命盘**：命盘概览、五行结构、人生主题。
3. **问哈基米**：带上下文的 AI 对话。
4. **报告**：基础、年度、事业、感情等专题。
5. **我的**：档案、订阅、隐私、数据管理。

### 7.2 网页端

网页端保留相同信息架构，改为左侧导航与更宽的报告阅读区，不单独设计另一套产品逻辑。

### 7.3 第一次体验流程

1. 落地页用一句话解释价值；
2. 输入出生信息，并解释每项信息为什么需要；
3. 显示排盘过程和信息准确度提示；
4. 先展示 3 条最有辨识度的洞察；
5. 用户选择“最想了解：自己 / 感情 / 事业 / 最近状态”；
6. 生成对应的首份报告；
7. 再邀请登录保存，不在开头强制注册。

## 8. 命理与 AI 系统架构

### 8.1 分层原则

```text
出生信息
  ↓
历法与时区标准化
  ↓
确定性排盘引擎
  ↓
结构化命盘 JSON
  ↓
命理规则与经审核的知识库
  ↓
内容编排器（选择证据、主题、语气和安全边界）
  ↓
大语言模型负责自然语言解释与对话
  ↓
事实校验、安全过滤和展示
```

### 8.2 强制边界

- 大语言模型不能自己推算四柱、节气或大运；
- 每段关键解释应能追溯到结构化命盘证据和采用的解释规则；
- 模型不知道或流派有分歧时必须明确说明；
- 用户问题涉及医疗、法律、金融、自伤等高风险领域时，切换到安全回应；
- 对话记忆只保存产品需要的信息，用户可查看和删除。

### 8.3 出生时间不确定

首版不伪装精确：

- 用户可以选择“不知道具体时辰”；
- 系统只展示不依赖时柱的内容，并标记准确度范围；
- 后期再考虑“时辰校正”，且必须解释其不确定性。

### 8.4 A/B 能力隔离

以上“出生信息 → 排盘 → 规则 → AI”的完整链路只部署在 B。A0 只允许“日期/节气等安全历法字段 → 有出处的文化内容 → 用户自述复盘”，不接收出生年月时地，也不能导入 B 的命盘、提示词、报告或支付包。工程边界详见 [双产品技术架构](./双产品技术架构-v0.1.md)。

## 9. 跨端技术路线（暂定）

### 9.1 推荐演进路径

**第一阶段：响应式 Web + PWA；第二阶段：按真实需求封装或开发原生客户端。**

外部验证支持这条路线，但原因不仅是成本：Apple 将 fortune telling 列为高度饱和类别并要求新 App 有显著差异；微信和部分大陆 Android 商店还存在内容审核风险。技术能打包成 App 或小程序，不等于渠道会接受实际功能。因此先用 Web/PWA 验证价值，再把渠道审核作为独立发布门。

建议组合：

- 前端：Next.js + TypeScript；
- 样式：Tailwind CSS + 自有设计令牌；
- 移动通用组件：优先评估 Ant Design Mobile，使用原创主题；命盘矩阵自行开发；
- 后端：每个产品使用独立 TypeScript API 或 FastAPI 服务；
- 数据库：每个产品使用独立 PostgreSQL 实例/项目、存储与备份；
- AI：模型无关的 Provider Adapter，不锁死单一供应商；
- 排盘：独立、可测试、无 AI 依赖的领域模块；
- 部署：网页与 API 分层部署，测试和生产环境隔离。

### 9.2 何时再做手机原生能力

只有在以下需求得到验证后再决定：

- 必须进入 iOS/Android 应用商店；
- 推送通知是留存关键；
- 需要应用内支付、原生分享或设备能力；
- PWA 的平台限制真实影响用户，而不是预想问题。

可选演进方案包括 Capacitor 封装、React Native/Expo 客户端，或为微信生态单独开发小程序适配层。最终选择需结合首发市场和团队能力。

当前默认采用 Capacitor 作为验证后的原生封装候选；只有在原生体验成为核心竞争力时才考虑 Expo。Flutter 不适合首版这种文字和报告密集的 Web 产品；uni-app 只在小程序内容与支付审核已经确认可行时采用。

## 10. 数据模型草案

以下首先描述 B 的数据模型；A0 使用独立账户租户，只保留文化内容进度、用户原始记录、同意、导出和删除所需的数据，不包含 `BirthProfile`、`Chart` 或命理 `Interpretation`。

- `User`：账号、地区、语言、同意状态；
- `BirthProfile`：出生资料、标准化时区、精度等级；
- `Chart`：排盘版本、结构化结果、校验哈希；
- `Interpretation`：规则版本、引用证据、生成内容；
- `Conversation`：用户问题、采用的命盘上下文、安全分类；
- `Report`：报告类型、版本、状态、购买授权；
- `ConsentRecord`：隐私同意、营销同意、撤回记录；
- `Entitlement`：会员或单次内容权益。

原则：原始出生资料、派生命盘、AI 对话和支付权益分别管理，不把所有信息塞进一个用户表。

## 11. 商业模式假设

商业化必须按地区拆分。下列“报告 + 会员”组合只适用于已确认允许提供该内容的市场；在中国大陆，不能把付费预测、运势、命书或占卜作为默认商业模式，任何收费对象都应在内容实质预审后确定。

### 11.1 推荐组合

**境外候选版：**

- 免费：基础命盘、有限的首份解释、少量追问；
- 单次购买：年度、关系、事业等专题报告；
- 短周期权益：例如限定时间的追问权限，用于验证持续价值；
- 会员：持续 AI 对话、周期报告、多个档案和历史回顾；
- 真人服务：只有在产品与合规成熟后再评估。

**大陆候选版：**

- 可能收费的对象只能围绕经审核的文化课程、阅读、记录和非预测性复盘工具；
- 不用“免费测出问题，付费看命运答案”的漏斗；
- 是否能够收费、需要哪些许可，必须在原型阶段专项确认。

### 11.2 不建议

- 首版依赖广告；
- 用危机或灾祸制造付费压力；
- 每个自然段都设置付费墙；
- 复杂的积分、代币和抽卡体系；
- 未验证价值就推出高价年费。

### 11.3 需要验证的价格问题

首版不直接拍脑袋定价，应通过访谈和小范围实验验证：

- 用户更愿意为“完整报告”还是“长期陪伴”付费？
- 首次付费发生在什么时刻？
- 报告是否真正提供了免费 AI 聊天无法替代的价值？

## 12. 核心指标

### 12.1 北极星指标候选

**每周完成一次“有保存或后续追问的有效洞察”的用户数。**

它同时要求结果对用户有意义，并产生后续行为，比单纯消息数或页面浏览量更健康。

### 12.2 MVP 观察指标

- 出生信息填写完成率；
- 首份报告读完率；
- 首份报告后继续追问率；
- 7 日内再次访问率；
- 保存或分享率；
- 用户主动标记“符合 / 不符合 / 有启发”的比例；
- AI 内容投诉率和高风险拦截准确性；
- 从免费体验到首笔付费的转化路径。

## 13. 安全、隐私与内容原则

- 大陆版不以算命、占卜、运势预测、改命转运为实际核心；免责声明不能替代实质调整；
- 明确说明产品属于传统文化与自我探索，不替代专业建议；
- 不预测死亡、重病、灾祸、犯罪结果或投资收益；
- 不对用户贴不可改变的负面标签；
- 不鼓励因命理结论立刻辞职、分手、投资或停止治疗；
- 完整个性化 B 产品首版为 18+；15～17 岁文化模式不收集出生时间、地点、关系档案，不开放个人命盘、自由对话、长期记忆、付费或个性化营销；
- 出生日期、时间、地点一旦与账号关联即按高敏感度产品数据保护；
- 实行最少收集、传输加密、权限隔离、删除与导出机制；
- 排盘尽量本地或由独立服务完成，模型只接收去身份化结构化结果；
- AI 内容在界面、分享图和导出报告中保留适用的显式及隐式标识；
- 上线国家或地区的生成式 AI、隐私、内容、广告、支付和消费者保护要求需经专业人士复核。

## 14. 分阶段路线图

### 阶段 -1：双产品可行性门

- 为 B 选择一个首个海外发布地区，并确定主体、支付、隐私与内容边界；
- 为 A 确认默认 A0 能力清单；如坚持 A1，先完成具体页面、输出和收费对象的实质预审；
- 确定两套产品的名称、域名、数据区、分析项目与发布权限；
- 制作首页、建档、结果、AI 对话和收费页的低保真样稿；
- 为 B 与 A0 分别准备 20 条允许输出、20 条拒绝输出和三套营销文案；
- A 路线由执业律师和属地主管部门做实质预审；B 路线按首个目标地区完成内容、隐私、支付和商店规则复核。

**通过标准：** 不是“没有发现问题”，而是对内容、模型、数据、备案、支付和渠道分别取得足够明确的可行结论。

### 阶段 0：方向验证

- 访谈 10～15 名 18～35 岁 B 目标用户；如验证青少年文化模式，另组 15～17 岁及监护人研究，不混入个性化命理测试；
- 测试三种产品定位和语言风格；
- 用可点击原型验证出生信息到首份报告的流程；
- 由命理顾问确认流派、规则范围和争议点；
- 明确 B 首个海外地区与支付方式，并确认 A0 是否作为第二条发布路线。

**通过标准：** 用户能复述产品价值，首份报告有明显辨识度，并愿意继续问一个真实问题。

### 阶段 1：B 可用 MVP

- 响应式网页与 PWA；
- 出生档案和确定性排盘；
- 基础报告；
- AI 连续追问；
- 保存、删除和基础后台；
- 埋点、质量评估和安全策略。

**通过标准：** 核心流程稳定，排盘测试通过，用户能够跨设备继续查看，内容错误可追踪。

### 阶段 2：留存与付费验证

- 周期主题和回访提醒；
- 专题报告；
- 会员或单次购买实验；
- 分享卡片；

### 阶段 3：扩展平台与内容

- 评估紫微、塔罗等独立能力包；

## 15. 在写完整产品前仍需拍板的决策

1. **B 首个海外地区在哪里？** 香港、台湾、新加坡、北美华人或其他；这决定主体、支付、隐私和营销规则。
2. **A 是否接受默认 A0？** 如果坚持 A1，先安排具体方案的律师与属地实质预审。
3. **首个付费主题是什么？** 关系专题还是事业专题；首版不同时做满所有报告。
4. **八字采用哪套具体规则？** 需要确定年/月/日/时柱、大运、真太阳时等争议点及负责金标准的顾问。
5. **正式名称与品牌角色是什么？** “哈基米”是否采用原创猫形陪伴角色，A/B 是否使用不同副标题。
6. **账号与 AI 供应商如何选择？** 需要在目标地区、隐私边界和成本已知后决定。
7. **谁为命理内容负责？** 需要明确规则来源、顾问、审核和版本管理机制。

## 16. 推荐的第一轮讨论顺序

下一轮建议只回答下面四个问题，不需要一次决定全部细节：

1. B 首个海外地区优先做：**香港、台湾、新加坡，还是北美华人？**
2. B 第一份可付费专题先验证：**关系**还是**事业**？
3. A 是否接受先做 **A0 文化与生活志版**，A1 个性历法结构等预审后再讨论？
4. “哈基米”要不要成为一只低频出现的原创猫形伙伴，还是只保留名称、不做角色？

这四个答案确定后，就能进入品牌命名、五页原型和计算适配层技术样机。

## 17. 当前暂定结论

- 产品顺序：B 海外中文命理解读版先行验证，A0 中国大陆文化自我探索版独立推进、不同日首发；
- 目标用户：品牌 15～35 岁；完整个性化产品首版为 18～35 岁，15～17 岁仅文化学习模式；
- 核心：八字；首版不同时加入其他术数；
- 定位：B 为专业底座 + AI 陪伴 + 轻量分享；A0 为历法文化学习 + 非预测性自我反思；
- 首发平台：中文、手机优先的响应式 Web/PWA；
- 技术：确定性排盘模块、规则证据层与 AI 表达严格分层；
- 商业化候选：B 免费基础体验 + 单次专题报告，会员待留存成立后验证；A 收费模式待实质预审；
- 底线：不确定性透明、隐私优先、拒绝恐惧营销和竞品换皮。

以上是当前实施基线；未列明的地区、规则、品牌和收费细节仍可继续讨论。
