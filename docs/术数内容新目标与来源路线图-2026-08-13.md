# 术数内容新目标与来源路线图

> 日期：2026-08-13
>
> 适用范围：八字主 Web、隔离紫微 4218、隔离西洋 4219
>
> 目标：让排盘后的内容更直接、更有上下文、更容易由用户／专家纠正，同时不把竞品文案、古籍定位或工程摘要冒充真值

## 1. 用户目标的产品化表达

用户希望的不是“再多放一些百科文字”，而是排盘后立即回答：

1. **盘里实际有什么**：十神、神煞、星曜、宫位、相位和组合事实；
2. **它具体落在哪里**：年／月／日／时柱，本宫／对宫／两组三合，天体的星座／宫位／相位；
3. **在这个位置关注什么**：直接说主题、可用端、受阻端和矛盾；
4. **什么条件会改变结论**：身强身弱、同柱关系、三方四正、四化、宫主星、定位星链、其他相位；
5. **当前能不能下结论**：事实、候选、已审、未审、冲突或不可判断必须分开。

“直言不讳”在本项目中的标准是：**不使用空泛套话，但必须把依据、成立条件、反例和未知项一起直说**；它不等于“注定”“一定发财”“必有疾病”等无法负责的确定事件。

## 2. 统一内容模型

三体系以后都按相同的四层输出，不强行混用规则：

| 层 | 用户看到什么 | 工程要求 |
| --- | --- | --- |
| 事实层 | 位置、关系、亮度／角距／orb、命中规则 | 来自当前已验真盘面；不可由内容文案反推或补猜 |
| 直读候选 | “这个位置主要观察什么” | 来源绑定、自写短文、禁止复制竞品长文；结果字段为空 |
| 条件合参 | 资源端、压力端、相互牵制、反例 | 保留冲突，不按项目数量直接加权，不跨体系推导 |
| 审稿状态 | 未审、批准、退修、拒绝及审稿归属 | 绑定当前快照；无签名／身份核验时不得自动激活 |

每条可显示主张以后统一登记：

`claimId / claimType / sourceType / exactLocator / traditionScope / factInputs / applicabilityConditions / counterexamples / prohibitedOutcomeClaims / reviewStatus / expertTruthClaimed / scientificValidityClaimed`。

详见 `八字内容-v0.17-旺衰政策单一事实源与当前盘命中复核包-2026-08-13.md`。

### P1：八字 v0.18——来源—主张账与旺衰证据叙事层（已定向收口）

当前源码已经形成独立 claim registry、逐项证据叙事、Web 只读账本，并把其摘要绑定进 v0.18 当前盘复核协议。本轮新执行 v0.18 定向 Vitest **4 files / 27 tests PASS**、默认身份定向 **3 files / 23 tests PASS**、根 typecheck、草案隔离 verifier、**2058 modules** E2E build，以及 Edge + Chrome **2/2 PASS**；没有借用 v0.17 数字。

已形成的最小范围：

1. 把当前盘旺衰判断展开为月令、四柱透干、四柱首位藏干、其余藏干的逐项证据账；
2. 显示每项的五行关系、权重、支持／消耗方向和月主气重复计权影响；
3. 为每句叙事绑定 `claimId`、流派、来源 locator、条件与反例；
4. 只生成“为什么当前候选落入本档、哪些输入会令它跨档”的说明；
5. 与 v0.17 当前盘包共用快照绑定，但不自动采用审稿结果；
6. 未知时辰只用三柱，所有时柱相关事实明确 withheld。

通过线已在本轮定向范围内关闭：同一事实与政策确定性；跨阈值边界可复演；来源／主张错配失败关闭；用户可定位每句话来自哪条事实；完整浏览器存储前后相等；跨 Revision 失效关闭；无个人吉凶和事件结果。应用内 Browser 在最新壳桌面与 390×844 显示 12 claims / 12 unique bindings、月主气 `4 + 2 = 6`，四个共享 SHA 一致，overflow／overlay／console warning-error 均为 0；E2E build 为 `bc2c28f15407`，默认身份仍是 legacy-v13/schema13。完整证据、截图摘要和版权边界见 `八字内容-v0.18-来源主张账与旺衰证据叙事-2026-08-13.md`。

### P2：紫微 v0.13——核心十二辅煞 × 三方四正 occurrence 动态审稿包（定向工程门已收口）

建议合同：`ziwei.core_minor_star.sanfang_occurrence_review/0.1`。

每条真实 occurrence 只绑定：

- 精确星键、标签与 Hakimi 事实类别；
- `self / opposite(+6) / trine(+4) / trine(-4)`；
- 宫位、地支、实际亮度与本命生年四化；
- 基础候选 ID、落宫候选 ID；
- 当前规则快照、事实快照、有序 occurrence 与来源摘要；
- “天空／地空”等命名冲突状态。

禁止按六吉／六煞、星数、亮度或四化加总；不借对宫补空宫；禄存、天马、天空、其他 minor 与全部 auxiliary 仍只显示事实、候选为 `null`。`orientation / eventOutcome / result` 继续为空。

当前源码把范围收紧为一份 `current_chart_all_twelve_sanfang_groups` 整盘包：12 个目标组；标准盘十二个核心事实各进入四组，共 48 occurrence。固定顺序为 `self → opposite(+6) → trine(+4) → trine(-4)`。五来源只复用既有核心星曜 2、宫位 2 与三方几何 1，没有新增星义语义来源；切宫只过滤显示，编辑、重算、重开或失败会使旧包失效。模板排除直接身份与原始输入，但派生四宫／星曜／亮度／四化仍属敏感事实，SHA-256 不是加密。v0.13 与旧静态反馈面板隔离，formal／scoring／outcome 均保持 `false / null`。本轮定向 Vitest **2 files / 30 tests**、三个 typecheck、隔离边界、默认身份 **3 files / 18 tests**、4218 build **108 modules transformed**、应用内 Browser 和 Edge／Chrome 独立场景 **2/2** 均通过；完整存储快照、390px 响应式及两浏览器同字节截图已核对。详细证据与未扩大的长门边界见 `紫微内容-v0.13-核心十二辅煞三方四正命中复核包与证据-2026-08-14.md`。

### P3：西洋 v0.8——七传统星体本质尊贵 occurrence 事实包

建议合同：`western.essential_dignity_occurrence_review/0.1`。

首版只做：

- 七颗传统可见星体；
- 热带黄道；恒星黄道请求明确 unsupported；
- 入庙、擢升、失势、落陷四种星座级 occurrence；
- 天体、精确经度、星座、黄道模式、来源表版本、表摘要、当前盘事实摘要和有序 occurrence 摘要绑定；
- 传统／现代守护星表不混合；
- 不做尊贵点数、强弱排名、互容、吉凶或事件。

三分、界、面要等专家选择昼夜规则、三分主体系和 Ptolemaic／Egyptian terms；角宫、顺逆、速度、日光关系属于偶然尊贵，应另立后续事实层，不能混成一个“星体强弱分”。本目标也不要求把 Astronomy Engine 换成 Swiss Ephemeris。

### P4：条件化内容版本（依赖现实审稿）

只有 P1～P3 的来源账和反馈包稳定后，才逐批推进：

- 八字：十神 × 柱位 × 当前旺衰条件；神煞 × 柱位 × 同柱十神，但不让旺衰直接决定神煞吉凶；
- 紫微：主星／核心辅煞 × 宫位 × 三方四正 × 本命四化；
- 西洋：天体 × 星座 × 宫位 × 主要相位 × 本质／偶然状态。

每一批都必须由用户或专家给出流派、成立条件、反例和具体退修意见；“全部 approve”本身仍不构成正式发布授权。
