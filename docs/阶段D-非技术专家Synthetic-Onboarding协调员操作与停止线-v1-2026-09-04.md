# 阶段 D：非技术专家 Synthetic Onboarding 协调员操作与停止线 v1

日期：2026-09-04  
适用对象：负责准备设备、启动本机流程、逐字代录和保管合成回件的协调员  
当前状态：`synthetic_onboarding_only`；`physicalExpertSurfaceReady=false`

## 先读结论

这份 runbook 只用于**固定合成材料的流程演练**，不是现实专家正式审定规程，也不是处理真实私密材料的授权。

当前账面必须保持：

- 现实专家：`0/2`；
- 正式冻结 Binding：`0/12`；
- `expertClaimsAuthorized=false`；
- `publicDeploymentAuthorized=false`；
- 发布治理：`legacy-v13 / targetSchema 13 / migrationId null`。

完成一次、两次或多次 synthetic onboarding，都不得增加 `0/2` 或 `0/12`，也不得据此宣称内容正确、专家认可、来源有权使用、产品已经发布就绪或可以公开发布。

当前已实现一个来源侧 single-seat clean-profile **启动候选**，并以实际安装的 Chrome／Edge 各观察过一次新建临时 profile 参数、进程启动和本次关闭清理；但它没有证明浏览器真正采用该 profile，也没有排除外网、扩展／企业策略影响或整个进程树残留。输出目录／文件 ACL、两文件原子提交、目录持久化和失败残留清理同样尚未建立。因此：

> 当前只允许工程人员或内部测试人员使用合成材料继续硬化。不得把现有 candidate 直接交给现实专家，不得输入或处理真人姓名、联系方式、出生资料、真实案例、专家身份／资质材料或真实专家意见。

本文件是未来 onboarding 的操作底稿；它本身不解除上述停止线。

## 1. 三本账必须分开

| 账 | 本流程可以留下什么 | 本流程不能证明什么 |
| --- | --- | --- |
| 工程与浏览器账 | 候选包身份检查、页面能否打开、逐字回显、回件字节和机械校验结果 | 内容正确、专家真实、专家独立、来源许可、法律结论 |
| Synthetic onboarding 账 | 使用固定练习题完成一次不计数的流程观察 | 正式专家意见、正式 Binding 通过、人与软件谁更准确 |
| 正式审定账 | 当前无新增，仍为 `0/2`、`0/12` | 不得把 rehearsal、测试或演示迁入正式计数 |

准确度研究是第四本独立的研究账，不属于本 runbook。不得在本表单中记录“专家比 AI 准”“AI 比专家准”、命中率或真人案例结果。

## 2. 人员职责

### 协调员负责

- 在专家接触设备前完成候选包、席位和本机页面的机械检查；
- 始终只让当前人员看到 A 或 B 中一个席位；
- 专家选择口述时逐字录入，不概括、不润色、不替换术语、不替专家选答案；
- 发现风险后立即停止，不绕过页面、不手工改 JSON、不手工拼回件；
- 保存合成回件和 sidecar 后只记录机械结果，不评价专家意见输赢；
- 完成一个席位后关闭该席本机服务，再处理另一席。

### 专家／试填者负责

- 只评价题面中的一条固定练习规则；
- 给出结论、理由、成立条件、反例／所需证据、面向用户的风险处理和修改建议；
- 如实选择作答时使用过的书籍、他人、聊天机器人、排盘软件或其他软件协助类别；
- 亲自通读全部回显，或逐项听取协调员读回后确认。

### 协调员不得负责

- 不得替专家生成、补全或“优化”专业意见；
- 不得向 B 泄露 A 的选择、理由、进度或表达方式，反之亦然；
- 不得把 hash 当成数字签名、本人认证、可信时间、同意记录或保管链；
- 不得以测试通过代替专家真值、内容真值、权利法律判断或发布授权。

## 3. 会前硬检查

任一项不能明确回答“是”，本次不启动。

- [ ] 会话明确标记为 `SYNTHETIC ONBOARDING / 不计入正式审定`。
- [ ] 题面、示例和材料均为固定合成内容，不含真实出生资料、真实案例或可识别个人信息。
- [ ] 本次不采集姓名、电话、微信、电子邮箱、机构、证件、资质文件或签名。
- [ ] A、B 为不同席位；两个 session nonce 不同；不会把整个 pair root 交给任一试填者。
- [ ] P、PM 和所选席位 S 的预期 pin 由协调端独立持有，cycle、pair、seat 与 nonce 已冻结。
- [ ] 当前席位由来源侧 verified-memory 流程核验并启动，不从候选包内运行 `START` 文件，也不执行候选包自己的 JavaScript。
- [ ] 页面只通过本机随机 loopback 地址打开，且显示固定练习题和“不填写真人资料”的提醒。
- [ ] 计划写入的目录是一个全新的仓库外、pair root 外目录；本次只保存合成内容。
- [ ] A、B 时间或空间隔离，双方不会旁听、看屏、看回件或交流答案。
- [ ] 已告诉试填者：可以不同意、可以写“无法判断”、可以随时停止；不以完成或同意作为报酬条件。

注意：即使上述清单全部勾选，当前 `physicalExpertSurfaceReady=false` 仍不改变。此清单不能替代尚未完成的隔离浏览器、ACL、隐私、同意和真人分发准入。

## 4. 冻结本次 mutation epoch

启动前，在协调侧冻结并记录：

- review cycle；
- pair run；
- A/B 席位与各自 session nonce；
- P、PM、SA、SB；
- 固定题面、示例、材料和缺失材料；
- 当前代码／候选包版本；
- 输出位置仅用于本次 synthetic 回件。

冻结后，题面、材料、问题、席位、pin、页面源码或运行边界只要发生变化，就立即结束当前 epoch。不得覆盖旧包、旧回件或旧记录来“继续同一次”；必须重新生成新的 cycle／pair／seat 身份并从会前检查重新开始。

## 5. 单席逐步操作

以下步骤先完整执行 A，再关闭 A 的服务；之后以独立条件对 B 重复。不得同时把 A、B 页面开放给同一人或同一浏览器会话。

### 步骤 1：协调端准备

1. 在试填者看不到技术信息的情况下选择本席。
2. 由来源侧代码核对 P、PM、所选 S、cycle、pair、seat、nonce、精确文件清单和实体字节。
3. 只在核验成功后启动随机本机地址的内存服务。
4. 协调员先核对页面标题、固定练习提醒和当前席位；不得把对面席位、协调页、pair root 或技术 pin 展示给试填者。

如果页面阻断、显示意外内容、出现另一席信息、地址不是预期本机随机地址，或任何机械核验失败：**不要刷新、不要换参数重试、不要自行修文件；关闭页面并执行第 8 节停止流程。**

### 步骤 2：交给试填者

协调员只说清四件事：

1. 这是固定练习题，不是真人命盘；
2. 不得输入姓名、联系方式、出生资料或真人案例；
3. 可以本人输入，也可以口述后由协调员逐字代录；
4. 任何时候不确定或不舒服，都可以停止并把设备交回。

不要解释“项目希望得到什么结论”，不要提示 A/B 另一方的答案，也不要劝专家选择同意。

### 步骤 3：本人输入或逐字代录

- 本人输入：协调员不碰答案区，不在旁边评价或改写。
- 口述代录：先选择“专家口述、协调员逐字代录”；协调员只输入听到的原话。
- 听不清、存在歧义或需要换词时，停下来请专家重复；不得猜测。
- 专家想修改时，由专家明确指出修改位置和新原话。
- 协调员必须勾选“逐字录入、未摘要”声明；做不到就停止，不得提交。

### 步骤 4：披露软件与其他协助

请试填者如实选择实际使用的协助类别，包括书籍、他人、聊天机器人、排盘软件或其他软件工具。

- 只记录类别，不记录账号、人名、聊天原文、prompt、知识库正文或第三方后台内容。
- “未使用”以及“不确定／不披露”不得与其他类别同时选择。
- 披露只是试填者自述，不代表系统已经证明实际使用或未使用。
- 使用软件不会自动使意见无效；隐瞒、强迫披露细节或由协调员代选都不允许。

### 步骤 5：隐私复核

在生成逐字核对稿前，协调员只检查“是否含禁入信息”，不判断专业答案对错。

若看到或听到姓名、联系方式、出生时间／地点、住址、证件、机构身份、真实案例细节、真实专家资质或受保护材料正文，立即停止。不要把禁入内容复制到聊天、截图、笔记或另一个文件，也不要承诺已经安全删除。

### 步骤 6：逐字读回

1. 生成逐字核对稿。
2. 专家亲自通读全部文字；如需代读，协调员逐项原样读出。
3. 专家确认文字准确表达本人意见。
4. 任一实质字段发生修改后，旧核对立即失效；必须重新生成并完整读回。
5. 只有全部最终确认均由专家明确确认后，才允许完成本席。

### 步骤 7：完成本席并交回设备

1. 专家点击完成后，不截图、不复制、不继续操作，把设备交回协调员。
2. 如果页面提示第一次确认未返回，只允许使用页面提供的“重试完成本席”，提交同一份精确内容。
3. 不得刷新后重填，不得修改答案再冒充同一次重试，也不得绕过页面直接发请求。
4. 页面显示本席完成，只证明本机流程接收了一个 synthetic 回件；不证明文件已经安全保存。

### 步骤 8：协调端收尾

1. 立即从试填者处收回设备，避免其看到技术摘要或下一席信息。
2. 关闭当前席位的本机服务，并确认关闭成功。
3. 仅对合成回件，调用来源侧外部写入能力；再次提供该完整回件的 raw SHA-256 pin。
4. 写入一个全新的仓库外、pair root 外目录；成功目录应只有完整回件和 `.sha256.txt` 两个文件。
5. 核对回执中的文件名、字节长度和 raw SHA-256；不要把摘要称为签名、身份认证或可信时间。
6. A 的全部收尾成功后，才以独立席位启动 B；对 B 重做会前硬检查。

当前输出 ACL 未获证明，因此上述写入步骤只允许合成内容。不得据此推断未来真人回件是私有或安全的。

## 6. A/B 独立与并列规则

- A 作答时不得看 B 的页面、进度或意见；B 同理。
- 两席不得共同讨论后再分别填写；一旦交流答案，本 pair 的独立性即失效。
- 只有两份原始回件分别封存后，协调员才能进行逐字段并列。
- 相同只记为一致；不同固定保持 `unresolved`，并按流派、输入、底本、解释、工程问题、高风险表达或无法判断分类。
- 分歧不得多数表决、求平均、拼成折中稿，也不得让生成模型或其他软件自动选择赢家。
- 需要补材料时，保留原始意见，另开新的追问或 mutation epoch；不得覆盖原话。

## 7. 可以记录与禁止记录的会后结论

### 可以记录

- “某次固定合成练习是否走完指定页面步骤”；
- “A/B 是否保持席位隔离”；
- “是否使用本人输入或逐字代录”；
- “是否完成逐字读回和协助类别自述”；
- “机械回件及其 sidecar 是否通过当前校验”。

### 禁止记录为结论

- “专家已经正式认可该规则”；
- “两位现实专家审定完成”或把计数改为 `1/2`、`2/2`；
- “某条 Binding 已冻结”或把计数改为 `1/12`；
- “专家／AI 更准”“命理准确度得到证明”；
- “来源可靠且可以再分发”“许可或法律问题已解决”；
- “已达到发布就绪”或“已经获得公开发布授权”；
- “八字演练证明紫微、西洋或吠陀体系也成立”。

## 8. 立即停止线

出现下列任一情况，立即停止当前席位；涉及席位独立性、冻结输入或 pair 身份时，整个 pair 作废并重新开新 epoch。

| 触发情况 | 立即动作 | 不得做的事 |
| --- | --- | --- |
| 发现或即将输入任何真人身份、联系方式、出生资料、地址、资质或真实案例 | 停止输入和提交，收回设备，仅记录“不合规内容出现”而不抄录正文 | 不截图、不复制、不写回件、不声称已安全删除 |
| 题面或来源出现真实／受保护正文 | 停止本次，交给来源与权利治理另行处理 | 不继续审、不把链接可访问等同于可复制或可再分发 |
| A/B 看见、听见或讨论了对方意见 | 停止整个 pair，标记独立性失效 | 不通过换名字或补声明修复，不投票决定保留谁 |
| P、PM、S、cycle、pair、seat、nonce、文件身份或内容校验失败 | 关闭页面与服务，保留错误码，工程侧排查后开新 epoch | 不改 manifest、不跳过校验、不从包内直启 |
| 页面显示另一席、技术控件、意外正文，或地址不是预期本机随机地址 | 立即收回设备并关闭页面 | 不刷新碰运气，不继续填写 |
| 协调员无法保证逐字代录，专家没有完成读回，或修改后未重新读回 | 不提交；回到相应步骤，无法纠正则终止本席 | 不替专家确认、不用摘要代替原话 |
| 专家拒绝、无法或不愿披露协助类别 | 允许选择“不确定／不披露”；若本人不愿继续则停止 | 不逼问账号、prompt、聊天内容或第三方后台 |
| 提交错误不能由页面内同内容重试恢复 | 收回设备，停止本席并保留无正文的错误状态 | 不手工重发、不重新拼装、不把失败称为已接收 |
| 外部目录不新、位于仓库／pair root 内、被重定向，或写入／校验失败 | 停止保存，隔离可能的部分输出并登记技术事件 | 不覆盖旧文件、不手工凑齐第二个文件、不称为保存成功 |
| 出现 `HANDLE_CLOSE_FAILED`、`SERVER_CLOSE_FAILED`、`SERVER_RUNTIME_ERROR_OBSERVED` 或 cleanup 无法确认 | 停止当前 pair，保持 fail-closed，交工程侧处理 | 不释放／复用不明 capability，不启动下一席 |
| 任何未列出的异常或协调员无法确认当前状态 | 默认停止并标记 `defer` | 不凭经验继续，不把“看起来正常”当作证据 |

失败后不得为了“凑齐两席”重用旧回件、旧 nonce、旧页面或部分输出。停止是有效结果，不是失败考核。

## 9. 当前真人使用前仍须另行通过的门

在任何现实专家接触当前页面、即使只做合成 onboarding 之前，至少还要分别建立并验证：

1. 把现有 clean-profile 启动候选提升为可证明浏览器实际采用 profile、排除既有状态，并建立明确网络禁用／允许策略的受控启动器；
2. 输出目录与文件的指定协调员 ACL；
3. 两文件提交、目录持久化、失败残留清理或可靠恢复策略；
4. 现实参与者知情同意、隐私告知、退出和事件处理流程；
5. 身份、资质与彼此独立性的核验方案，但身份材料不得进入本 synthetic 表单；
6. 合成 onboarding 与正式审定存储、计数和权限的物理隔离；
7. 正式材料的底本、版本、exact quote、作品层与载体层权利依据。

这些门没有逐项取得独立证据前，`physicalExpertSurfaceReady` 必须保持 `false`，现有 candidate 不得用于真实私密材料。
