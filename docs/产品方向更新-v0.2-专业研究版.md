| 项目 | 当前决定 |
| --- | --- |
| 产品路线 | 当前集中推进 **B：完整八字研究工具**；A 路线未被永久取消，但不进入本轮开发范围 |

## 2. 新的一句话定义

**哈基米八字研究台是一款可离线使用、规则可追溯、支持多盘对照与案例记录的专业八字研究工作台。**

它的核心竞争力不是“AI 说得像不像大师”，而是：

1. 同一个命盘可以复算；
2. 每个规则可以看到参数、版本和来源；
3. 不同流派或设置的差异可以并列比较；
4. 研究者能保存案例、事件、笔记和检索条件；
5. AI 只能整理、检索和解释，不参与确定性排盘裁决。

## 3. 如何覆盖“所有研究八字的人”

不为不同人群做三套产品，而是在同一数据上提供三层视图：

| 视图 | 面向用户 | 默认展示 |
| --- | --- | --- |
| 概览 | 初学者 | 四柱、五行、十神、核心关系、术语解释入口 |
| 结构 | 有基础的学习者 | 藏干、十二长生、纳音、空亡、干支作用、大运流年 |
| 研读 | 专业研究者 | 完整字段、规则命中、参数版本、推导过程与依据 |

视图只改变信息密度，不改变底层命盘。专业用户可以把“研读”设为默认；多盘、规则和修订比较统一进入独立“对照台”，新手不会被一整屏术语挡住。

## 4. v1“功能做全”的定义

完整闭环为：

```text
出生信息录入与校时
  → 可复现排盘
  → 规则包与参数切换
  → 大运、流年等运限叠加
  → 案例标注与多盘对照
  → 典籍和规则依据溯源
  → 本地保存、检索、备份与导出
```

### 4.1 排盘与校时

- 公历、农历、闰月输入与互转；
- 出生地点、IANA 时区、夏令时、经纬度；
- 民用时间与真太阳时并列预览，不静默改写用户输入；
- 未知时辰和时间范围；按 12 时支展示，其中子时按换日边界拆成前后两段，共生成 13 个代表性探针进行对照；探针不是出生时刻推断，也不直接保存成 13 个真实案例；
- 年、月、日、时柱及每张盘的算法版本、时区版本、规则配置和复算信息；
- 基础字段：天干地支、藏干、十神、五行、纳音、空亡、十二长生；
- 干支合、冲、刑、害、破与生克关系；
- 神煞作为可关闭的独立层，每项必须有规则来源，不能与基础排盘混成唯一事实。

### 4.2 规则与流派

- 先实现“传统子平基础规则包”，但不把它描述为唯一正确流派；
- 立春/春节界年、节气换月、子初/午夜换日、顺逆排运和起运算法全部参数化；
- 旺衰、格局、调候、用神等解释规则与历法计算分层；
- 同一命盘可用两个规则配置并列显示差异；
- 每个结果保留 `engine_version`、`rule_profile`、`tzdb_version` 和来源；
- v1 建立可导入的版本化规则包接口，但不承诺首版内置所有盲派、新派或个人口诀。

当前 v1 工程已支持受限声明式 Profile 规则包：完整性通过后只按内容摘要保存到本机隔离库，导入绝不自动激活；不兼容包可保留作研究，但不能激活。用户必须显式确认风险后才能激活精确摘要，新排盘会再次验真并把最终 Profile 与 `rulePackBinding` 绑定进结果哈希；悬空活动记录、摘要/Profile 不符或引擎不支持时失败关闭。这个机制不认证发布者、顾问身份或包内“已审核”自述；内置配置仍待顾问复核，当前引擎也只执行已实现的规则子集，因此“全部参数化、任意流派可运行”仍是后续目标，不是当前结论。

### 4.3 运限时间轴

- 起运年龄、顺逆及完整推导过程；
- 大运、小运、流年、流月、流日、流时；
- 原局、大运和所选时间节点同屏；
- 时间轴缩放、跳转与筛选；
- 用户可在节点记录真实事件、标签、反馈和后续验证；
- 两个不同案例的结构研究只并列各自冻结事实，并在同一 UTC 瞬时点分别展示双方各自运限；不生成评分、吉凶、缘分、婚配结论或跨盘推导。

### 4.4 研究工作台

- 本地案例库：匿名编号、姓名别名、标签、收藏和全文搜索；
- 结构化事件与任意字段笔记；
- 两盘/多盘并排，以及同盘不同规则包的差异视图；
- 按字段组合筛选，例如日主、月令、结构、运限和事件标签；
- CSV 批量建档、字段映射与错误预览；
- 保存研究视图和常用筛选；
- 每条计算事实与解释都可以打开“依据条”。

研究工作台是本产品与普通消费型算命 App 的核心差异，优先级不低于 AI 报告。

### 4.5 术语、典籍与知识

- 术语字典、干支五行表与常用关系表；
- 合法来源的公版古籍全文检索；
- 命盘字段反向链接到书名、章节、版本和原文段落；
- 用户可导入自己的 Markdown、TXT，以及后续经验证的 PDF 索引；
- 现代注解、竞品知识库和数字化整理文本未经许可不得搬运；
- 首版不承诺内置所有古籍与所有现代注疏，内容库可以持续扩展。

### 4.6 AI 研究助手

AI 是可插拔模块，不是排盘依赖：

- 带引用地检索典籍和术语；
- 整理盘面结构，不自行重算四柱；
- 比较两个规则配置的差异；
- 总结用户笔记、生成研究提纲；
- 明确区分“计算事实、规则观点、AI 表达”；
- 未配置 AI 或断网时，排盘、规则、案例和知识库仍完整可用。

项目不能把公共 API Key 写进网页或 Android 包。无付费阶段可选择暂缓云 AI，或后续支持用户自行配置兼容端点；该决定仍待确认。

### 4.7 本地数据、离线与备份

- Web v1 采用 local-first：普通构建固定为 Dexie v13 bridge，显式 production-v14 构建在不改变十五个用户数据分区的前提下新增笔记/事件案例活动流索引；两代都保存受限附件、研究者资料 singleton、应用设置 singleton、内容寻址 `ruleRegistry`、只追加 `tzdbMigrationReceipts` 与 `eventTimeMigrationReceipts`。大型知识索引或超出现有容量门的附件以后再经显式版本迁移评估 OPFS/Cache Storage，不能静默换存储；
- Service Worker 缓存应用壳、排盘内核、规则包和基础知识库；
- 首次成功加载后，除 AI 和在线地点搜索外，核心研究功能可以离线；
- 地点搜索离线时允许手动输入时区、经纬度；
- 浏览器本地数据可能被系统清理，因此必须有显式全量备份、恢复和风险提示；
- Web 首版确定为纯本地、无账号、无云同步，不上传出生资料；未来若重新立项同步，必须另做隐私、冲突和迁移协议。

当前工程已经建立独立 `/settings/data`：显示十六分区和本机存储估算，管理研究者资料、应用设置、附件、规则仓库、CandidateSet/Event 两类只追加时间迁移凭证及 Revision 计算收据，并把本地明文敏感风险放在导入导出操作旁。这里是 Web 数据管理能力，不代表云同步、Android 存储或固定设备容量已经通过。

### 4.8 导入与导出

- 当前 full v1.2 默认导出单文件 ZIP，并保留 JSON 兼容；十六分区都进入版本化计数和摘要。冻结 full v1.1 必须先按原十五分区完整验真，再只补空计算收据分区，旧 Revision 不回填。规则仓库继续复核 installed 规范 JSON、包/Profile 摘要、身份索引与 active 关系；CandidateSet/Event 两类迁移凭证及 Revision 计算收据分别复核端点、冻结上下文、正文摘要、解释/对照、来源绑定与唯一性；附件额外校验二进制字节数、SHA-256 与关联目标；
- full v1.0 作为严格冻结的十四分区契约先验真，再只补空 `eventTimeMigrationReceipts` 迁入 v1.1；full v0.9 及更早版本也先按各自版本契约验真再逐版迁移。恢复前生成精确安全备份并要求两次确认，实际替换带并发状态检查和事务回滚；
- CSV 批量导入、字段映射和研究表格导出；
- 单盘导出为 PNG、PDF、Markdown；
- 单盘保留匿名导出开关；双案例默认只能直接导出匿名 Markdown，完整审计 JSON 必须逐次确认敏感资料；
- 双案例匿名报告以系统事实白名单重新投影，不从完整对象做反向删字段；完整审计文件保留复算所需投影并自带敏感警告；
- 规则配置、案例、事件、笔记、来源引用、附件、研究者资料、可移植应用设置及两类时间迁移回执可迁移；
- 没有公开格式或授权时，不承诺直接兼容问真等商业产品的专有备份；截图 OCR 导入放在 v1.1 评估。

当前基线为全量 Vitest 101 个文件 / 1168 项、`test:tzdb` 58/58、typecheck、依赖审计、production-v14 与默认构建通过，`dist/web` 最后保持 v13。CandidateSet 2025b/2026c Edge 门 1/1 已通过。本命盘只读复演 v1 只登记 bazi 0.4.0 六字段 executor，按 exact bundled 2026c/2025b 从冻结输入重算 time/luck/facts/hash；完整性先验和全部不支持条件失败关闭，研读页 exact-only、零写入。Edge tzdb 门 1/1 覆盖当前 2026c UI 与 390×844，服务覆盖 2025b Casablanca。该首切片不包含关系、运势、流年、Transit 或其他历史 engine；Chrome、Firefox、Android/WebView、跨代 registry、极端容量和分卷仍待验收，不能写成完整 Revision replay、Web v1 或 APK 已完成。

## 5. 三个 Web 体系到 Android 的技术顺序

### Web/PWA 首发

```text
React + TypeScript PWA
  → 自有 bazi-core 适配层
  → 固定版本 lunar-typescript
  → 规则引擎与 ChartFacts
  → IndexedDB / OPFS 本地研究库
  → 可选 AI Provider Adapter
```

- [`lunar-typescript`](https://github.com/6tail/lunar-typescript) 只通过自有适配层使用，页面不能直接调用第三方 API；
- 排盘、规则、数据契约和研究逻辑做成平台无关 TypeScript 包；
- 桌面端优先做好多盘并排、筛选器、时间轴和典籍侧栏；
- 手机浏览器采用单列、分步和底部抽屉，保证功能完整而非一次展示全部字段。

### 紫微与西洋 Web 模块

- 八字 Web v1 仍是当前主线，不因多体系规划降低其 P0/P1/P2、真值和恢复门；
- 紫微斗数与西洋占星分别使用自己的输入、引擎、规则、专家真值、数据库和备份；
- 每个模块先完成输入、计算、保存、重开、检索、备份、故障矩阵和支持浏览器门，再进入共同工作台；
- 第二体系正式可用前不在主应用放置伪可点击入口，也不进行自动综合评分。

### Android 后续阶段

只有八字、紫微斗数和西洋占星三个 Web 模块都达到已约定的功能与独立质量门后，才开始 Android 产品壳：

- 默认采用 [Capacitor](https://capacitorjs.com/docs) 复用 Web 构建和 TypeScript 内核；
- 不默认采用 [Trusted Web Activity](https://developer.chrome.com/docs/android/trusted-web-activity)，因为本产品需要可靠离线、本地资料库、文件导入导出和后续原生能力；
- 下载、分享、文件、返回键和存储都先经过平台适配接口；
- 可运行时注入的 `FileTransferPort` 已建立：完整备份、报告、CSV 与设置工件统一使用文件选择、保存、显式分享、取消、不支持和失败结果；Web adapter 支持普通下载、受支持安全上下文中的 File System Access 指定位置保存与 Web Share，且只有可写流成功关闭才报告 `saved`。单盘 Markdown/CSV 与匿名双案例 Markdown 已接入先冻结 Blob、再明确选择交付路径的用户界面；取消可重试，失败不暗中下载。下一步由 Capacitor shell 注入 Android SAF/Filesystem/系统分享 adapter；
- Web IndexedDB 不会自动迁移到 APK，因此 v1 就必须固定备份格式；
- Android 阶段再评估原生 SQLite、系统分享、应用锁和签名 APK/AAB；
- [`lunar-java`](https://github.com/6tail/lunar-java) 只用于同一批命例的差分校验，不作为第二套正式产品内核；
- iOS 暂不进入路线图。

## 6. 当前八字 Web v1 明确不做

- 付费、会员、广告、积分、代币和付费墙；
- 社区、直播、真人大师市场；
- 当前版本不同时实现紫微斗数、西洋星盘、六爻、塔罗等其他体系；其中紫微斗数与西洋星盘已列入长期独立能力包规划，但不改变本轮八字发布范围；
- 转运商品、法事、符咒和恐惧营销；
- 未授权复制问真的 UI、文案、数据、课程和备份格式；
- 首版云账号与跨设备同步，除非用户下一轮明确要求；
- 首版原生 Android 功能和 Android 商店发布；
- iOS 与原生 iOS 适配；
- 对“所有流派、全部古籍、所有历史年份已完全覆盖”作不真实承诺。

## 7. 质量发布门

“历法准确、规则实现一致、解释观点”分开验收：

1. 首发建立 360 个经专家、权威历书或明确规则来源确认的金标准输入案例；
2. 数千个随机差分测试，用其他实现找分歧，但不把商业 App 当唯一真值；
3. 覆盖节气交接、闰月、23/24 点、真太阳时、DST、跨日、跨年和极端经度；
4. 每条规则有固定样例、来源和版本；
5. 备份恢复、数据库升级和导入导出做往返测试；
6. Chrome、Edge、Android Chrome 的响应式、离线、PWA 安装升级与回滚测试；
7. Android 阶段再增加 Capacitor WebView、文件权限和数据迁移测试。

## 8. 2026-08-10 已确认补充与剩余问题

已确认：

- Web 首版纯本地、无账号、无云同步；
- v1 允许随包典籍正文继续为 0，古文与合法版本内容以后补充；
- 八字、紫微斗数和西洋占星的 Web 功能完成后再进入 Android；
- v14/v15 是否曾真实部署目前不确定，查清前不得晋级 v16；
- 用户允许在敏感文件、生成物和忽略规则审计完成后建立受控 Git 初始基线。

仍需确认：

1. **流派基线：** 是否同意先以传统子平为基础，盲派、新派等以后作为独立规则包？建议同意。
