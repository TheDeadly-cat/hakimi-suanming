## 1. 结论

本阶段为吠陀体系新增一份项目自写、隔离的 JSON Schema 草案 `hakimi.vedic.facts/0.1-draft`，以及绑定该草案的 fact requirements 账。草案只定义四类事实载荷的结构：`observation_instant_fact`、`graha_position_facts`、`lagna_fact` 与 `bhava_facts`；它不包含事实值，不建立计算能力，也不复用八字、紫微或西洋的事实、规则、producer、来源、权利、专家或发布身份。

fact requirements 中 12 项 prerequisite 均为开放的草案覆盖项，`requirementsDraftCovered=12`、`requirementsResolved=0`、`requirementsUniverseClosed=false`。四个 fact family 的覆盖情况单列为 `non_requirement_fact_family_coverage_summary`，不得把 4 个 family 再计入 12 项 prerequisite，也不得把当前 scoped inventory 解释为吠陀事实要求宇宙已经穷尽。

## 3. 单向依赖与证据限度

当前绑定关系按集合陈述，不再压缩成一条线性箭头：

- input requirements 精确绑定 ADR 与 input draft；
- fact draft 精确绑定 ADR、input draft 与 input requirements；
- fact requirements 精确绑定 ADR、input draft、input requirements 与 fact draft；
- 后续 rule draft 精确绑定此前五层，rule requirements 再绑定 rule draft；
- parent productization aggregator 精确绑定 input／fact／rule 三套 draft 与 requirements。

三份 requirements child 都不反向绑定 parent，rule draft 也不含 parent／中央 registry backlink，因此不存在 child／parent raw-hash 循环。held handle、同一 Buffer hash／parse、端点 identity revalidation、普通目录链和单链接端点只建立逐文件端点证据；`crossFileAtomicSnapshot=false`、`intervalMutationExcluded=false`、`abaExcluded=false`、`mutationEpochAvailable=false`。这些机制不证明跨文件原子快照、读取区间不变、ABA 排除或 mutation epoch。
