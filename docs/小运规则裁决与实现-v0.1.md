# 小运规则裁决与实现 v0.1

> 状态：**工程工作口径已锁版，流派结论未终审**  
> 截止：2026-08-01  
> 当前验证状态：`engineering_preview`；小运金标通过数 `0`；`releaseGatePassed=false`  
> 适用范围：当前 Web/PWA 研究工作台；后续 Android 壳复用同一规则快照，不另设算法。

## 1. 本轮结论

当前产品采用“**出生时柱相邻起法**”作为可复算的工程工作默认：虚岁 1 从出生时柱沿已确定的顺逆方向移动一步，以后每一虚岁再移动一步；虚岁分界采用固定 `UTC+08:00` 的精确立春时刻。

这项决定只回答“产品当前怎样稳定计算”，不声称：

- 它是古籍唯一的小运算法；
- “固定丙寅/壬申起法”等其他传承错误；
- 精确立春、虚岁、终身排小运或半开区间由原典逐项规定；
- 当前实现已经通过专家裁决或发布金标。

如果后续专家结论改变，必须新增规则版本并并列复算，不能改写已经保存的旧规则快照。

## 2. 证据分层

### 2.1 原始文献能够支持的事实

1. [《三命通会》小运相关条文](https://ctext.org/wiki.pl?chapter=578162&if=gb)提供了从出生时辰附近起小运、并区分顺逆的文本依据。它足以把“时柱相邻起法”列为有文献根基的候选，但不能单独推出本项目全部 13 个计算字段。
2. 另有文本呈现“男命虚岁一岁丙寅起、顺行”和“女命虚岁一岁壬申起、逆行”的固定起点路径：[男命固定起点相关页](https://ctext.org/wiki.pl?chapter=181298&if=gb)、[女命固定起点相关页](https://ctext.org/wiki.pl?chapter=388209&if=gb)。这证明至少存在与“从本命时柱相邻起”不同的可实现方法，不能把其中任一方法无标注地称为通行唯一标准。
3. [小运适用阶段相关条文](https://ctext.org/wiki.pl?chapter=17423&if=gb)留下“只用于幼年或未交大运前”与“可排至终身”的范围解释空间。当前资料不足以把 `whole_life` 说成原典已定。

以上链接是本轮定位入口，不替代正式版本学工作。进入人工金标前，顾问仍须补齐书名、卷次、篇名、底本/影印本、页码或稳定章节标识，并核对文字异同。

### 2.2 原始文献没有直接规定的工程细节

古籍不会直接给出以下现代软件语义，因此这些内容必须明确归入产品建模，而不能写成“古法事实”：

- ISO 8601 瞬时、毫秒精度和固定 `UTC+08:00` 时间框架；
- 立春边界是否取“恰好当刻”，以及区间是否左闭右开；
- 未知性别、未知时辰和人工顺逆的错误/降级契约；
- 节点 ID、规则摘要、版本迁移和历史快照重放；
- 移动端或 Web 展示窗口的节点数量；
- 上游程序库的具体数据结构。

### 2.3 仍待专家裁决的问题

| 问题 | 当前处理 | 终审需要的证据 |
| --- | --- | --- |

| 顺逆是否完全复用大运方向 | 当前复用“命盘年干阴阳 × 性别”，性别不明时人工指定 | 原典语义、不同流派对照、四象限命例 |

| 增龄边界是立春、农历年初、生日还是其他时点 | 当前取精确立春 | 原典/师承说明与边界前后命例 |

## 3. 已锁版的工程工作默认

“锁版”表示字段进入不可变 `luckCycleRuleSnapshot.xiaoyun`；它不是“学术争议已经结束”的同义词。独立默认模板身份为 `ziping-directional-jie-xiaoyun-working-default@1.1.0`；写入具体修订时使用 `${profileId}:luck-cycle-xiaoyun@${profileVersion}`，并以完整规则摘要区分内容。旧版仅含大运的身份保持 `${profileId}:luck-cycle`。当前新生成的运限时间轴版本为 `hakimi-transit:1.2.0`；`hakimi-transit:1.1.0` 仅在 algorithm 为 `hakimi-transit-core:parallel-active-intervals:v2` 时进入只读/恢复兼容验真，旧引用保持 1.1，不会被静默改名。

| 字段 | 锁定值 | 产品语义 | 证据属性 |
| --- | --- | --- | --- |
| `method` | `birth_hour_adjacent` | 从出生时柱相邻干支起步 | 有原典候选依据；仍有替代流派 |
| `directionRule` | `exact_chart_year_stem_and_gender` | 使用按当前命盘边界规则算出的年干与性别，不用公历年份猜测 | 产品建模 |
| `directionReuse` | `luck_cycle_or_manual_direction` | 复用大运顺逆；性别不明时复用人工方向 | 产品建模 |
| `firstAge` | `1` | 第一节点标记为虚岁 1 | 工作口径 |
| `firstStepOffset` | `1` | 虚岁 1 已从时柱移动一步，不把时柱本身当第一小运 | 时柱相邻法的实现解释 |
| `ageBasis` | `nominal_age` | 年龄标签使用虚岁 | 工作口径 |
| `boundaryAlignment` | `flow_year_start_exact` | 以精确流年起点，即精确立春，切换年龄 | 产品建模 |
| `boundaryFrame` | `fixed_plus08` | 立春计算统一在固定 `UTC+08:00` 框架 | 产品建模 |
| `scope` | `whole_life` | 当前允许生成终身小运窗口 | 未终审的产品选择 |
| `cycleLength` | `60` | 沿六十甲子循环 | 干支循环事实的实现约束 |
| `intervalPolicy` | `half_open` | 每段采用 `[start, end)`，边界当刻进入下一节点 | 软件确定性约束 |
| `unknownSexPolicy` | `require_manual_direction` | 性别不明时必须人工指定顺或逆 | 产品降级策略 |
| `unknownHourPolicy` | `unsupported` | 未知时辰不生成伪造小运 | 产品安全边界 |

### 3.1 干支步进

设出生时柱在六十甲子中的序号为 `H`，虚岁为 `A`，当前锁版参数为 `firstAge=1`、`firstStepOffset=1`：

```text
step = firstStepOffset + A - firstAge = A
顺行：xiaoyunIndex = (H + step) mod 60
逆行：xiaoyunIndex = (H - step) mod 60
```

因此：

- 时柱为甲子、顺行、虚岁 1 → 乙丑；
- 时柱为甲子、逆行、虚岁 1 → 癸亥；
- 虚岁 61 与虚岁 1 的小运干支相同。

### 3.2 时间区间

- 虚岁 1：`[出生瞬时点, 出生后的严格下一次立春)`；
- 虚岁 2：从上述立春当刻开始；
- 以后每段：`[当年精确立春, 次年精确立春)`；
- 目标时刻早于出生瞬时点：`not_applicable / PRE_BIRTH`；
- 边界前 1 ms 仍属于旧节点，边界当刻进入新节点。

这里的“严格下一次”很重要：如果出生瞬时点恰好等于立春，当前工作规则不会生成零长度的虚岁 1，而把下一年的立春作为其终点。这一点必须进入候选金标，不能只靠单元测试自证。

## 4. 历史快照与降级行为

小运字段在总起运规则快照中保持可选，只用于兼容小运锁版前已保存的数据；新建修订必须完整写入 13 个字段。

| 情形 | 必须行为 |
| --- | --- |
| 新修订包含完整小运快照 | 按该快照计算；规则摘要、时间轴版本和节点引用一同保存 |
| 旧修订有大运快照但没有 `xiaoyun` | 旧数据继续可读；小运返回 `unsupported / XIAOYUN_RULE_SNAPSHOT_MISSING`，轨道为空 |
| 更早修订连完整起运快照也没有 | 只允许按旧固定常量推断原有大运行为；不得反向补写当前小运默认；小运仍为上述 `unsupported` |
| 小运字段被修改成未支持组合 | 拒绝计算，不能静默回退当前默认 |
| 性别不明且没有人工方向 | 大运和小运均返回 `MANUAL_DIRECTION_REQUIRED`；其他不依赖方向的层可继续 |
| 性别不明但给出人工方向 | 人工方向进入快照上下文及稳定节点引用，复算时必须一致 |
| 时辰未知 | 返回 `unsupported / XIAOYUN_UNKNOWN_HOUR_UNSUPPORTED`，不尝试猜时柱 |

快照与摘要必须成对存在；只删除其中一个会被拒绝。带 `-xiaoyun` 的现代身份必须包含完整小运块，旧版身份则不得伪装成含小运规则。轨道契约还会拒绝乱序、区间重叠、活动标记与目标瞬时点不符，以及 slot 与轨道节点事实不一致的记录。

历史兼容的核心原则是“可读但不伪造”。新默认不能被偷偷套到旧记录，否则相同修订在软件升级前后会产生不同事实。旧快照与新快照的规则摘要应不同；稳定节点必须能由修订、规则摘要、方向、节点类型和半开区间起点复算。

### 5.1 候选转正式金标的门槛

每个候选必须同时满足：

1. 输入和预期结果采用严格 Schema，不接受截图作为唯一证据；
2. 至少一条原始文献或明确师承规则来源；边界例另有独立历书/天文时刻来源；
3. 主审与复审为不同人员，分别记录接受、替换或拒绝及理由；
4. 同一算法生成的两个衍生库不能冒充两份独立证据；
5. “时柱相邻法”和“固定丙寅/壬申法”对 G01～G06 的不同输出均入审计记录；
6. 裁决绑定候选数据摘要、规则摘要和证据版本，后改内容必须使摘要失配；
7. 16 例全部通过仍只代表小运子集通过，不替代项目 360 输入总金标和运限其他层验收。

## 7. 发布与后续裁决

当前界面必须同时显示“工程工作口径”“小运金标 0”“非唯一流派结论”，不得使用“权威”“精准验证”“唯一正确”等表达。小运从工程预览提升为 v1 可发布事实层前，至少需要：

1. 16 个候选完成双人裁决并转为正式金标；
2. 固定丙寅/壬申替代法被明确收录为可选规则包，或留下经专家签署的不收录理由；
3. 对立春边界、出生恰逢立春、未知性别/时辰和 60 步回环完成浏览器与离线复算；
4. 找到不依赖同一 6tail 代码血缘的校验来源；
5. 规则版本、数据摘要、节点引用和备份恢复在 Web/PWA 通过后，再用同一数据包验证 Android 安装壳。

在这些门槛完成前，当前实现的价值是“可讨论、可复算、可推翻”，而不是替研究者结束争议。

## 8. 摘要

当前仅锁定“出生时柱相邻、复用大运顺逆、虚岁 1 起、精确立春增龄”的工程工作规则，旧快照不会被新默认污染。16 例仍是待双人裁决的金标候选，正式通过数为 0。GitHub 代码只在许可证与来源清楚的边界内作为依赖或差分参考，本项目不整库搬运，并保留固定丙寅/壬申等替代方法进入后续规则包裁决。
