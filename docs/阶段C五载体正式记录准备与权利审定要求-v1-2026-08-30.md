# 阶段 C 五载体正式记录准备与权利审定要求 v1

## 1. 本轮只推进什么

本轮没有再造 `SourceCarrierRecord` schema，也没有创建正式载体记录或权利审定回执。新增的是一个单向、deny-only、zero-instance 的准备缺口账：把当前 source v1.6 与 rights v1.2 的 4 个来源候选／5 个载体观察层逐项对齐到既有 `SourceCarrierRecord` v1 字段，并明确每个载体仍缺什么。

机器账位于 `content/system-admission/bazi-source-carrier-record-readiness.v1.json`；loader 会从固定 workspace 路径稳定读取父账、readiness、既有 contracts 与 C-M1 v1.1 支持依据，拒绝 symlink／hardlink／路径 alias、非严格 JSON和重复键。它还必须消费 canonical source／rights supersession 与 readiness 1.7 两个 full loader 的私有品牌。持久 child 的 `27322` bytes／raw SHA-256 `d5624c796f715b3e4a9846714a036621a8ccc66d8e3433a91e7bf69beba291e9` 被独立固定，并必须与固定父字节机械重建的 expected 全等；所有 zero-instance、`legacy-v13 / 13 / null`、mutation／ABA 和 authority 红门还会被逐字段直接断言。只重算 child digest 不能改变任何准入结论。

本门只返回由语言级私有字段和模块私有构造令牌建立的 opaque capability，不向调用方暴露完整 ledger；其私有摘要由固定 child identity 与常量红值构造，不从可变的重建对象复制 authority。状态读取器每次只复制一份无品牌、仅含原始值的红门摘要。canonical serializer 固定其使用的 `Object.keys`、`Array.isArray`、sort、`JSON.stringify` 与 `Reflect.apply` 引用，不在验证时重新读取 ambient 原语；canonical 比较完成后，persisted 与 expected 的红门、固定 ledger identity 和 status 会再次直接断言，随后执行覆盖全局 authority／mutation、回执签发与自动晋级、独立 reviewer／owner 门，以及五行各自三层清权、复制／引用／再分发、法律结论、admission、正式记录和物化资格的原始值终检。所有 review／row getter-bearing 读取结束后，constructor 前还会立即执行不调用数组、枚举、JSON 或其他 helper 的最终 authority latch；现有回归精确证明，代理数组 `length` getter 直接把重建态 authority 改成允许值时，会在能力签发前被 `FINAL_AUTHORITY_LATCH_DRIFT` 拒绝。首次 import 前替换 `node:vm` export、污染 ambient `WeakSet`／`Object.freeze`、植入本轮已覆盖的有状态 `Object.keys`、`Array.isArray` 或 receipt-length 变体、给 capability 增添同名公开字段、复制或重新冻结对象、取得公开 constructor 后改写 static method，均不能借这些已测路径铸造品牌或改写返回的私有摘要。

这不是对恶意同 realm 中临时 `expected` 不可变性的普遍保证。有限次、有顺序的字段读取仍可能被更复杂的有状态 Proxy 安排为：在较后字段返回红值时，改写已经检查过的较早字段，并让 loader 走完；也可能在返回后继续改写已丢弃对象。临时 `expected` 因此不是可传递的 authority 对象，loader 不返回它，constant-red constructor 也不消费它；唯一返回的品牌是固定红摘要 capability。此边界只保证已固定父链／child 检查流程完成后返回的 capability 不携带许可或发布晋级，不保证恶意 ambient realm 中每个临时重建字段在所有瞬间都保持不变，更不代表许可、内容真值、专家真值或发布授权。

每行同时锁定 source／rights candidate digest、binding、evidence subject、source、anchor、file page、标题、URL、MediaWiki SHA-1、载体 SHA-256、bytes、页数、MIME、provider、edition relation、notice 和 reviewer 空集合。扫描载体的 SHA-256 只说明观察到的载体字节身份，不能冒充归一化文本的 `documentContentHash` 或 `contentDigest`。

## 3. 仍然阻塞的正式字段

五行均没有 `carrierId`、`documentId`、`documentContentHash`、归一化 `contentDigest`、正式 acquired/access 记录、正式 `SourceRightsRecord`、正式 `SourceCarrierRecord`、项目副本物化记录或权利审定回执。作品层、版本／转录层和载体层均未清权；复制、引用、再分发三项在项目准入门中全部保持未授权的 false。这是 fail-closed 工程值，不是“法律禁止”的裁定。

平台上的 Public domain、PD-old、PD-scan 或 PDM 字段、公开 URL、HTTP 可访问性、稳定 hash、无 attribution 字段和视觉对应都只能是观察，不能自动建立司法辖区适用性、作品／版本／载体许可或再分发权。

## 4. 未来权利审定回执的边界

本 child 不能签发回执。未来另门至少必须绑定：

- source／rights 父账 raw 与 semantic identity、逐 candidate digest、精确载体 anchor 与 raw byte identity；
- 作品、版本／转录、载体三层分离判断；
- 司法辖区、notice 适用性与复制／引用／再分发逐项判断；
- 证据修订身份；
- 至少两名现实自然人的身份、资质、角色范围、独立性及其实际签署 tuple。

仅在记录里写两个不同 reviewer ID 不足以证明现实身份或独立性。分歧必须保持 unresolved；不得多数表决、平均，也不得由生成模型自动选赢家。正式使用还需独立 owner 授权门，本账不会自动 promotion。
