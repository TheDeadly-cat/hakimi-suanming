## 3. 重放结果与读取边界

独立 child parser 不导入或执行 draft TypeScript 实现。它对冻结 fixture 做 canonical base64、gzip、压缩体 hash、解压 raw hash、CSV 结构和逐日连续性校验，再独立重建边界矩阵：

| observation | exact count |
|---|---:|
| 年度资源 | 6 |
| raw source bodies | 6 |
| 公历日记录 | 2,192 |
| 年内边界对 | 74 |
| 跨文件 year seams | 5 |
| 农历新年 | 6 |
| 普通月转换 | 62 |
| 闰月开始 | 3 |
| 闰月结束 | 3 |

fixture 文件的 SHA-256 与 JSON parse 使用同一次 held-handle 读取所得 Buffer；每个年度资源的 hash 与解析使用同一个解码后 Buffer。父 requirements 的 candidate entry 直接复用 child verifier 返回的 `artifact.path/bytes/sha256`，不再为同一 candidate 进行第三次读取，因此单条 candidate 内的工件身份与语义摘要来自同一次已核对 child 读取。draft TypeScript 文件只冻结字节身份，没有在 child 中执行，因此明确记录 `parserHashAndExecutionUseSameReadBuffer=false`，不能把独立重放写成“已执行并证明该 TypeScript parser”。

父 requirements 的三个 basis artifact 也已改为 held-handle 读取：同一 Buffer 同时产生 bytes 与 SHA-256，并对读取前后端点身份及长度做核对。读取仍是逐文件的有界证据，不是跨文件原子快照；当前没有 mutation epoch，端点检查也不能排除恢复到相同可见身份的 ABA。这些未证明项均保持 `false`。
