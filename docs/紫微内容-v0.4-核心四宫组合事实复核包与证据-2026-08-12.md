# 紫微内容 v0.4：核心四宫组合事实复核包与证据（2026-08-12）

## 1. 本轮结果

在 v0.3 的“十四主星 × 命、财帛、官禄、迁移四宫”56 条位置化候选之下，新增来源绑定的组合事实复核包：

1. 只要本命盘核心四宫中实际出现主星，就为该“主星 × 实际宫位”生成一条组合复核包；默认工程样例实际生成 5 条。
2. 每条直接汇总本星亮度、生年四化、同宫其他主星、同宫辅／杂曜，以及对宫和两组三合位的主星事实。
3. 每条提出四个不同的审稿问题：亮度如何调节、当前生年四化如何调节、同宫星如何并列／增强／转向／冲突、三方关系如何合参。
4. 每条绑定冻结规则快照 SHA-256 和当前 Browser 工件事实 SHA-256，表明复核问题针对哪套规则、哪张已验真盘面。
5. 所有组合结论固定为 `result:null`；状态固定为 `awaiting_expert_rule / isolated_review_only`，不允许直接结果、评分或专家真值声明。
6. 非核心宫组不生成位置候选，也不生成组合复核包；切换到默认样例的兄弟宫组时两者同时归零。

本轮完成的是“让用户和专家看见一条位置化短解究竟还缺哪些组合规则”，不是用星数相加或网页套话生成吉凶。

## 2. 组合复核契约

- 版本：`ziwei.major_star_core_palace.combination_review/0.1`
- 类型：`source_bound_combination_fact_review`
- 生成范围：本命盘 `life / wealth / career / travel` 中实际出现的主星
- 四化范围：`natal_birth_year_only`
- 审稿状态：`awaiting_expert_rule`
- 发布状态：`isolated_review_only`
- 结论字段：`result:null`
- 固定声明：`factsDerivedFromVerifiedArtifact:true`
- 固定声明：`interpretationIncluded:false`
- 固定声明：`expertTruthClaimed:false`
- 固定声明：`directOutcomeAllowed:false`
- 固定声明：`scoringAllowed:false`

该契约只位于主线程只读显示投影，没有加入 Worker 回包、Browser 工件 Schema、Revision、IndexedDB 或备份格式。

## 4. 本轮来源与禁止推断边界

### 4.1 亮度

- [iztro 星曜系统](https://docs.iztro.com/zh_TW/learn/star)明确说明不同门派存在四级与七级亮度表差异，并给出本项目冻结口径使用的亮度表。
- 本项目只保留已验真盘面原值；不会把“庙／旺”自动映射为吉、加分、成功，也不会把“陷／不”自动映射为凶、减分或失败。

### 4.2 四化

- [iztro 四化资料](https://docs.iztro.com/zh_TW/learn/mutagen)说明四化依附星曜、会调节星曜呈现，同时明确这不是简单好坏标准，并区分本命、宫干和不同运限四化。
- 当前 Browser 工件只验真本命生年四化，因此组合包固定 `natal_birth_year_only`；宫干、自化、大限、流年等一律不补入。

### 4.3 同宫与三方会照

- [iztro 基础术语](https://docs.iztro.com/learn/basis)把“同宫／同度”定义为星曜在同一宫，把“会／扶拱”定位到三方位，把“照／冲”定位到对宫。
- [iztro 星盘资料](https://docs.iztro.com/zh_TW/learn/astrolabe)也把主星、辅星、亮度、四化和三方四正列为不同信息层，并提示各派分析方法不同。
- 本轮只据几何关系列事实，不按星数相加、不把对宫与三合位视为同一权重，也不自行分类“助力／冲突”。

### 4.4 古典合参顺序

- [《紫微斗数全书》卷三](https://zh.wikisource.org/wiki/紫微斗數全書/卷三)的“谈星要论”依次列命宫、身主、迁移／财帛／官禄三方，并同时提及庙旺、四化和同会条件，支持“组合条件不可省略”这一结构结论。
- 同一段古籍包含大量富贵、灾祸、疾病、身份和寿命强断语；这些内容一律不进入 UI 或规则候选。

现代网页受原作者版权约束。本轮只登记链接、资料边界和重新组织的审稿问题，没有复制原文段落。专用 Firecrawl/Exa 本轮未配置，研究由内置网页检索完成。

## 5. 代码与失败关闭门

### 5.1 生成门

- 组合包只能绑定已有 `palaceCandidateContent`；核心宫主星缺位置候选会直接停止投影。
- 规则快照与事实摘要必须是 64 位小写十六进制 SHA-256。
- 每个组合包的 `reviewId` 和绑定的 `candidateContentId` 在当前盘内唯一。
- 同宫事实排除本星，不能出现重复星曜。
- 三方事实必须恰好包含对宫、`+4` 三合位和 `−4` 三合位三种关系。

### 5.2 来源与内容门

- 每条必须绑定亮度、四化、同宫／会照术语和古典合参顺序四类来源。
- 每条必须有四个不同的审稿问题。
- 事实摘要不得包含“一定、必然、注定、保证、终身、大吉、大凶、发财、富贵、适合”等结果化措辞。
- `result` 非空、`interpretationIncluded:true`、专家真值、直接结果或评分任一越界都会在模块初始化阶段失败。

### 5.3 写入门

- 应用内 Browser 验收只计算、切换宫位和查看，没有点击保存；开始和结束时 Revision 均为 0、资料代次均为 5。
- Edge 自动门的保存、完整恢复、清空、配额和并发测试继续走既有 mutation epoch 与原子事务，没有直接改 IndexedDB。

## 6. UI 呈现

每条位置化候选下新增“亮度／四化／同宫／会照 · 合参事实包”，包含：

1. 一句话事实摘要；
2. 本星状态、同宫主星、同宫辅／杂曜、三方主星、四化范围五行事实；
3. 四个需要专家逐项回答的问题；
4. 明示“组合结论：未生成（result:null）”；
5. 亮度、四化、同宫／会照和古典顺序四个来源链接。

首次 390×844 检查发现问题正文只有 9.92px。该轮立即调整为 11.2px、行高 18.144px 后重建并复验；内容无裁切、无横向溢出。
