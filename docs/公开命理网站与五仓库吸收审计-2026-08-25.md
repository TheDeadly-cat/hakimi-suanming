# 公开命理网站与五仓库吸收审计（2026-08-25）

## 0. 结论

本轮之前，不能称为“已经充分学习并吸收”。项目虽已有较强的本地优先、恢复安全、工程证据和报告边界，但对外部优秀产品与指定五个 GitHub 仓库的吸收仍主要停留在零散参考；八字旺衰证据注册表的 `8 sources / 12 bindings` 当时也只是来源资格快照。当前 `single-chart-report` v1.7 的核心机械准入已落盘，并完成受影响合同、scoped TypeScript、治理边界、隔离构建及真实浏览器的定向复核；这仍不等于外部内容已被纳入、内容真值已被证明、权利法律结论已经成立或已取得公开发布授权。

本轮完成的是公开、只读、clean-room 研究：

- 核对 5 类公开命理产品的输入、排盘、解释、知识、隐私和高级设置流程；
- 核对指定 5 个 GitHub 仓库的默认分支、近期公开提交、许可证、架构、测试／发布证据和明显风险；
- 核对本项目 8 个 registry 来源的版本、定位器、作品层与载体层权利；
- 形成“可以吸收／需要另审／不得直接复制”的工程清单。

这仍不等于：

- 访问过任何未公开后台、管理端、私有 API 或账号数据；
- 运行或复现了五个外部仓库；
- 验证了其准确率、古籍正统性、术数结论或专家共识；
- 取得了其提示词、知识文本、数据集或运行时资产的再分发授权；
- 完成本项目正式内容准入、专家审定或公开发布授权。

## 1. 研究方法与安全边界

访问日期：`2026-08-25`。

本轮只使用公开网页、公开 GitHub 页面／API、公开 MediaWiki API 与公开条款页面。没有登录对方系统、提交命盘或个人资料、探测未公开接口、绕过访问控制、批量抓取正文、下载大型数据集，也没有把外部仓库克隆进本项目。

“学习后台”在本项目中只能指研究公开披露的系统结构、API 文档、隐私说明、公开源码与运行流程；不包含未经授权进入管理后台、私有 API、数据库或运营系统。

### 2.1 Astro.com

公开入口：

- [Extended Chart Selection](https://www.astro.com/cgi/genchart.cgi)
- [Birth Data Entry](https://www.astro.com/cgi/ade.cgi?lang=e&ract=genchart.cgi)
- [Terms of Use](https://www.astro.com/contact/user_e.htm)

1. 出生资料录入与高级盘面设置分开，普通用户不必先理解全部专业参数。

### 2.6 网站基准形成的项目原则

本项目应吸收：

- 先采集最低必需信息，再逐步展开高级规则；
- 明示出生时间不确定性、时区／夏令时／真太阳时／日界口径；
- 计算事实、术数规则、来源知识与叙事解释分层；
- 本地／访客／账号三种数据生命周期可见；
- 外部 AI 提供商、跨境传输、缓存、删除和导出边界可见；
- 保存的设置必须带版本与规则摘要；
- 不确定输入自动降低功能与证据等级，而不是静默补默认值。

本项目不应吸收：

- 对方的解释正文、提示词、知识库、古籍整理文本、视觉资产和私有算法；
- 用营销数字代替测试、来源、专家或权利证据；
- 用“已有出处标签”代替精确版本、页行、原文摘要与权利记录。

### 3.2 可吸收的共同工程模式

#### A. 事实计算与叙事解释隔离

命盘事实必须由确定性算法产生；LLM 只能消费冻结、校验过的结构化数据，不能自行重排四柱、星位或时间窗口。模板负责视觉，模型不能直接拼任意 HTML。

#### B. canonical 数据只生成一次

完整盘面、输入口径、候选状态和计算 provenance 形成 canonical snapshot；职业、关系、合盘等模块只读消费。报告只展开本次实际用到的证据，但不能从 canonical 源中删除“不吻合”的候选。

#### C. 三种不确定性分开

至少分为：

- `inputReliability`：出生时间、地点、历法、资料来源是否可靠；
- `computationStability`：规则变体或分钟扰动是否改变计算结果；
- `interpretationReview`：解释是否经过适当人工复核。

三者都不能等同于术数真值或科学有效性。

#### D. 声明算源与实测算源分开

为每个可计算 binding 记录 `declaredComputationSource` 与 `observedComputationSource`。若引擎、版本、endpoint、export schema 或上游 commit 不一致，自动 withheld，不允许静默沿用声明值。

#### E. 忠实性不等于真值

可以机械审计报告断言是否被盘面事实支持、是否凭空新增、是否和计算结果矛盾；该 `factFaithfulnessStatus` 只证明“叙事忠于输入快照”，不证明命理判断正确。

#### F. 跨体系保持分歧

八字、紫微、西占、吠陀等体系分别保留证据 IDs。综合结果应为 `agreement / disagreement / unresolved`，不得通过平均、投票或强行统一制造虚假共识。

#### G. 规则条件不只是一串正向命中

参考 `required / bonus / breaking`，本项目可采用更证据化的：

- `requiredEvidence`
- `supportingEvidence`
- `breakingEvidence`
- `withholdingConditions`

任何 breaking／withholding 条件命中都必须留在报告证据账中。

#### H. 发布与文档漂移守卫

source／binding 的新增、删除、重命名应同时触发 Schema、测试、黄金文件、文档和 provenance 清单更新。发布资产可借鉴 manifest、SHA256、SBOM 和跨平台 smoke，但这些仍只是工程证据。

### 3.3 明确不直接吸收的部分

- 倪海夏相关讲义、提示词、解读、样本答案；
- 五仓库内的格局文案、古籍数字化正文、解释表与 RAG knowledge 目录；
- AGPL 代码或受商业限制的 `SKILL.md`、prompts、resources/references；
- 大型数据集，仅凭 README 授权句不进入正式内容链；
- 外部项目的开放 CORS、任意出站 URL、弱密码哈希等安全实现；
- 作者自述的准确率、“正统”“古籍级别”和测试数量，除非本项目独立复现并限定证据范围。

## 4. 本项目现有 8 sources / 12 bindings 的真实状态

当前 `single-chart-report` v1.7 已把来源资格快照推进到按 binding 计算的核心机械准入：

- 静态注册表仍是 `8` 个唯一来源、`12` 条 binding；每条 binding 具有稳定、显式的 `evidenceSubjectId`；
- 每个来源的 `sourceRightsRecordStatus = binding_scoped` 只表示报告按 binding 观察权利记录，不证明来源身份或权利成立；
- `mechanicalAdmission.sourceIdentityStatus = not_assessed` 固定失败关闭，Citation target 也不得被解释为来源身份已建立；
- 准入状态按与 binding 精确匹配的 Citation、KnowledgeDocument 和 SourceRights 记录机械计算，可区分无记录、candidate、rejected、verified-private 与 verified-redistributable；
- KnowledgeDocument 的实际内容摘要、章节范围和 exact quote／locator 必须闭合；报告内 `C#`、`D#` 引用必须一致，同一 `D#` 必须复现完整来源与权利投影而不只比较 hash；
- full 报告只按唯一目标／唯一文档／唯一权利记录汇总；解释被 DST 边界扣留时明确标为 `not_evaluated_interpretation_withheld`，不能把全零误读为已评估；
- anonymous 报告仅保留固定 redacted 形状，不泄露动态 citation／rights 状态或来源细节；
- v1.7 独立冻结 golden 已建立；本轮合并定向回归为 **10 files / 269 tests**，scoped TypeScript、三项治理边界、离线 lockfile dry-run、隔离 Vite build 与应用内真实浏览器 full／anonymous／`390×844` 均通过。完整应用、默认 build、PWA、跨浏览器与公开主机未验证。

这些合同只能证明结构完整性、精确连接和失败关闭行为。它们不能证明引用内容正确、术数主张为真、来源身份真实、权利记录具有法律效力、专家已经审定，也不能证明公开发布获准或 release ready。

## 5. v1.7 已落盘的核心机械准入与后续内容门

v1.7 已建立版本化的：

`source binding → KnowledgeDocument → CitationRecord → SourceRightsRecord`

已落盘的机械合同包括：

- 稳定 `evidenceSubjectId`；
- source／edition／revision／locator 原字形；
- `documentId` 与 `documentContentHash`；
- 行号范围和逐字 quote 校验；
- candidate／verified／rejected citation 状态；
- 双 reviewer 记录与 decision note；
- 作品层和载体层分开的 rights basis；
- distribution policy；
- 按 binding 机械计算的完整／匿名汇总与失败关闭边界。

覆盖率与准入状态由实际 join 机械计算。以下情况一律不升级：

- 只有书名／章节名，没有冻结文档和 exact quote；
- citation 指向的文档 hash 不一致；
- 只有 candidate citation；
- rights 记录属于另一个文档版本；
- 作品层公版但载体层未清；
- reviewer 记录不满足合同；
- 匿名导出试图携带正文或不必要个人信息。

后续仍须另行建立且不能由 v1.7 机械合同替代的内容门包括：冻结并获准使用的实际文本、逐条版本／底本核对、作品层与载体层权利审查、真实专家身份与独立复核、冲突裁决，以及 `declaredComputationSource / observedComputationSource`、`inputReliability / computationStability / interpretationReview` 等更上层忠实度评价。任何 `factFaithfulnessStatus` 也只能描述证据审查状态，不是术数真值。
