## 1. 本轮目标

v0.12 已冻结十二个核心辅煞的 12 条基础中性候选和 `12 × 12 = 144` 条落宫候选。v0.13 不扩写一套新的星义，也不把传统“六吉／六煞”升级为个人吉凶，而是把**当前整张命盘真实出现的核心十二辅煞**按三方四正关系展开为可下载、可离线填写、可在当前盘上只读预检的动态审稿包。

当前源码合同为：

- 一份包固定覆盖当前整盘 12 个目标宫组；标准盘的十二个核心星曜事实各进入四个目标组，因此共有 48 个 occurrence；
- 目标组按当前盘宫位显示顺序排列；组内固定为 `self → opposite(+6) → trine(+4) → trine(-4)`，同宫内继续保留原始星曜顺序；

这里的 `48` 是标准盘结构覆盖，不是 48 条新星义；同一真实星曜事实在四个目标组中以不同关系位置出现。

## 2. occurrence 只携带什么

每个 occurrence 只绑定当前已验真事实与 v0.12 既有候选：

- 目标宫、来源宫及其地支；
- `self / opposite(+6) / trine(+4) / trine(-4)` 关系；
- 精确星键、标签、`minor` 事实类别、原始星序；
- 当前盘实际亮度与本命生年四化；
- v0.12 基础候选与落宫候选的完整快照和内容 ID；
- 当前规则快照 SHA-256、当前事实 SHA-256、有序 review／occurrence 摘要；
- 每条来源的 locator、`bindingTarget` 与 `semanticCandidateSupport`；
- 地空与古籍“天空地劫”不能精确同名绑定时的 `nomenclature_conflict` 状态。

空宫边界保持不变：本宫没有核心十二辅煞时，本宫 occurrence 就是空的；对宫和两组三合位只保留原关系，不借入本宫、不替本宫补星。禄存、天马、天空、其他 minor 与全部 auxiliary 仍是事实层成员，其 v0.12 基础／落宫候选保持 `null`，不会被 v0.13 动态包扩权。

## 4. 模板、隐私与只读预检

动态模板不包含直接身份标识、原始表单字段、用户备注、档案标题、请求 ID、Revision ID 或出生输入文本；但它包含四宫关系、星曜、亮度、四化等**派生命盘事实**。这些事实仍可能敏感，导出和对外分享必须由用户自行决定。

模板中的 SHA-256 只用于把来源登记、当前规则、当前事实、12 组 review、48 个有序 occurrence 和逐项完整快照绑定在一起。SHA-256 不是加密、签名、匿名化或审稿人身份证明；拿到文件的人仍能读取其中派生事实。

只读预检固定：

- 不写 Browser 工件、Revision、IndexedDB、localStorage、sessionStorage 或 Cache Storage；
- 不修改 mutation epoch，不绕过任何 CAS／事务边界；
- 审稿人身份为自述且未核验，无签名、无自动采纳；
- 不把 v0.13 决定继承到 v0.12 静态 12 条基础／144 条落宫候选，也不改动旧 v0.10 静态 48 项四化反馈面板；
- `formalActivationAllowed`、自动整合、网络提交、存储写入、直接结果与评分能力均为 `false`；
- `goodBadOrientation / eventOutcome / result` 全部保持 `null`；
- 即使 48 项全部由具名复核人填写，也不能自动成为正式内容、专家真值或科学有效性证据。

禁止按 `supporting_six / challenging_six`、星数、亮度、四化或 occurrence 数量加总，也不生成“吉星多所以吉”“煞星多所以凶”之类分数和结论。

## 5. Web 状态机边界

4218 页面中的 v0.13 面板属于当前整盘，和旧 v0.10 静态四化反馈面板完全分离：

1. 当前盘通过验真后，页面建立 12 组／标准 48 occurrence 的只读投影；
2. 用户显式准备模板后才允许下载，不自动上传或保存；
3. 用户选择本地 JSON 后，只在内存中做大小、结构、当前盘绑定、完整快照与摘要预检；
4. 切换三方四正焦点只更新当前可见证据，不使整盘模板失效；
5. 编辑输入、重新计算、重开其他档案、计算失败或异步旧请求迟到，都会清空旧动态范围与预检；
6. 篡改、错盘、漏项、乱序、额外字段、来源错配、几何规则错配或旧包导入新盘都必须失败关闭，并清空旧动态预检显示。
