## 4. 失败关闭门

保存 manifest 明确记录：

```text
bindingFrozenVerified = 0 / 12
independentExpertReviewsVerified = 0 / 2
sourceBundleComplete = false
rightsBundleComplete = false
expertReviewBundleComplete = false
releaseEvidenceComplete = false
publicDeploymentAuthorized = false
expertClaimsAuthorized = false
```

以下改动均会使验证失败：

- 删除或替换任一组件文件；
- 文件字节、文件 SHA-256、组件摘要或总摘要漂移；
- 删除组件或加入未知顶层字段；
- 把 0/12、0/2 直接改成完成；
- 把内容、专家或权利法律账改成已建立；
- 把 `engineering_candidate` 直接改成 `released`；
- 单独打开公开部署或专家主张授权。

## 5. 接入位置

`check:bazi-domain-release-manifest` 与 `check:bazi-source-binding-candidates` 已接入根级 `prebuild`、`pretest` 和 `pretypecheck`。因此默认构建、全量测试或全仓类型检查启动时，会先验证当前机器身份与来源候选锁；这些检查通过不代表后续完整命令通过。

验证器只读取固定的工作区相对文件闭包，不读取 manifest 提供的任意外部路径，不访问网络，也不接受 URL 作为组件文件。
