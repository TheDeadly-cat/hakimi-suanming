- `publicDeploymentAuthorized`：`false`

## 结论

v0.2 只关闭“跨体系人工观察如何保持显式分区、可追溯且失败关闭”的工程缺口。它没有生成跨体系结论，也没有把八字、紫微、西洋或吠陀的概念、规则、来源与权威合并。

## 七个精确分区

`observations` 必须且只能包含下列七个数组：

1. `convergences`：人工登记的表面共识观察；不代表真值、统计共识或概念等价。
2. `divergences`：人工登记的输出或观点分歧；不裁定赢家。
3. `inputSemanticConflicts`：出生时刻、地点、历法、时区或其他输入口径不能直接对齐的情况。
4. `schoolConflicts`：同一体系内或跨体系规则流派与版本前提不同的情况。
5. `evidenceQualityDifferences`：来源、许可、底本、版本、exact quote 或专家证据成熟度不同的情况。
6. `nonComparableConcepts`：明确登记不得自动映射的概念；`declared_concept` 依据只允许出现在本区。
7. `unresolvedQuestions`：依据仍不足，暂不能判断是否可比或是否存在冲突的问题。

空数组只表示“当前没有显式条目”，不能解释为体系一致、无冲突或已审定。

## 每条观察的固定边界

每条记录必须具有精确字段，并固定为：

- `entryMode = manual_explicit_entry_unverified`；
- `assessmentState = unreviewed_observation`；
- `conceptEquivalenceClaimed = false`；
- `expertTruthClaimed = false`；
- `modelArbitrationUsed = false`。

除 `unresolvedQuestions` 可只指向一个 included system 外，其余分区至少涉及两个体系。体系顺序必须与载荷的 canonical system order 一致，每个列出的体系至少有一条 `basisRef`。

## 可引用依据

依据只允许四类：

- `frozen_fact`：精确匹配当前摘要中的 `field=value`；
- `rule_identity`：精确匹配 `profileId@profileVersion`；
- `source_reference`：精确匹配当前摘要的 `sourceRefs` 项；
- `declared_concept`：只登记不可比较概念，不声明同义或等价。

依据必须解析到本载荷内已经包含的体系摘要；不能引用外部隐藏资料、另一个 Revision、另一个规则版本或未携带的来源。

## 禁止的综合方式

顶层必须同时保持：

- `noScoring = true`；
- `noWeighting = true`；
- `noMajorityVote = true`；
- `noModelArbitration = true`；
- `noAutoPersonMerge = true`；
- `noConceptEquivalenceInference = true`。

verifier 对顶层、体系摘要、事实、规则身份、人物关联、观察和依据引用都执行 exact-key 校验。增加 `score`、`weightedScore`、`weight`、`winner` 等字段，即使同步重算 canonical SHA-256，也不能通过。

## 当前示例不是领域结论

隔离样例只登记两条未审观察：

- 八字“财星”与紫微“财帛宫”不得自动等价；
- 两体系的输入时间边界是否可比较仍未解决。

这两条用来验证工程边界，不证明相关术数判断正确，也不证明两个体系实际存在或不存在某种关系。
