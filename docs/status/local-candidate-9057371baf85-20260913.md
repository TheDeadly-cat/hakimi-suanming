## 首次失败与修复

1. 新 AppData 安装路径被当前应用进程重定向到 Codex LocalCache。真实路径与声明路径不一致，检查正确拒绝；失败目录原样保留。候选默认安装与日志位置一起改到显式 USERPROFILE 下，没有绕过路径核验。
2. 外置 `.ts` QA 配置起初被按 CommonJS 加载，遇到 `import.meta` 在浏览器启动前失败；改为 `.mts`，没有减少测试或放宽断言。
3. 安装后的首轮真实完整流程两个浏览器均因控制台检查失败。启动器发送的 `Content-Security-Policy-Report-Only` 含有被忽略的 `upgrade-insecure-requests`。修订 4 只在候选 HTTP 响应中移除此无效指令，保留其他指令与响应头，原 `_headers` 文件及 Web 产物不变。[W3C 规范](https://www.w3.org/TR/upgrade-insecure-requests/#delivery)明确该指令在仅报告策略中被忽略。修复后原完整流程和 PWA 在安装入口复跑通过。
4. 补充 UI 身份脚本起初将静态 HTML 标题当成 React 最终路由标题；实际标题符合 `app.tsx` 的“工作台 · 哈基米八字研究台”合同。纠正 QA 预期后验证工作台与帮助页标题，未改应用。
5. 新源码工作区未安装依赖时首次治理检查在加载 `@playwright/test` 前失败；正常离线安装依赖后才取得实际治理 CLI 成功结果。
