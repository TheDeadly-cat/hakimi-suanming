## 修复为什么仍覆盖原目的

默认生命周期协调器明确拒绝 typecheck、test、build 的 root pre/post hook 和未知 Web build hook。根 hook 注入用例全部保留，按错误的 `message` 精确断言。涉及实际遍历的用例改在 `postcheck:release-governance` 或 `postpreview:release-artifact` 注入，以确保确实经过别名、前缀、workspace 和循环路径，再由原候选隔离规则拒绝；没有将它们改成“任意抛错即可”。

两个 CI 重复命令用例不再依赖人可读步骤名称，仍向 toolchain job 注入历史/当前检查，并要求原验证器指出命令跨 job 重复。三项计数断言之外，固定 canonical closure digest、原候选不可达项和正式回执 allowlist 都继续验证。

首次修复回归为 223/228，5 项仍失败：新增辅助断言用锚定正则匹配 Error 字符串，漏掉了 `Error:` 前缀。改为精确匹配 Error 的 `message` 属性后，完整文件 228/228，随后完整组 477/726。两次日志均保留，不用后一次覆盖首次失败。
