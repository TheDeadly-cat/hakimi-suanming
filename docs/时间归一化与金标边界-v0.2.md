# 时间归一化与金标边界 v0.2

> 状态：P0 实施决策  
> 目标：在排盘之前把“用户填写的墙上时间”、“可复算的 UTC 瞬时点”和“太阳时对照”明确分开，不做静默推测。

## 1. 不可变原则

1. 原始历法类型、日期、闰月标记、民用时间、IANA 时区、经纬度和精度始终原样保存。
2. 夏令时重叠时刻必须由用户选择较早或较晚偏移；默认 `reject`。
3. 夏令时空档时刻不自动“推到下一个有效时间”；界面先告知差异，再让用户更正。
4. 平太阳时和视太阳时始终与民用时并列展示，默认不改变活动命盘。
5. “宣称支持范围”与“金标强验证范围”是两个字段；没有审核证据时不得显示为已强验证。

## 2. 归一化输出

```text
原始墙上时间 + IANA 时区
  │
  ├─ 唯一时刻 → UTC instant + 实际偏移
  ├─ DST 重叠 → 两个候选 instant，等待 earlier/later
  └─ DST 空档 → 无候选 instant，拒绝计算

UTC instant + 经度
  ├─ 地方平太阳时 = UTC + 4 分钟 × 经度
  └─ 地方视太阳时 = 平太阳时 + 均时差近似
```

太阳时必须记录模型 ID、修正分钟、坐标精度和“近似值”警告。当日期或时辰跨界时，界面要主动标出“可能改变日柱/时柱”，但不自动切盘。

### 2.1 农历与闰月先解析、后校时

农历输入不是 IANA 墙上日期，不能直接送入 DST 解析。当前工作链路明确分为两步：

1. 保留 `calendarType=lunar`、农历 `YYYY-MM-DD` 与 `lunarLeapMonth` 原值；
2. 用固定 `lunar-typescript@1.8.6` 适配器把普通月或负号闰月转换为公历日期，并做公历→农历往返校验；
3. 把解析后的公历日期与用户原民用时间组合，再进入所选 IANA 时区的唯一/重叠/空档判断；
4. `CalendarResolution` 保存输入历法、原日期、闰月标记、公历日期、算法 ID、上游版本、固定 +08 历法框架、来源和警告；
5. 无效大小月、不存在的闰月、往返不一致或转换后越出 1900—2100 公历范围时明确拒绝，不猜测相邻日期。

这只是版本化工程口径。其输入/输出已经进入结果哈希、修订、备份和导出，但尚未计入独立权威金标。

### 2.2 `lunar-typescript@1.8.6` 的固定 +08 适配边界

该上游的节气计算在内部把时刻固定表示为 UTC+8 墙上时间，`Solar.fromYmdHms` 本身没有 IANA 时区参数。因此适配层不把纽约、东京或历史上海 DST 墙上时间直接与其节气字符串比较，而是：

1. 年柱/月柱：把已解析 UTC instant 投影到固定 `+08:00`，再调用上游精确立春/交节候选；
2. 日柱/时柱：使用用户所选地本地民用时与显式换日规则；
3. 时干：从最终显示的日干和时支重新推导，不借用上游在另一换日口径下的时干；
4. 十神、藏干、五行、纳音、十二长生、旬和空亡：全部从最终混合四柱重建，并记录独立 provenance。

这一适配修正了明确的时区输入错位，但在 360 例金标发布门通过前仍只是工程候选。

### 2.3 秒级边界输入

`BirthInput.timePrecision=exact_second` 使用严格 `HH:mm:ss`，归一化、UTC 瞬时点、结果哈希、案例修订与备份均保留秒。网页排盘入口可直接填写秒级时间；分钟输入仍必须使用 `HH:mm`，两种精度不能混写。该通路用于证明交节前一秒、当刻和后一秒的归属语义，不代表对应期望值已经获得权威复核。

## 3. 首批时间边界 fixture

| 分类 | 固定输入 | 必验结果 |
| --- | --- | --- |
| 普通时区 | `1995-08-18 08:26 Asia/Shanghai` | 唯一 instant，偏移 `+08:00` |
| DST 重叠 | `2024-11-03 01:30 America/New_York` | reject 得到两个候选；earlier/later 相差 60 分钟 |
| DST 空档 | `2024-03-10 02:30 America/New_York` | reject 且不生成活动 instant |
| 45 分钟时区 | `2024-01-01 12:00 Asia/Kathmandu` | 偏移 `+05:45` |
| 日期线 | `2024-01-01 00:30 Pacific/Kiritimati` | 偏移 `+14:00`，UTC 日期为前一日 |
| 真太阳跨日 | 上海时区 + 时区西缘经度 + 零点附近 | 民用日期不变，太阳时可并列显示前一日 |
| 农历普通月 | `1995-07-23` 农历、非闰月 | 显式解析为 `1995-08-18`，原农历仍保留 |
| 同名普通/闰月 | `2023-02-01` 农历 | 普通二月为 `2023-02-20`；闰二月为 `2023-03-22` |
| 无效闰月 | `2024-01-01` 农历并勾选闰月 | 明确拒绝，不退化为普通正月 |

这些只是时间归一化底座的首批样例，不等于 360 例排盘金标已完成。

## 4. 发布门

- 上述 fixture 在 Node 和目标浏览器的输出一致；
- 重叠/空档在界面上有可操作的确认路径；
- 时间校准快照进入结果哈希和备份；
- 不同时区数据库或引擎版本可并列复算，不覆盖旧修订；
- 太阳时模型更换会改变规则快照与结果哈希。

2026-08-03 工程状态：普通新推导使用 IANA 2026c，registry 保留 2025b。CandidateSet 可按两份数据并列复算；本命盘只读复演 v1 当前只登记 bazi 0.4.0 六字段 executor，可按 exact bundled 2026c/2025b 从冻结输入重算 time calibration、luck rule、facts 与 hash。完整性先验后，未知 engine、legacy tzdb、工件/descriptor、规则/精度/DST 问题均失败关闭；研读页 exact-only 且零写入。Edge CandidateSet 1/1、Edge 2026c Revision 复演 1/1、tzdb 58/58、全量 101 文件/1168 项及两种构建通过。关系/luck/流年/Transit 历史执行器、其他 bazi engine、Chrome、Firefox、固定 Android 仍未完成，因此不能标记 v1 通过。
