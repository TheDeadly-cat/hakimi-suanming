## 1. 本轮目标

v0.9 已冻结四化 × 十二宫的 48 条位置化候选，但用户或受邀研究者还没有一份可离线填写、再回到 4218 做严格预检的反馈合同。

v0.10 补齐一条不依赖专家授权即可安全推进的内部通道：

1. 从当前 48 条候选确定性生成完整 JSON 模板；
2. 同时绑定候选快照、有序内容 ID 与五来源登记的 SHA-256；
3. 允许逐项填写流派、裁决理由、成立条件、反例、退修要求和补充 HTTPS 来源；
4. 允许提出“条件满足时可能偏支持／挑战、正反并见、证据不足”等方向提案；
5. 回到 4218 后只做内存预检与展示，不写 Browser 工件、Revision、IndexedDB 或 mutation epoch；
6. 即使 48 项全部裁决，也不把提案提升为正式吉凶或自动整合。

这是一条“收集可归属、可反驳的审稿意见”的工程通道，不是专家认证系统或内容发布系统。

## 3. 确定性反馈合同

当前模板绑定值：

```text
contentVersion: ziwei.natal_transformation_all_palaces.neutral_candidate/0.1
matrixSha256: 6cadd7a56208cbe403b834b506618bc4846aa8488bab6df10468c62f339198b6

itemCount: 48
sourceCount: 5
```

每项不可改写的候选快照包括：

- 内容 ID、顺序、四化标签与宫位角色；
- 通用四化候选 ID 与宫位问题域候选 ID；
- 位置化短解、反向提醒、专家问题与五个来源定位。

可填写字段限定为：

- `reviewer`：审稿人 ID、显示名、机构、自述专业背景、可选身份证据引用；
- `reviewSession`：ISO 审稿时间、方法、流派范围与总备注；
- `decision`：`unresolved / approve / revise / reject`；
- `orientationProposal`：`unresolved / potentially_supportive / potentially_challenging / mixed_conditional / not_assessable`；
- `selectedSchool`、`decisionReason`、`applicabilityConditions`、`counterexamples`；
- 只在 `revise` 时允许的 `revisionRequest`；
- 去重的 HTTPS 补充来源；
- 与逐项值完全一致的裁决及方向提案声明计数。

任何已裁决项都必须同时给出非空流派、理由、成立条件和反例；方向提案不能仍为 `unresolved`。任何人类输入出现后，都必须完整提供 reviewer ID、显示名、自述专业背景、有效 ISO 时间、方法与流派范围。

## 4. 固定关闭边界

模板、逐项记录、根边界和预检结果都保持：

```text
identityVerified: false
digitalSignatureVerified: false
eligibleForFormalActivation: false
autoIntegrationAllowed: false
artifactRevisionOrStorageMutationPerformed: false
goodBadOrientation: null
eventOutcome: null
result: null
```

`orientationProposal` 只是带条件、待核验的审稿建议，不等于 `goodBadOrientation`。全 48 项均为 `approve` 也不会改变上述关闭字段。

预检严格拒绝：

- 非法 JSON、额外／缺失字段、Profile 或版本失配；
- 非 48 项、顺序或候选快照变化；
- 三个摘要、五来源登记或声明计数失配；
- 未裁决项带裁决内容，或已裁决项缺流派、理由、条件、反例和方向提案；
- `revise` 缺退修要求，或非 `revise` 项带退修要求；
- 补充来源不是 HTTPS 或出现重复；
- 任一身份、签名、正式激活、自动整合、存储 mutation 或正式结果字段被打开。

UI 只读取 `.json`，使用 `TextDecoder("utf-8", { fatal:true })`，文件必须为 1 字节至 2 MiB。每次导入先清空旧有效结果；非法文件会回到 `0 已裁决 / 48 未裁决`，避免旧状态残留。

## 5. 4218 页面行为

页面在档案区与备份区之间新增“四化 × 十二宫 · 48 项审稿反馈”：

- 下载当前源码确定性生成的完整模板；
- 用真实 file chooser 导入已填写 JSON；
- 显示总数、已裁决、未裁决及“自述，未核验”的审稿归属；
- 每个已裁决项直接显示宫位、决定、条件化方向、流派、理由、成立条件、反例、退修要求和补充来源；
- 面板与卡片都用 data 属性暴露全部关闭边界，便于浏览器门核对；
- 文件只在当前页面内存中预检，不保留，不接入档案 repository。

应用内 Browser 的既有独立库基线为 `revisionCount 0 / mutationEpoch 5 / totalBytes 0 B`。有效导入、篡改导入前后均保持 `0 / 5 / 0 B`；这里的 epoch 5 是已有历史状态，不是本轮写入。
