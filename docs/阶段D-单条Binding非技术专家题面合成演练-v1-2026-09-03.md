# 阶段 D：单条 Binding 非技术专家题面合成演练 v1（2026-09-03）

## 结论

本 tranche 新增一条与既有五场景 usability pilot 分离的、固定合成题面的单条 Binding 中文演练。它让不懂代码或 AI 的命理专家排练“看材料边界—作答—口述代录—逐字读回—完成确认”的现场流程，但不复用 formal successor 的 `binding_freeze_evidence` purpose，也不授权输入现实专家、私人来源或真人案例。固定 fixture 为 synthetic-only；专家自由文本始终按 `unassessed_private` 处理，不能把页面用途约束误写成所有自由文本已经验证为合成。

固定治理保持：

```text
releaseIdentity = legacy-v13
targetSchema = 13
migrationId = null
publicDeploymentAuthorized = false
expertClaimsAuthorized = false
```

当前正式账没有变化：现实专家 `0/2`，冻结 Binding `0/12`，`formalAdmissionAllowed=false`，formal 2/2 与 expert gate delta 均为 0。

## 专家看到什么

入口位于：

- `isolated-drafts/bazi-expert-review-pilot/single-binding-rehearsal-a.html`
- `isolated-drafts/bazi-expert-review-pilot/single-binding-rehearsal-b.html`

页面固定只显示 `binding:policy:thresholds` 的合成题面：25%、43%、57%、75% 四个候选分界，以及 42%／43%／57%／58% 四个临界例子。它同时列明：

- 审什么：候选分界是否讲得通、成立条件、反例／缺失证据和高风险表达；
- 不审什么：真人命盘、专家与 AI 准确度、许可法律、发布、其余 11 条 Binding 和其他体系；
- 已有材料：固定候选值、合成临界例子、用词说明和范围说明；
- 缺失材料：可靠案例集、冻结底本／版本／exact quote、三层权利、两位现实独立专家和 12 条正式冻结 Binding。

“目前无法判断”被细分为材料不足、题意不清、超出流派、来源／版本不清和其他原因。材料不足不被强迫改成支持或反对。页面会阻断明显联系方式、身份、数字／中文日期、现实案例和准确度／样本命中叙述；该词法预检并不证明个人资料或准确度材料已被完全排除，仍固定 `personDataPresenceAssessed=false / personDerivedDigestExcluded=false / freeTextSyntheticOnlyVerified=false`。

固定题面另有独立的 `synthetic_rehearsal_manifest_identity_only` 身份，精确绑定 `evidenceSubjectId`、synthetic candidate ID／digest、`candidateStatusCode=pre_freeze_candidate`、`formalBindingDigest=null`、完整 fixture content digest、question-set digest 和 synthetic manifest digest。完整 fixture snapshot 也进入 readback seed；改变题目、已有／缺失材料或临界例子会改变对应摘要。该身份明确固定 `formalReviewInputManifestAuthorityEstablished=false / currentWorkspaceCandidateIdentityVerified=false`，不能冒充 formal successor 的 current input manifest。

## 现场记录和逐字确认

页面要求明确选择：

- 专家本人输入；或
- 专家口述、协调人逐字代录。

代录路径必须自述没有概括、润色、替换项目术语或代替专家选择答案。协助披露使用受控类别：未使用、其他人、书籍／资料、AI／软件、不确定或不披露；它只记录自述，固定 `externalAssistanceExcluded=false`，不把勾选框当成真实性证明。

完成前先生成当前进程内 branded readback candidate。逐字核对稿包含全部专业文字、填写方式和协助披露；专家必须本人通读，或由协调人逐项读回后确认。任何实质字段变化都会使旧 readback digest 失效并要求重新生成。最终确认仍只是自述，固定 `reviewerReadbackVerified=false / opinionAuthenticityEstablished=false`。

## A/B 与准确度边界

A/B 使用两个独立 HTML 入口。seat-specific loopback server 只提供选定席位的入口和三项共同静态资源，另一席 URL、原件、状态和意见均不提供。页面没有文件、粘贴、storage、上传、赢家、投票、平均、自动合并或模型裁决接口。

这不是准确度研究：没有作者标签随机化、结果标签、预注册评分、真实案例或专家／AI 表现比较。因此持续固定：

```text
authorshipBlindingEstablished = false
expertVsAiAccuracyEvaluated = false
predictiveAccuracyEvaluated = false
accuracyStudyRecordEmitted = false
```

未来如需评估“专家、AI、专家复核后的 AI”，必须另立独立协议和证据账，不能使用本题面或 formal 2/2 内容审定替代。

## 工程记录与 formal 拒绝

本 tranche 只产生三个独立 rehearsal 类型：

```text
bazi_expert_single_binding_nocode_rehearsal_draft_v1
bazi_expert_single_binding_nocode_rehearsal_readback_candidate_v1
bazi_expert_single_binding_nocode_rehearsal_submission_candidate_v1
```

它们已加入 formal successor 的 pilot／rehearsal deny inventory；不能直接改名、重摘要或作为 v3 outer record type 输入。deny test 另以三条独立字面量固定，避免生产常量误删时测试同时消失。

外层 deny list 无法查看 `encryptedPayloadBase64` 内部。此前任何字节都能被重包装进外层 v3 envelope，并在 link-only 行上得到 `eligibleAsStageCBindingEvidenceCandidate=true`。当前 successor 已把无可信解密、解密后 schema／record type、来源认证、真实性、first-seen 和 custody 的状态降为纯结构观察：三项 usability／Stage-C／formal eligibility 全部固定 `false`，repository projection 必须携带 `private_payload_uninterpreted_no_evidence_eligibility`。新增负例把 rehearsal submission JSON 作为 base64 payload 重包装后，仍只能得到结构先决条件满足、正式 eligibility false、计数 delta 0。这是刻意的 fail-closed 能力收缩；未来只有新增可信解密与真人认证门后，才可另开正向版本。
