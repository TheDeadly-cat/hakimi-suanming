# ADR-0001：吠陀占星保持独立研究、暂不集成

- 日期：2026-08-26
- 状态：accepted-research-boundary
- productStatus：`research-only`
- integrationStatus：`not-integrated`
- authorityStatus：`not-authoritative`
- publicReleaseAuthorized：`false`

## 决定

当前不在八字生产壳、`legacy-v13` 数据库、full v1.2 备份、Service Worker、主应用路由或跨体系只读预览中加入吠陀占星。不得借用八字、紫微或西洋的工程、来源、专家或权利证据为吠陀体系背书。

在独立准入门关闭前，不创建占位计算结果、空数据库分区、伪成功回执、用户可点击入口或“综合命运”输出。

## 独立输入门

未来输入契约至少必须显式冻结：

- 原始民用出生时间、地点、IANA 时区、DST 歧义和时间不确定区间；
- UTC 转换、历书/星历版本与时间尺度；
- sidereal zodiac 与 ayanamsa；
- Rahu/Ketu 采用 mean 还是 true；
- Bhava/宫位口径；
- 出生时间扰动的候选集合和跃迁点。

任何缺失或歧义都必须结构化阻断，不能由默认值或生成模型补猜。

## 独立事实与规则门

未来事实和规则必须分别版本化。候选范围至少包括 D1、D9、D10 等分盘、Vimshottari Dasha、Chara Karaka、Shadbala 与 Ashtakavarga；本 ADR 不确认这些方法的具体实现、流派取舍或内容真值。

规则层必须声明流派、适用条件、冲突、反例、来源、版本和摘要。不得把工程权重、稳定性分数或格式化结果包装为传统原文或专家结论。

## 来源与权利门

现有外部审计只允许 clean-room 吸收 canonical reader、fail-fast、输入稳定性和渐进证据读取等通用工程思想。

禁止直接复制或嵌入外部 Vedic 项目的 `SKILL.md`、prompt、resources、references、输出文案、图表、OCR/PDF、专有知识内容或数据。已观察到的 AGPL 与额外商业限制必须由独立权利/法律复核解决；本 ADR 不作许可兼容或商业使用结论。

正式来源包必须逐项建立作品、版本、载体三层身份与许可记录。权利未知或不允许再分发的材料只能 private、link-only 或不存储。

## 运行时与部署门

是否接受 Python、Swiss Ephemeris、数据文件和额外 Worker/服务尚未决定。未来提案必须量化：

- Web/PWA 本地优先体积、首次加载、离线和更新成本；
- 浏览器内实现与本地服务实现的安全、隐私和可复现性；
- 代码许可、星历数据许可和再分发条件；
- Edge/Chrome 及目标设备的独立测试矩阵；
- 独立数据库、备份、恢复、mutation epoch、容量和回滚方案；
- 独立 Release Evidence 与长期证据保存。

不得为了复用现有 v13 发布管线而把吠陀数据写入八字 Schema 13。

## 现实专家与高风险表达门

吠陀体系必须有其范围内的现实专家，不得由八字或西洋专家顺带签署。至少两名专家的身份、资质、彼此独立性和原始意见必须分别核验、不可变保存；分歧不得多数表决、平均或由生成模型选赢家。

在专家和来源门关闭前，任何输出只能是工程诊断或研究候选，不得生成健康、法律、财务、生死、灾祸等高风险断言，也不得声称科学有效性或预测准确率。

## 跨体系边界

当前 `@hakimi/cross-system-comparison-draft` 只包含八字、紫微和西洋的隔离只读摘要，吠陀不得在没有独立冻结事实摘要和准入决定时加入。

即使未来加入，也只能并列展示：各体系事实、来源、证据质量、输入语义冲突、流派分歧和不可比较项。禁止把八字财星、紫微财帛宫、西洋第二宫与吠陀 D2/Hora 直接视为同一概念，禁止权重、平均、投票或综合分数。

## 重新评审条件

只有在以下材料全部出现后才重新评审集成：

1. 本项目自己的输入、事实和规则草案；
2. 运行时与体积提案；
3. 作品/版本/载体三层来源权利账；
4. 至少两名目标范围现实专家的可核验审阅计划；
5. 独立数据库、备份、恢复与回滚设计；
6. 独立浏览器质量门和 Release Evidence 设计；
7. 所有者对产品范围、许可和部署边界的明确决定。

在此之前，本 ADR 只证明“拒绝静默集成”的产品决定，不证明吠陀占星的工程可行性、内容真值、专家真值、许可结论、发布就绪或公开发布授权。
