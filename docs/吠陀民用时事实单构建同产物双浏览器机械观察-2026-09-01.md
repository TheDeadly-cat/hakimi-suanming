日期：2026-09-01

## 1. 产物定位

本文件记录一个隔离的、synthetic-only 的 civil-time fact-only 工程观察 child。它只回答：一次受控 Vite 构建产生的同一 output tree，是否由自有 loopback 静态服务器以相同 body 身份送达本机 Google Chrome 与 Microsoft Edge，并在两个浏览器各完成五个固定场景。

它不是正式产品、正式 Release Evidence、生产浏览器回执、内容权威、专家意见、来源许可结论、发布就绪或公开发布授权。它不更新 parent、registry、domain manifest、browser-quality design，也不继承项目默认 `legacy-v13 / targetSchema 13 / migrationId null`；该三元组仅作为项目上下文保存，新 child 的 product/release/targetSchema/migrationId 均为 `null`。

正式候选路径：`content/system-admission/vedic-civil-time-same-artifact-browser-observation-child.v1.0.0.json`

当前状态：正式候选已由第十一次矩阵按 raw origin-form 路由 P2 修订重签，但其状态仍为 `isolated_fact_only_single_build_dual_browser_observation_not_admitted`；它没有取得 public release / public deployment / expert claims 授权。

## 2. 固定浏览器场景

每个浏览器必须 exact 5/5、合计 10/10，`workers=1`、`retries=0`：

1. `unique`：唯一民用时产生 fact-only 投影；passed、结果容器可见、错误容器隐藏、10 个事实槽均非空；随后输入变化使结果隐藏且 10 槽全空。
2. `gap`：先产生并逐项确认 10 槽非空的 unique 投影，再用不派发 input/change 事件的 synthetic DOM setup 写入 gap；点击执行前旧投影仍可见且 10 槽仍非空，失败完成后结果隐藏、10 槽全空、错误文本 exact。
3. `overlap_reject`：与 gap 相同的旧投影与 synthetic DOM setup 证据；默认 reject 的失败完成态无可见部分事实，错误文本 exact。
4. `overlap_earlier`：passed、结果可见、错误隐藏、10 槽均非空，并校验较早瞬时点的 exact UTC、offset 与 decision 文本。
5. `overlap_later`：passed、结果可见、错误隐藏、10 槽均非空，并校验较晚瞬时点的 exact UTC、offset 与 decision 文本。

这里的 gap/reject 证据证明“带着已观察到的旧投影进入失败执行链，失败完成态所有可见事实槽为空”。它不外推为 Worker response 内部一定没有 partial facts，也不把未观察的 running 瞬间写成机械事实。

spec、sanitized reporter 与 Playwright config 由三个 exact role/path/bytes/SHA-256 binding 固定。runner 在构建前机械检查这些 exact bytes；仅有 10/10 结果而固定断言文件已漂移时，必须失败关闭。

## 3. 单构建与来源边界

构建命令只允许显式使用 `apps/web/node_modules/vite/bin/vite.js`，Vite 版本固定为 7.3.6，config loader 固定为 `runner`。不能使用根目录 Vite 8.x 或裸 `vite` 解析。

`expectedAuthoredBuildInputClosure` 是 24 个 authored/non-installed 文件的静态审计闭包，包含：

- 根 `package.json`、`package-lock.json`、`tsconfig.json`、`tsconfig.base.json`；
- isolated draft 的 package、tsconfig、HTML、base/wrapper Vite config、`styles.css`；
- civil-time 主线程、Worker、协议、输入合同、UI 投影等 10 个 TS 文件；
- tzdb-core package、index、packed resolver 与 retained `iana-2025b` adapter。

24 路闭包只做 pre/post/current 端点 hash 对账，明确不是 Vite main/Worker module-load telemetry，也不是“Vite 实际读取全集”。因此：

- `viteMainAndWorkerModuleLoadTelemetryEstablished=false`；
- `completeSourceToBuildAttestationEstablished=false`；
- `crossFileAtomicSnapshot=false`；
- `intervalMutationExcluded=false`；
- `abaExcluded=false`。

base Vite config 的 17 个 locked input 逐项绑定 stable role、workspace-relative path、bytes、SHA-256，并由 runner 做 pre/post/current 对账。base plugin 的 `buildStart` exact preflight 只属于主 build；它不建立 Worker same-buffer、全时段 lock、跨文件原子性、interval integrity 或 ABA 排除。

base 临时 build manifest 中两个 `concurrentSameAccount...Excluded=true` 只作为既有 manifest shape/产物字段被机械校验。本 child 不据此提升 loaded-config same-buffer、Worker same-buffer、interval、ABA 或跨文件原子性，相关 child 字段仍全部为 false。

## 5. output tree 与 served-body 分账

一次构建必须得到 exact 12-file output tree：index、main JS/map、CSS、Worker JS/map、retained IANA JS/map、临时 build manifest 与三份 license。output tree 在浏览器矩阵前后必须逐文件 bytes/SHA-256 与 tree digest 相同。

服务端由 runner 在动态分配的 `127.0.0.1` 端口启动，不使用公开主机、Vite preview、PWA 或 Service Worker。它先从 output snapshot 读取并持有受控 body Buffer；每次 response 的 bytes/SHA-256 由实际传给 `response.end` 的同一 Buffer 计算和记账。

逐浏览器 ledger 严格分成：

- `scenarioRuntimePaths`：index、main JS、CSS、Worker JS，共 4 类自然场景请求；
- `evidenceOnlyOutputBodyProbePaths`：retained `iana-2025b` chunk，共 1 类。

五个场景均固定使用 current 2026c snapshot，正常 resolver 不会自然执行 retained 2025b chunk。IANA body 只由 unique 场景用 exact query marker `?hakimi-vedic-evidence-only=1` 作顶层 evidence-only navigation；该 response 强制使用 `text/plain; charset=utf-8`、`Content-Disposition: inline` 与 `nosniff`，Playwright 读取完整 body 后只断言 byteLength 非零，因此不会把 chunk 当脚本执行。无 marker 或 marker 错误的 retained chunk 请求必须计入 `unmarkedRetainedChunkResponseCount` 与 unexpected 并失败关闭。因此候选只允许：

- `retained2025bChunkScenarioRuntimeRequested=false`；
- `retained2025bChunkEvidenceOnlyBodyProbeObserved=true`；
- `retainedIanaChunkExecutedByCivilResolverEstablished=false`。

服务端还固定每个 body variant 的 responseCount、逐浏览器 natural/probe/combined manifest digest，并要求 aggregate response count 等于两个浏览器分项之和。wrong method、无/错 project header、非法/未知 path、非 exact query、无 marker IANA、body mismatch 与 handler failure 都必须进入对应失败计数；成功候选中 unattributed/unexpected/bodyMismatch/unmarked 四项均为 0。

## 6. 浏览器版本与清理时序

Chrome 与 Edge 使用 Playwright exact `channel: chrome` / `channel: msedge`。版本由各 channel 在矩阵前后分别启动、读取并关闭；版本前后必须一致。该证据是 pre/post endpoint observation，不是每个 test process 的 direct capture，也不排除 interval mutation 或 ABA。

runner-owned UUID root 位于系统 temp；该 root 同时成为子进程 `TEMP/TMP/TMPDIR`。build output、Vite cache、Playwright output、sidecar 与浏览器临时资料均限制在该 root 或其严格子目录。trace、screenshot、video、download 均关闭。

签发顺序必须是：Vite CLI 退出 → Playwright CLI 与其受控浏览器退出 → 版本 probe handles 关闭 → server 停止 → 原端口重新 bind/close 验证释放 → output/source/tool/lock post endpoint 读取完成 → UUID temp root 无 link 安全删除并确认不存在 → 才在 OS temp 以 `wx` 写 sanitized candidate。正式 workspace candidate 只能由代理读取该 sanitized bytes 后用 `apply_patch` 新增；不得由 runner 直接写工作区。

失败路径不生成正式 candidate；不得把 raw Playwright report、error、stdout/stderr、attachment、media、download、输入或临时根复制进候选。
