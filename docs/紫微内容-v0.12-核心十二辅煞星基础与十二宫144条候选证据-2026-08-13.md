## 1. 目标与范围

v0.11 已把十四主星、宫位问题域、本命生年四化和三方四正组织成四段式直读，但辅曜、煞曜和杂曜仍只有名称、位置、亮度与四化事实。若直接按 `minor` 类别、星数或传统“六吉／六煞”给分，会把上游事实分类、传统分组和个人结果混成一层。

v0.12 因此只冻结十二个精确星键，先建立 12 条来源绑定的基础中性候选，再与十二宫问题域形成 `12 × 12 = 144` 条落宫候选。当前盘只为真实命中的精确星键附加候选；其他星继续显示事实，不补写语义。

2. 右弼 `ziwei.star.iztro.youbi-min`

4. 文曲 `ziwei.star.iztro.wenqu-min`
5. 天魁 `ziwei.star.iztro.tiankui-min`
6. 天钺 `ziwei.star.iztro.tianyue-min`
7. 擎羊 `ziwei.star.iztro.qingyang-min`
8. 陀罗 `ziwei.star.iztro.tuoluo-min`
9. 火星 `ziwei.star.iztro.huoxing-min`

11. 地空 `ziwei.star.iztro.dikong-min`
12. 地劫 `ziwei.star.iztro.dijie-min`

协议字段使用 `factCategory: "minor"`，表示 Hakimi 对 `palace.minorStars` 的事实投影；它不冒称 iztro `FunctionalStar.type`。传统 `supporting_six / challenging_six` 各六条，只作来源绑定的编辑元数据，并固定 `traditionalClusterIsOutcome:false`。

禄存、天马虽也来自 `minorStars`，但不在本轮白名单；其他 `minor` 与全部 `auxiliary` 同样保持两个候选字段为 `null`。iztro 同时存在“地空”和独立的“天空”；古籍篇名“天空地劫”登记为 `nomenclature_conflict`，`semanticCandidateSupport:false`，不得把“天空”按标签别名命中“地空”。

## 4. 12 条基础候选与 144 条落宫候选

每条基础候选固定包含：精确星键与标签、三个中性主题、白话说明、反向提醒、专家复核问题、两个来源定位、事实投影边界，以及全部关闭的结果字段。

每条落宫候选同时绑定：

- 基础星曜候选 ID；
- 十二宫问题域候选 ID 与标签；
- 星曜 × 宫位的位置化摘要；
- 星曜来源与宫位来源，共四个去重来源引用；
- `requiresCombinationReview:true`，要求继续合看主星、亮度、本命生年四化、同宫与三方四正。

所有 156 条候选均固定：

```text
goodBadOrientation: null
eventOutcome: null
result: null
reviewStatus: awaiting_expert_review
publicationStatus: isolated_candidate_only
expertTruthClaimed: false
directOutcomeAllowed: false
scoringAllowed: false
```

面向用户的直读主题与位置摘要另有高风险结果词门，覆盖灾祸／伤残、疾病／寿命、妊娠／婚育、财富／就业、关系／身份及心理诊断／人格定型等直接结果表达；专家复核提示仍可用明确否定句说明这些禁区。面向用户的反向提醒使用另一道惊吓性断语门，避免为了否定而重复事故、暴力、破财或诊断性词汇，并统一改成现实事件、财务处境、心理状态或长期结果等中性边界。

## 5. 亮度、四化与失败关闭

亮度按“精确星键 × 当前地支”登记十二支矩阵，而不只判断这颗星能否有亮度。文昌、文曲、火星、铃星十二支各有冻结值；擎羊在寅、巳、申、亥和陀罗在子、卯、午、酉必须为 `null`；左辅、右弼、天魁、天钺、地空、地劫十二支全部为 `null`。`brightnessCanAppear` 仅保留为界面兼容摘要，实际守门只认 `brightnessByEarthlyBranch`。本命年干四化只允许：左辅壬科、右弼戊科、文昌丙科／辛忌、文曲己忌／辛科；另外八星不得补写四化。

矩阵按项目规范地支顺序 `子、丑、寅、卯、辰、巳、午、未、申、酉、戌、亥` 固定：

| 星曜 | 十二支亮度 ID |
| --- | --- |
| 左辅、右弼、天魁、天钺、地空、地劫 | 全部 `null` |
| 文昌 | `de, miao, xian, li, de, miao, xian, li, de, miao, xian, li` |
| 文曲 | `de, miao, ping, wang, de, miao, xian, wang, de, miao, xian, wang` |
| 擎羊 | `xian, miao, null, xian, miao, null, xian, miao, null, xian, miao, null` |
| 陀罗 | `null, miao, xian, null, miao, xian, null, miao, xian, null, miao, xian` |
| 火星、铃星 | `xian, de, miao, li, xian, de, miao, li, xian, de, miao, li` |

iztro 原数组使用寅起顺序，项目冻结规则层已重排为子起顺序；单测又把本模块矩阵逐行与当前已验真 `ruleSnapshot.rules.brightnessTable` 比较，避免只靠另一份手抄常量自洽。

投影必须同时核对 stable ID、中文标签、`factCategory` 和当前地支，并验证实际亮度／四化是否与上述精确事实一致。非白名单星正常返回两个 `null` 候选；白名单星的标签／类别错配、把天空别名当成地空、未知地支、错误的亮度值或错误地把应为空的格子填值，以及非法四化，都会抛错失败关闭。两条路径都不按类别广播内容。

## 6. 4218 只读展示

当前盘的四组三方四正事实卡会只为实际命中的十二星显示基础与落宫候选；逐宫直读包显示相同命中的紧凑摘要；v0.11 四段式之后显示独立的核心十二星补充区，不修改四段式自身的主星绑定、计数或结果合同。传统分组旁明确标注“分组不是个人吉凶结果”。

盘面中的非核心 `minor` 和全部 `auxiliary` 继续可见，但候选 ID 为 `null`。计算与切宫只派生内存显示，不创建 Revision、不写 IndexedDB／localStorage／sessionStorage／Cache，也不推进 mutation epoch。

## 10. 下一目标

v0.12 已补齐“精确十二星 × 十二宫”的语义原子及当前盘只读呈现，但它还不是专家规则：

1. 下一安全项应为**当前盘核心十二星三方四正动态审稿包**：逐 occurrence 绑定真实星曜事实、基础／落宫候选 ID、关系宫位和两个事实摘要，保留冲突，不按星数或传统分组计分。
2. 随后提供与当前盘快照绑定的离线审稿反馈模板和只读预检；身份未核验、无签名，不自动写规则、Revision 或正式入口。
3. 具名专家可按流派逐项提交成立条件、反例与条件化方向；只有经过独立代码审查和明确发布授权后，才讨论是否形成正式内容版本。
4. 八字身强身弱、十神／神煞位置语义和西洋当前盘动态内容继续是独立内容线，不能从本轮紫微候选推导。
