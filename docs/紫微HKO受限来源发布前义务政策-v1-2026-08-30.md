# 紫微 HKO 受限来源发布前义务政策 v1

日期：2026-08-30

## 1. 结论

本轮新增的是一项**必须在紫微构建前现场执行、但不保存“最近一次通过”结论**的独立发布前义务政策。它把 HKO 2023–2028 公农历来源材料的双隔离构建排除门固定接入两个紫微构建生命周期和 Quick CI，并由发布治理静态检查这些接线没有被删除、绕过、容错或重排。

这不是来源许可结论、来源冻结、内容真值、专家审定、正式 Release Evidence、发布就绪或公开发布授权。

## 4. 三层分账

### 4.1 持久化政策

以下文件持久化的是“每次必须重跑”的义务：

- `content/system-admission/ziwei-hko-restricted-source-pre-release-policy.v1.json`
- `scripts/ziwei-hko-restricted-source-pre-release-policy-lib.mjs`
- `scripts/formal-npm-lifecycle-closure-lib.mjs`

政策固定：

- `mustExecuteFresh = true`
- `historicalPassMaySatisfy = false`
- `gateFailureModeWhenExecuted = fail_closed`
- `preLifecycleCannotBeSkippedEstablished = false`
- 两个紫微构建表面的 `prebuild` 接线
- 两个表面的实际 `build`、`preview` 命令及其 Vite config 精确值
- Quick CI 中 exact one check、exact one test、顺序和 fail-closed 要求
- Quick CI `toolchain-and-boundaries` 目标 job 的 2,300-byte 结构身份与 SHA-256 `c11c430b0642e9bb7f593df4eef220a2ede751e721cb7e7fb969c6ec5afaa73e`
- 新增 root package `build:ziwei-*` 或 `preview:ziwei-*` 入口必须显式登记；当前 root package 受保护命令的别名也必须登记
- live gate 的库、CLI、拒绝测试以及共享 npm/lifecycle 闭包解析器的精确 bytes/SHA-256

policy 原始 JSON 在进入语义校验前必须通过 strict UTF-8、无 BOM、无重复键解析。Verifier 同时拒绝 Proxy、getter、隐藏 `__proto__`、循环、非原生数组、symbol-key 或额外 implementation artifact、代理 Buffer 和非精确 build/preview 别名。

真正的双隔离构建只由 live gate 在当前时点执行。一次 exit 0 只说明该次运行针对当前登记的精确表示通过；下一次构建仍必须重跑，历史通过不能代替未来运行。

### 4.3 正式发布证据

本政策没有加入：

- default-v13 正式回执 allowlist
- 紫微独立 Manifest 的准入字段
- 四体系中央 registry
- 既有 iztro notice evidence 的父绑定

因此它不构成正式 Release Evidence，也不会让紫微草案进入八字默认发布闭包。

中央发布治理与本政策共用同一 npm/lifecycle 闭包解析器；本政策不接受调用者传入的闭包结论，而是从 default-v13 receipt、root package、Web workspace package 和正式浏览器 embedded commands 独立重算**静态命令与 npm/lifecycle 引用图**。即使调用者附带自洽但伪造的空闭包，也不能遮蔽 root、workspace、prefix 或 embedded command 的 HKO 间接别名。

静态模型只接受当前精确登记的 28 条终端命令；任意新 Node wrapper、`node -e`/loader/import、未知 Vite/Playwright/Vitest config、shell 动态构造以及 npm `--` 参数透传均失败关闭。缺失的可选 `pre*`/`post*` 探针会保留为已尝试状态，但后来若被正式命令要求，仍必须报错，不能被“已访问”缓存遮蔽。

这仍不等于有效 npm 运行时闭包：环境中的 `NPM_CONFIG_WORKSPACE(S)`、`NPM_CONFIG_IGNORE_SCRIPTS`、`SCRIPT_SHELL`、`USERCONFIG/GLOBALCONFIG`、`NODE_OPTIONS` 等尚未由受控 launcher 中和；已登记终端模块或 config 的传递执行也未作全调用图证明。因此政策把这些结论固定为 false。政策不持久化父闭包的精确摘要；紫微独立 Manifest、四体系 registry 和既有 iztro notice evidence 只做“不得反向引用本政策 ID/path/digest”的负向扫描，不建立 child→parent 绑定。

## 5. 强制接线

现场检查命令：

```text
npm run check:ziwei-iztro-isolated-build-license-notices
```

拒绝测试命令：

```text
npm run test:ziwei-iztro-isolated-build-license-notices
```

在当前静态 root package 脚本模型下，两个紫微构建入口的 `prebuild` 均登记为先运行 live check，再运行 draft boundary check：

- `build:ziwei-browser-preview`
- `build:ziwei-browser-workspace`

Quick CI 的 `toolchain-and-boundaries` job 要求 live check 和拒绝测试各出现一次，且位于 system-contract、来源账、独立 Manifest、中央 registry 和 release-governance 检查之前；不得使用 `continue-on-error` 或 shell 容错把失败改成成功。

目标 job 的 reviewed raw block identity 还会拒绝把 `run:` 文本藏进 YAML block scalar、条件跳过、表达式式 `continue-on-error`、自定义 shell、working-directory、env/defaults、重复 job 或其他结构化伪装。中央 Quick CI 治理另行固定当前完整 workflow 身份，防止同型伪命令绕过其他发布 job。

## 7. 始终为 false 的权威边界

政策和 verifier 均固定以下结论为 false：

- 来源 binding 已冻结、来源包完整
- 作品层、版本层、载体层权利已成立
- 法律结论或再分发授权已成立
- 专家身份、独立性、意见或专家 claim 已授权
- Release Evidence 已完成、release ready
- 公开构建纳入、公开部署、公开发布已授权
- 跨文件原子快照、区间完整性、ABA 抵抗、mutation epoch 已建立
- 有效 npm 运行时闭包、环境配置已中和或 pre/post lifecycle 不可跳过
- 已登记终端模块、config 或 wrapper 的传递执行缺失已建立
