# GitHub 开源复用评估

> 调研与本地静态检查日期：2026-08-01  
> P1-11 归档依赖追加核对：2026-08-02  
> P1-11 混合回执跨浏览器复核：2026-08-03  
> 目标：判断是否存在可以直接复用的八字计算、AI 解读或 PWA 产品代码。  
> 结论：**可以复用经过封装的底层库和少量通用组件；当前没有适合整站原样搬运的项目。**

## 1. 结论先行

### 建议采用

1. 以 [`6tail/lunar-typescript`](https://github.com/6tail/lunar-typescript) 作为首选历法与基础八字计算候选；
2. 在项目自己的 `time-core` / `bazi-core` 适配层后使用，不让业务页面直接调用第三方 API；
3. 公农历逐日真值以香港天文台冻结历表为权威对照，以 .NET `ChineseLunisolarCalendar` 做独立实现差分；`saju` 和 `tianji` 仅作四柱/产品结构诊断，不自动计入农历独立来源；
4. 移动 PWA 外壳优先评估 MIT 许可的 [`ant-design-mobile`](https://github.com/ant-design/ant-design-mobile)，但命盘、品牌和内容结构自行设计；
5. 当前 full v1.0 的 ZIP 压缩固定使用 MIT 许可的 [`fflate@0.8.2`](https://github.com/101arrowz/fflate)，只复用编解码能力；归档形状、大小门、路径检查、完整性和迁移语义由项目自己的备份层控制，旧 full v0.9/v0.8 继续按冻结十三/十二分区契约先验真再逐版迁移；
6. UI、品牌、提示词、内容策略、账号、支付与数据结构自行设计；
7. 任何复制进仓库的代码都保留原许可证与版权，并记录文件来源和修改。

### 不建议

- 不直接 fork 任一完整命理网站作为正式产品；
- 不复制“问真八字”的图标、文案、截图、页面像素布局或品牌识别；
- 不使用没有明确许可证的仓库；
- 不把开源项目的医疗、投资、灾祸或确定性预测逻辑带进产品；
- 不把“测试通过”等同于命理流派正确或产品可合规上线。

## 3. 本地验证证据

候选仓库被浅克隆到独立临时审计目录，没有复制进项目。执行前先检查了根许可证、清单、脚本和明显的进程执行模式；安装依赖时禁用了依赖生命周期脚本。

### `lunar-typescript`

- 根目录 MIT LICENSE；
- 24 个测试相关文件；
- `npm install --ignore-scripts --no-package-lock` 后构建成功；
- Mocha 结果：`272 passing`；
- 构建输出约 1.44 MB，包含大量本产品未必需要的历法和宜忌能力；
- 安装时出现旧版 `inflight`、`glob`、`mocha-typescript` 的开发依赖弃用警告。

判断：运行时库本身适合作为候选，但需要评估包体积、固定版本并只暴露允许的字段；专业研究版也不能因为底层能算吉凶、宜忌就把未经审计的能力展示出来。

### `saju`

- 根目录 MIT LICENSE；
- 仅一个运行时依赖 `lunar-javascript`；
- 33 个命盘测试全部通过；
- 31 个 attribution、隐私与交付测试全部通过；
- 官方 README 明确其阅读页会将出生字段和命盘上下文经 Cloudflare Worker 发送给 Anthropic，并把出生状态编码进可分享 URL。

判断：适合借鉴“浏览器端确定性计算 + AI 叙事层”以及边界测试；不采用其敏感 URL 和原始出生字段传输设计，也不直接沿用韩国流派输出。由于它依赖 `lunar-javascript`，与当前 `lunar-typescript` 属同作者/同数据谱系，不能相互证明公农历转换正确。

### `tianji`

- 根目录 MIT LICENSE；
- Python/FastAPI 项目，包含 12 个测试文件；
- 独立虚拟环境安装后，Pytest 结果：`140 passed`；
- 项目元数据标记 `Development Status :: 3 - Alpha`；
- GitHub 页面显示社区规模仍小。

判断：可作为候选诊断实现，用于发现四柱、十神和已知日期分歧；在依赖与历表来源谱系审计完成前，不把它计入农历转换的独立来源，也不单独承担生产计算。

### 权威历表与独立实现差分

公农历转换现已采用与 GitHub 代码复用分离的证据链：

- 香港天文台 1901—2100 年公历/农历对照表提供逐日权威参考；
- DATA.GOV.HK 的 CSV 与香港天文台文本表属于同机构、同一来源谱系，只用于载体核对；
- .NET Framework 4.8 `ChineseLunisolarCalendar` 作为不同实现谱系的差分票，并通过仓库内只读 PowerShell 脚本重跑、核对冻结结果；
- 首批冻结 24 个唯一日期对、48 个方向断言；当前适配器 48/48 匹配，.NET 为 23 条匹配、1 条低于其支持下界、0 条分歧；
- 软件一致性不等于人工金标，当前仍为 `verified=0`。

详见 [首批 24 条农历历表候选](./首批24条农历历表候选-v0.1.md)。

### `life-kline`

- Apache-2.0，具备完整 React/Vite/Express 结构；
- 只有 6 个提交；
- 唯一名为测试的文件实际是打印结果的演示脚本，没有断言；
- 公开功能包含健康风险、加密货币交易运势和暴富流年预测；
- 账号、积分、管理员、AI、内容种子和服务端代码耦合较多。

判断：可以研究移动导航、表单和分享交互，但直接 fork 会把大量不需要且高风险的逻辑带进项目，清理成本可能高于自行搭建。

### `fflate`

- `@hakimi/backup` 固定依赖 `fflate@0.8.2`，不使用浮动版本；
- 只调用 ZIP/UTF-8 编解码，不让第三方库决定备份 manifest、数据 Schema、摘要或迁移；
- 自有归档层限定 ZIP 只能包含根目录单文件 `hakimi-full-backup.json`，并在解压前检查单卷、条目数、路径、标志位、压缩/解压尺寸、local/central header 一致性；加密、ZIP64、data descriptor、未知标志、符号链接、额外条目与非法 UTF-8 均失败关闭；
- 输出使用固定时间戳以保持同一 JSON 的归档字节可重复；当前 full v1.0 同时保留直接 JSON 兼容入口，v0.9 及更旧版本仅作为冻结迁移输入；
- 该评估当时的全量 Vitest 基线为 88 个文件 / 1015 项、typecheck 与 1990 模块生产构建通过；备份与平台边界定向回归 120/120。数据库升级与备份组合门 4/4 覆盖物理 Edge v9/v10→v13、390×844 首次离线 full v1.1 往返，以及 Chrome 150→全新 Edge 151 的混合非空回执恢复/再导出：同包含 `2 CandidateSet + 1 tzdbMigrationReceipt`、`2 Event + 1 eventTimeMigrationReceipt`、活动规则包和二进制附件；恢复后十五个 payload 分区与各分区摘要逐项相等。这里的 CandidateSet 是旧 comparison/receipt v1 证据，不替代后续 2025b/2026c v2 浏览器门；该历史数字也不是当前全量计数。这些证据仍不替代 v12→v13 升级中断/旧标签页阻塞、Firefox、固定 Android/WebView、大库容量、可靠文件落盘/分享或分卷验收。

判断：这是“固定小型通用依赖 + 自有安全协议”的合适复用，不是搬运第三方备份产品。Chrome→Edge 与首次离线主流程已经验证这条边界，但项目目前仍只有单文件 ZIP、无分卷。正式发布仍需把 MIT 许可纳入 SBOM/第三方通知，并在升级版本时重跑恶意归档、确定性、跨浏览器和容量回归。

## 4. 推荐导入方式

### 4.1 不复制源代码，优先固定依赖

首选做法：

```text
应用页面
  ↓
自有 time-core / bazi-core 接口
  ↓
lunar-typescript（固定精确版本）
  ↓
自有金标准测试与差分校验
```

业务层只允许使用我们定义的结构：

- 标准化后的出生时间和时区；
- 四柱；
- 藏干；
- 十神；
- 五行结构；
- 大运基础数据；
- 计算版本和不确定性信息。

吉凶、宜忌、灾煞、健康、财富和预测字段不直接穿透到业务层。

### 4.2 把其他实现变成诊断票

- 先审计依赖、历表与算法来源谱系，再决定它是否独立；
- 收集多个实现都同意的基础样例，但把“一致票数”与“权威/人工金标”分开；
- 收集立春前后、夏令时、跨时区、23:00 子时和未知时辰等边界样例；
- 每个分歧交给命理顾问选择采用的具体规则；
- 将决定写入规则版本与测试，不由 AI 临时决定；
- 升级第三方依赖时重跑全部金标准。

### 4.3 如果确实复制代码

每个复制文件旁记录：

- 上游仓库 URL；
- 上游提交 SHA；
- 原许可证；
- 原版权声明；
- 本项目修改日期和修改摘要。

项目根目录维护 `THIRD_PARTY_NOTICES.md`，并保留 MIT 或 Apache-2.0 要求的许可证内容。Apache-2.0 代码还要保留 NOTICE，并清楚标注修改。

## 5. 不能直接搬运的内容

- 问真八字或其他商业产品的品牌名、Logo、图标、截图、文案和独特页面组合；
- 开源仓库里来源不明的图片、字体、名人照片、案例数据和古籍整理文本；
- `.env`、API 地址、埋点 ID、支付配置、密钥示例和管理员逻辑；
- 上游 AI 提示词、健康/投资/灾祸预测和恐惧营销；
- 未成年人档案、第三方合盘资料和未经同意的分享 URL；
- 没有 LICENSE 或许可证适用范围不清楚的代码。

## 6. 技术采用建议

```text
生产计算候选：lunar-typescript（固定版本、自有适配层）
权威日期对照：香港天文台冻结历表
独立历法差分：.NET ChineseLunisolarCalendar
同源替代比较：lunar-javascript（不能作为独立证据）
四柱诊断票：saju + tianji（先做来源谱系审计）
最终金标：独立来源材料 + 两位不同复核人 + 版本化裁决
产品 UI：原创 React/Vite PWA
移动通用组件候选：Ant Design Mobile；不使用默认主题
ZIP 编解码：fflate 0.8.2（固定版本；自有单文件安全归档层）
完整开源命理站：只研究，不整站 fork
问真八字：只借鉴信息层级和专业工作流，不复制表达资产
```

## 7. 引入前的最终门槛

即使候选库测试通过，正式引入前仍需：

1. 命理顾问确认采用的年、月、日、时柱和大运规则；
2. 按最新专业研究版计划建立 360 个金标准输入案例，其中包含所有时间边界；
3. 固定依赖版本并生成软件物料清单；
4. 跑依赖漏洞、许可证和恶意包扫描；
5. 评估浏览器包体积和离线性能；
6. 确认专业研究版允许暴露的字段、工程候选标识与争议规则提示；
7. 完成第三方通知与升级策略。

在这些门槛完成前，结论应表述为“可进入技术验证”，而不是“已经可以无审查直接商用”。
