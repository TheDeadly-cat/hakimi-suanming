# 紫微斗数契约草案

这是一个不可被生产代码导入的结构探针。它只冻结紫微斗数未来适配器需要回答的输入、规则快照、本命事实、来源和失败关闭边界；不提供排盘算法，不创建数据库记录，也不代表专家真值。

- 包版本固定为 `0.0.0-draft.0`，`exports` 为空。
- 当前手写样例只能标记为 `synthetic_contract_fixture`，且只能声明 `fixture_structure`；它不是 `upstream_regression`，也不能笼统称为“金标”。
- 早子、十二时辰与晚子使用冻结的 13 项索引/地支/半开区间表；`24:00` 仅是晚子区间终点，不能作为出生瞬时输入。
- 十二宫按项目规范的子至亥顺序保存，不能直接复制候选实现从寅宫开始的数组索引；星曜 scope 当前只能是 `natal`。
- 规则快照包含 162 项星曜键↔项目 ID↔zh-CN 显示名双射注册表、十天干完整四化 manifest、以及按子至亥顺序展开的 20×12 亮度表；本命四化必须匹配出生年干对应表项。
- 大限明确保存出生年支、年支阴阳、排盘用性别和解析后顺逆，并保存虚岁口径、五行局起点、十二个连续十年区间以及所绑定宫位干支。
- 五个启用事实族都必须有 provenance；规则专家声明必须由至少两名不同审核者明确签署 `rule_profile`。
- 首个候选适配器可以研究 `iztro`，但必须锁精确版本、提交、完整有效配置和完整依赖图；不得依赖模块级默认值或上游的 `^` 依赖范围。
- 契约 `0.1.0-draft.3` 已定义项目自己的 canonical JSON v1 投影，并由异步 `verifyZiweiNatalFixtureDraft` 通过运行环境原生 WebCrypto 重算四个 SHA-256；只有等待该函数并得到 `success: true` 才算通过摘要门，单独 `Schema.parse` 仍只证明结构。
- 输入摘要覆盖完整输入；规则摘要排除自己的 `ruleSnapshotSha256`；事实摘要覆盖完整事实；整件摘要覆盖输入、带已验证规则摘要的规则快照、事实、provenance、evidence 和回执元数据，仅排除回执里的四个摘要值。
- `digestVerification` 固定为 `recomputed_sha256_canonical_json_v1`。这能发现内容被改写，但不是数字签名、身份认证、上游运行证据或命理真值证明。
- 包不增加密码学依赖，也不内置自写 SHA-256；运行环境缺少 WebCrypto 时验证门直接失败关闭。
- 当前不支持未知时辰、真太阳时、多规则并发、持久化、查询、备份或用户入口。

相邻的 [`../ziwei-iztro-adapter-draft`](../ziwei-iztro-adapter-draft) 已能在一次性 Node Worker 内运行精确锁定的 iztro 2.5.8，但它也保持空 `exports` 且不进入生产。其 `upstream_regression` 只是工程行为回归，不是专家真值。
